Callable 하나를 MIR로 만들기

하나의 function이나 operation이 매개변수·block·본문을 가진 MirCallable이 되는 과정

← 이전: HIR→MIR 경계전체 목차LowerHirArtifact() 세부 설명
다음: 고전 값과 SSA 버전 →

9장에서는 Next와 Work가 각각 하나의 MirCallable이 된다는 사실만 확인했습니다.
이번 장에서는 callable 하나를 변환할 때 무엇을 먼저 만들고, 소스 본문이 어디에 들어가며, 최종 결과가 어떤 모양인지 살펴봅니다.

이번 장에서 비교할 두 callable

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

두 선언은 모두 callable이지만 모양은 다릅니다.
Next는 매개변수 하나와 반환값이 있는 짧은 function이고, Work는 지역 배열과 큐비트, 조건문을 가진 진입 operation입니다.

이 정확한 입력을 현행 컴파일러로 처리하면 최종 HIR의 두 callable은 Next h6과 Work h44입니다.
MIR에서도 같은 숫자를 보존하므로 각각 Next c6과 Work c44가 되며, 뒤의 코드 주석에서도 이 ID를 계속 사용합니다.

왜 HIR을 MIR로 바꾸는가

HIR은 사용자가 작성한 코드의 중첩 구조를 보존하는 트리입니다.
예를 들어 Work 아래에 배열 선언, 대입문, if, H 호출이 놓이고, if 아래에는 조건식과 X 호출이 놓입니다. 이 구조는 이름과 타입을 검사하고 원래 코드를 이해하기에 알맞습니다.

반면에 어느 시점의 값이 현재 값인지 추적하려면 트리만으로는 불편합니다.
소스에서는 같은 values라는 이름을 계속 사용하지만, MIR에서는 갱신 전 배열 %v1, 읽어 온 원소 %v4, Next의 결과 %v5, 갱신된 배열 %v6을 서로 다른 값으로 구분합니다.

MIR은 실행 경로를 block 사이의 연결로 나타내고, 새로 만들어진 고전 값을 별도의 SSA 값으로 기록합니다.
따라서 이후 분석은 소스 트리를 다시 해석하지 않고도 그래프를 따라가며 값의 변화와 분기 합류를 확인할 수 있습니다. 즉 HIR은 소스의 의미를 보존하고, MIR은 실행 흐름과 값 추적을 쉽게 만드는 역할을 맡습니다.

Callable마다 전용 변환기를 하나씩 만듭니다

callable lowerer는 한 번에 callable 하나만 담당하는 변환 객체입니다.
예를 들어 Next를 처리하는 동안에는 Next의 매개변수, 현재 block, 만들어진 값만 관리합니다. 그 작업이 끝난 뒤에는 새 lowerer를 만들어 Work를 별도로 처리합니다.

실제 코드에서 callable을 하나씩 꺼내는 부분

아래 코드는 현행 LowerHirArtifact() 전체입니다.
실행문은 실제 구현과 같고, 주석만 이번 장의 Next와 Work 값에 맞춰 덧붙였습니다.
이 추적에서는 선택형 lowering 추적기를 전달하지 않았으므로 traceSink = null입니다.
아래 C# 코드에서 밑줄이 표시된 함수명을 직접 클릭하면 해당 함수의 실행 추적으로 이동합니다. 

private static MirSnapshot LowerHirArtifact(
    HirSemanticArtifact hirArtifact,
    IMirLoweringTraceSink? traceSink)
{
    // hirArtifact에는 의미 분석이 끝난 최종 HIR이 들어 있습니다.
    // Callables = [Next h6, Work h44]
    // EntryCallable = Work h44
    ArgumentNullException.ThrowIfNull(hirArtifact);

    var hirSnapshot = hirArtifact.Source;
    var hirProgram = hirSnapshot.Program;

    // 예제값: hirEntryCallable = Work h44
    var hirEntryCallable = hirProgram.EntryCallable
        ?? throw new InvalidOperationException(
            "validated HIR must contain an operation before MIR lowering");

    // 아직 변환한 callable이 없으므로 두 값 모두 비어 있습니다.
    var mirCallables = new List<MirCallable>();
    MirCallable? mirEntryCallable = null;

    foreach (var hirCallable in hirProgram.Callables)
    {
        // 첫 반복: hirCallable = Next h6
        // 둘째 반복: hirCallable = Work h44
        // 반복마다 새 lowerer를 만들기 때문에 두 callable의 작업 상태는 섞이지 않습니다.
        var mirCallableLowerer = new HirCallableToMirLowerer(
            hirCallable,
            hirArtifact,
            traceSink);

        // 첫 반복 결과: mirCallable = Next c6
        // 둘째 반복 결과: mirCallable = Work c44
        var mirCallable = mirCallableLowerer.LowerToMirCallable();
        mirCallables.Add(mirCallable);

        // Next는 진입 operation이 아니므로 첫 반복에서는 false입니다.
        // Work는 hirEntryCallable과 같은 객체이므로 둘째 반복에서 true입니다.
        if (ReferenceEquals(hirCallable, hirEntryCallable))
            mirEntryCallable = mirCallable;
    }

    // 최종 결과:
    // Callables  = [Next c6, Work c44]
    // EntryPoint = Work c44
    var mirProgram = new MirProgram(
        mirEntryCallable
            ?? throw new InvalidOperationException(
                "validated HIR entry callable must be lowered into MIR"),
        mirCallables);

    return MirSnapshot.CreateLowered(mirProgram);
}

첫 반복이 끝나면 Next c6이 목록에 들어가고, 둘째 반복이 끝나면 Work c44이 추가됩니다.
이때 Work가 진입 operation이므로 같은 Work c44 객체가 MirProgram의 진입점으로 선택됩니다.

반복마다 호출되는 lowerer 생성자는 아래가 전부입니다.
담당 HIR callable, 최종 의미 정보, 선택형 추적기를 보관하고, HIR callable의 노드 ID 숫자를 해당 MIR callable ID에도 그대로 사용합니다. 

public HirCallableToMirLowerer(
    HirCallable hirCallable,
    HirSemanticArtifact hirArtifact,
    IMirLoweringTraceSink? traceSink)
{
    // 첫 객체: Next h6
    // 둘째 객체: Work h44
    _hirCallable = hirCallable;
    _hirArtifact = hirArtifact;

    // h6은 c6으로, h44는 c44로 이어집니다.
    _mirCallableId = new MirCallableId(hirCallable.Id.Value);

    // 기본 CLI 실행에서는 별도 추적을 요청하지 않으므로 null입니다.
    _traceSink = traceSink;
}

new로 만든 lowerer는 매개변수 목록과 block 목록이 모두 비어 있고 현재 block도 없는 상태에서 시작합니다.
callable마다 새 block ID 할당기도 가지므로 Next와 Work 모두 첫 block을 b0부터 만들 수 있습니다.

Callable 하나를 만드는 공통 순서

모든 function과 operation은 이 순서를 공유합니다.
차이는 매개변수와 본문에 무엇이 들어 있느냐에서 생깁니다. 단순한 function은 block 하나로 끝날 수 있지만, 조건문이 있는 operation은 여러 block으로 나뉩니다.

Next와 Work를 대입해서 실제 함수를 따라가기

LowerToMirCallable()은 Next h6을 가진 lowerer와 Work h44을 가진 lowerer에서 각각 한 번씩 실행됩니다.
아래 주석에는 같은 코드에서 두 입력의 값과 분기가 어떻게 달라지는지 함께 표시했습니다. 

public MirCallable LowerToMirCallable()
{
    // 첫 번째 실행: _hirCallable = Next h6
    // 두 번째 실행: _hirCallable = Work h44
    var mirCallableOrigin = MirOriginFor(_hirCallable);

    // 결과: 현재 Next 또는 Work 선언 symbol
    var hirCallableSymbol = RequireHirDeclarationSymbol(
        _hirCallable.Id,
        $"callable `{_hirCallable.Name}`");

    // 현재 callable이 어느 namespace에 속하는지 기록한 HIR 이름 구조입니다.
    var hirScopeGraph = _hirArtifact.Model.ScopeGraph
        ?? throw MirLoweringError(
            "the final HIR semantic model has no scope graph");

    // Next 실행: qualifiedSourceCallableName = "Next"
    // Work 실행: qualifiedSourceCallableName = "Work"
    var qualifiedSourceCallableName =
        hirScopeGraph.QualifiedName(hirCallableSymbol);

    // 두 lowerer 모두 자신의 첫 block을 만들므로 각각 별개의 b0입니다.
    _currentMirBlockBuilder = CreateMirBlock(mirCallableOrigin);

    // Next 실행: value 매개변수를 %v0으로 등록합니다.
    // Work 실행: 매개변수가 없어 _mirParameters = []입니다.
    LowerParameters();

    /* LowerStatements()가 현재 callable의 본문을 모두 처리합니다.

    Next
    - return value + 1;을 처리하면서 b0에 계산 명령과 MirReturn terminator를 추가하고 b0를 종료합니다.
    - 현재 block인 b0가 종료되었으므로 _currentMirBlockBuilder = null이 됩니다.
    - _mirBlockBuilders = [b0]

    Work
    - b0는 변수 선언, 큐비트 준비, 배열 대입, if 조건을 처리한 뒤
      b1 또는 b2로 분기하면서 종료됩니다.
    - b1은 참 경로의 X(q[0]);를 처리한 뒤 b3으로 이동하면서 종료됩니다.
    - b2는 처리할 소스 문장이 없는 거짓 경로이며, b3으로 이동하면서 종료됩니다.
    - b3은 b1과 b2가 합류하는 block이며, 마지막 H(q[0]);를 처리합니다.
    - H(q[0]);는 block을 종료하지 않고 그 뒤에 명시적 return도 없으므로,
      b3은 열린 현재 block으로 남습니다.

    처리 후
    ├─ _mirBlockBuilders = [b0, b1, b2, b3]
    └─ _currentMirBlockBuilder = b3 */
    LowerStatements(_hirCallable.Body.Statements);

    // Next: 현재 block이 null이므로 아래 if를 건너뜁니다.
    // Work: 현재 block이 b3이므로 아래 if에서 b3을 종료합니다.
    if (_currentMirBlockBuilder is not null)
    {
        if (_hirCallable.IsFunction)
        {
            // 이번 예제에서는 이 분기를 선택하는 실행이 없습니다.
            MarkCurrentMirBlockUnreachable(
                MirOrigin.GeneratedFrom(
                    mirCallableOrigin,
                    "missing validated function return"));
        }
        else
        {
            // Work 실행: b3에 값 없는 implicit return을 붙입니다.
            ReturnFromCurrentMirBlock(
                value: null,
                MirOrigin.GeneratedFrom(
                    mirCallableOrigin,
                    "implicit operation return"));
        }
    }

    // Next 실행: builder 목록 [b0]
    // Work 실행: builder 목록 [b0,b1,b2,b3]
    // 각 builder를 더 이상 바뀌지 않는 MirBlock으로 완성합니다.
    var mirBlocks = new List<MirBlock>(_mirBlockBuilders.Count);
    foreach (var mirBlockBuilder in _mirBlockBuilders)
    {
        var mirBlock = mirBlockBuilder.Build();
        mirBlocks.Add(mirBlock);
    }

    // 첫 번째로 생성한 b0이 항상 진입 block입니다.
    var mirEntryBlock = mirBlocks[0];

    // Next 반환: c6, "Next", int, [%v0], b0, [b0]
    // Work 반환: c44, "Work", null, [], b0, [b0,b1,b2,b3]
    return new MirCallable(
        _mirCallableId,
        qualifiedSourceCallableName,
        _hirCallable.ReturnType is { } returns
            ? MirType.Scalar(returns)
            : null,
        _mirParameters,
        mirEntryBlock,
        mirBlocks,
        mirCallableOrigin);
}

이 함수가 하는 일은 앞의 도식과 같습니다.
먼저 진입 block을 만들고 본문을 처리합니다. Next는 명시적 return으로 끝나고, Work는 남아 있는 operation 경로를 빈 return으로 닫은 뒤 각각 MirCallable Next c6과 MirCallable Work c44로 완성됩니다.

두 callable의 본문 문장은 어디로 들어가는가

위 코드의 LowerStatements()는 본문을 처음부터 끝까지 순회하고, LowerStatement()는 현재 문장의 종류에 맞는 변환 함수 하나를 선택합니다.
두 함수의 현행 전체 코드는 다음과 같으며, 주석에는 Next와 Work에서 실제로 들어오는 값을 표시했습니다. 

private void LowerStatements(IReadOnlyList<HirStatement> hirStatements)
{
    // Next 본문: [return value + 1], 시작 b0
    // Work 최상위: [var, use, 대입, if, H], 시작 b0
    // if 참 본문: [X(q[0])], 시작 b1
    // if 거짓 본문: [], 시작 b2
    for (var hirStatementIndex = 0;
         hirStatementIndex < hirStatements.Count;
         hirStatementIndex++)
    {
        // 반복 시작 시 현재 경로가 이미 끝났다면 남은 문장은 방출하지 않습니다.
        // 공통 예제의 네 실행에서는 이 분기를 선택하지 않습니다.
        if (_currentMirBlockBuilder is null)
        {
            for (;
                 hirStatementIndex < hirStatements.Count;
                 hirStatementIndex++)
            {
                MarkUnreachableDeclarations(
                    hirStatements[hirStatementIndex]);
            }
            return;
        }

        LowerStatement(hirStatements[hirStatementIndex]);
    }
}

반복문이 문장 하나를 꺼낼 때마다 아래의 LowerStatement()를 호출합니다. 

private void LowerStatement(HirStatement hirStatement)
{
    switch (hirStatement)
    {
        // Work의 use q 문장이 선택합니다.
        case HirQubitDeclarationStatement hirQubitDeclaration:
            LowerQubitDeclaration(hirQubitDeclaration);
            return;

        // Work의 var values 문장이 선택합니다.
        case HirVariableDeclarationStatement hirDeclaration:
            LowerDeclaration(hirDeclaration);
            return;

        // Work의 values[0] 대입문이 선택합니다.
        case HirAssignmentStatement hirAssignment:
            LowerAssignment(hirAssignment);
            return;

        // Work의 H 호출이 선택합니다.
        // if 안의 X 호출도 중첩 본문을 처리할 때 같은 분기를 선택합니다.
        case HirCallStatement hirCallStatement:
            LowerStatementCall(hirCallStatement);
            return;

        // Work의 if 문장이 선택합니다.
        case HirIfStatement hirIf:
            LowerIf(hirIf);
            return;

        case HirForStatement hirFor:
            LowerFor(hirFor);
            return;

        case HirWhileStatement hirWhile:
            LowerWhile(hirWhile);
            return;

        case HirRepeatStatement hirRepeat:
            LowerRepeat(hirRepeat);
            return;

        // Next의 return 문장은 이 분기를 선택합니다.
        case HirReturnStatement hirReturn:
            LowerReturn(hirReturn);
            return;

        default:
            throw MirLoweringError(
                $"unsupported HIR statement {hirStatement.GetType().Name}");
    }
}

이 switch는 문장의 의미를 새로 판단하지 않습니다.
HIR에서 이미 구분된 문장 종류를 보고 그 타입에 맞는 helper 하나를 호출한 뒤 즉시 끝납니다.

Next는 block 하나로 완성됩니다

Next에는 value라는 int 매개변수 하나가 있습니다.
lowerer는 이 매개변수를 MIR 입력값 %v0으로 등록하고, 진입 block b0에서 본문을 처리합니다.

소스의 return value + 1;은 계산과 반환으로 나뉘지만, 모두 같은 b0 안에 들어갑니다.
return이 block을 끝내므로 별도의 종료 문장을 추가할 필요가 없습니다.

Work는 조건문 때문에 여러 block으로 나뉩니다

Work에는 매개변수가 없지만 지역 배열과 큐비트가 있습니다.
먼저 진입 block에서 배열을 만들고 큐비트를 준비한 뒤, 배열 값을 갱신하고 조건을 계산합니다.

if를 만나는 순간 실행 경로가 둘로 갈라지므로 b1과 b2가 필요합니다.
두 경로에서 실행을 마치면 b3으로 합쳐지고, 소스에서 조건문 뒤에 있는 H(q[0]);가 이 block에 들어갑니다.

Work의 소스에는 return이 없습니다.
operation은 값을 반환하지 않으므로 lowerer가 마지막 b3에 빈 반환을 자동으로 붙여 block을 정상적으로 닫습니다. 이것을 implicit return이라고 부릅니다.

최종 MirCallable이 보관하는 것

callable lowering이 끝나면 작업 중이던 목록을 하나의 MirCallable로 묶습니다.
완성된 MirCallable에는 callable의 ID와 이름, 반환형, 매개변수, 진입 block과 전체 block 목록이 남습니다.

정리하면 callable lowerer는 HIR 선언 하나를 받아 실행 순서가 분명한 block 구조로 바꾸는 역할을 합니다.
다음 장에서는 그 block 안에 들어간 고전 값만 확대하여, 소스의 같은 변수 이름이 왜 MIR에서는 여러 SSA 값으로 나뉘는지 살펴봅니다.

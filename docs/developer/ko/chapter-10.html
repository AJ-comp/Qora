Callable 하나를 MIR로 만들기

foreach의 두 반복에서 lowerer 생성부터 MirCallable 반환까지

← 이전: HIR→MIR 경계전체 목차
다음: 고전 값과 SSA 버전 →

9장의 foreach 안으로 들어갑니다.
첫 반복의 Next h6과 둘째 반복의 Work h44가 각각 어떤 생성자 인수로 들어가며, LowerToMirCallable()이 매개변수·block·문장을 어떤 순서로 소비하고 무엇을 반환하는지 실제 상태값으로 확인합니다.

이번 장에서 처리할 두 callable

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];
    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

첫 반복 직전에는 hirProgram.Callables = [Next h6, Work h44], mirCallables = [], mirEntryCallable = null입니다.
foreach가 먼저 Next h6을 꺼내 아래 생성자를 호출하고, 그 작업이 끝난 뒤에야 Work h44을 꺼내 새로운 lowerer를 만듭니다. 

// 첫 반복의 실제 호출
var mirCallableLowerer = new HirCallableToMirLowerer(
    hirCallable: Next h6,
    hirArtifact: 최종 effect-analysis artifact,
    traceSink: null);
var mirCallable = mirCallableLowerer.LowerToMirCallable();
// 반환값: Next c6

// 둘째 반복의 실제 호출
var mirCallableLowerer = new HirCallableToMirLowerer(
    hirCallable: Work h44,
    hirArtifact: 첫 반복과 같은 artifact,
    traceSink: null);
var mirCallable = mirCallableLowerer.LowerToMirCallable();
// 반환값: Work c44

새 lowerer에 세 인수 저장하기

생성자에 들어가는 세 값은 모두 호출부에서 왔습니다. hirCallable은 현재 foreach 원소이고, hirArtifact는 9장에서 ToMir()이 꺼낸 객체이며, traceSink는 기본 CLI 실행이 전달한 null입니다.
생성자 전체는 다음과 같습니다. 

public HirCallableToMirLowerer(
    HirCallable hirCallable,
    HirSemanticArtifact hirArtifact,
    IMirLoweringTraceSink? traceSink)
{
    // 첫 반복: Next h6, 둘째 반복: Work h44
    _hirCallable = hirCallable;

    // 두 반복 모두 같은 최종 HIR artifact
    _hirArtifact = hirArtifact;

    // 첫 반복: new MirCallableId(6)  = c6
    // 둘째 반복: new MirCallableId(44) = c44
    _mirCallableId =
        new MirCallableId(hirCallable.Id.Value);

    // 기본 CLI 예제값: null
    _traceSink = traceSink;
}

첫 lowerer가 반환된 뒤 그 객체를 재설정하여 Work에 사용하지 않습니다.
둘째 반복은 새 객체를 만들기 때문에 callable 내부의 block·값·instruction 번호가 다시 0부터 시작합니다.

생성 직후 작업 상태

다음 필드는 lowerer 인스턴스가 만들어질 때 초기화됩니다.
아래 코드는 현재 구현의 필드 선언이며, 오른쪽 주석은 생성 직후의 예제값입니다. 

private readonly List<MirBlockBuilder> _mirBlockBuilders = new(); // []
private readonly MirBlockId.Allocator _mirBlockIds = new();       // 다음 ID b0
private readonly List<MirValue> _mirValues = new();               // []
private readonly List<IMirParameter> _mirParameters = new();      // []
private readonly Dictionary<MirQubitId, MirQubit>
    _initialMirQubitsById = new();                                // {}
private readonly Dictionary<MirQubitId, int>
    _nextMirQubitVersionById = new();                             // {}

private int _nextMirInstructionIdValue;                           // 0
private int _nextMirStorageIdValue;                               // 0
private MirBlockBuilder? _currentMirBlockBuilder;                 // null
private LoweringFlowState _currentFlowState = new();              // 값 {}, 큐비트 {}

이 상태는 프로그램 전체의 전역 카운터가 아닙니다.
따라서 Next c6과 Work c44은 둘 다 b0, %v0, i0을 가질 수 있으며, 어느 callable에 속하는지 함께 보면 충돌하지 않습니다.

LowerToMirCallable() 전체 실행 순서

이제 호출된 메서드 전체를 읽습니다.
코드는 실제 구현과 같으며, 예제값을 밝히는 주석만 추가했습니다. 

public MirCallable LowerToMirCallable()
{
    // 첫 반복: Next h6의 Origin, 둘째 반복: Work h44의 Origin
    var mirCallableOrigin = MirOriginFor(_hirCallable);
    var hirCallableSymbol = RequireHirDeclarationSymbol(
        _hirCallable.Id,
        $"callable `{_hirCallable.Name}`");
    var hirScopeGraph = _hirArtifact.Model.ScopeGraph
        ?? throw MirLoweringError(
            "the final HIR semantic model has no scope graph");
    var qualifiedSourceCallableName =
        hirScopeGraph.QualifiedName(hirCallableSymbol);

    // 각 lowerer의 첫 block이므로 두 반복 모두 b0
    var mirEntryBlockBuilder = CreateMirBlock(mirCallableOrigin);
    _currentMirBlockBuilder = mirEntryBlockBuilder;

    // Next: value 매개변수 하나를 %v0으로 만듭니다.
    // Work: 매개변수가 없어 상태가 바뀌지 않습니다.
    LowerParameters();

    // Next: return value + 1 한 문장
    // Work: 선언, use, 대입, if, H 호출의 다섯 문장
    LowerStatements(_hirCallable.Body.Statements);

    if (_currentMirBlockBuilder is not null)
    {
        if (_hirCallable.IsFunction)
        {
            MarkCurrentMirBlockUnreachable(
                MirOrigin.GeneratedFrom(
                    mirCallableOrigin,
                    "missing validated function return"));
        }
        else
        {
            // Work의 H 호출 뒤 열린 b3을 value: null인 return으로 닫습니다.
            ReturnFromCurrentMirBlock(
                value: null,
                MirOrigin.GeneratedFrom(
                    mirCallableOrigin,
                    "implicit operation return"));
        }
    }

    var mirBlocks = new List<MirBlock>(_mirBlockBuilders.Count);
    MirBlock? mirEntryBlock = null;
    foreach (var mirBlockBuilder in _mirBlockBuilders)
    {
        var mirBlock = mirBlockBuilder.Build();
        mirBlocks.Add(mirBlock);
        if (ReferenceEquals(mirBlockBuilder, mirEntryBlockBuilder))
            mirEntryBlock = mirBlock;
    }

    if (mirEntryBlock is null)
        throw MirLoweringError("the MIR entry block was not emitted");

    // 첫 반복 반환: Next c6, 매개변수 [%v0], block [b0]
    // 둘째 반복 반환: Work c44, 매개변수 [], block [b0,b1,b2,b3]
    return new MirCallable(
        _mirCallableId,
        qualifiedSourceCallableName,
        _hirCallable.ReturnType is { } returns
            ? MirType.Scalar(returns)
            : null,
        _mirParameters,
        mirEntryBlock,
        mirBlocks,
        mirCallableOrigin);
}

메서드의 순서는 이름과 진입 block을 먼저 확정하고, 매개변수를 현재 흐름 상태에 등록한 다음, 본문 문장을 소스 순서대로 내리는 방식입니다.
그 뒤 열린 경로를 닫고 임시 block을 불변 MirBlock으로 만든 후 MirCallable 하나를 반환합니다.
다음 절부터 같은 순서를 예제값으로 나눠 확인합니다.

1. Next h6의 이름과 출처 확정

첫 반복에서 _hirCallable = Next h6입니다. MirOriginFor(Next h6)은 현재 artifact와 h6을 묶고, RequireHirDeclarationSymbol(h6, "callable `Next`")은 의미 모델에서 Next 선언 Symbol을 꺼냅니다.
이 예제에는 namespace가 없으므로 hirScopeGraph.QualifiedName(hirCallableSymbol)의 결과는 "Next"입니다. 

첫 네 지역 변수
├─ mirCallableOrigin = (최종 hirArtifact, Next h6)
├─ hirCallableSymbol = Symbol(Next 선언)
├─ hirScopeGraph      = 같은 artifact.Model.ScopeGraph
└─ qualifiedSourceCallableName = "Next"

둘째 반복에서도 동일한 코드가 실행되며 값만 Work h44, Symbol(Work 선언), "Work"로 바뀝니다.

2. 첫 block을 만들고 현재 block으로 선택

각 lowerer의 block allocator는 아직 한 번도 사용되지 않았으므로 AllocateMirBlockId()가 b0을 반환합니다. CreateMirBlock() 전체는 새 builder를 목록에 등록한 뒤 그 객체를 그대로 반환합니다. 

private MirBlockBuilder CreateMirBlock(MirOrigin mirOrigin)
{
    // Next와 Work 모두 첫 호출에서는 AllocateMirBlockId() = b0
    var mirBlockBuilder = new MirBlockBuilder(
        this,
        AllocateMirBlockId(),
        mirOrigin);

    // [] -> [b0 builder]
    _mirBlockBuilders.Add(mirBlockBuilder);
    return mirBlockBuilder;
}
CreateMirBlock() 직후
├─ mirEntryBlockBuilder = b0 builder
├─ _mirBlockBuilders    = [같은 b0 builder]
└─ _currentMirBlockBuilder = 같은 b0 builder

3. Next(value: int)의 매개변수 등록

LowerParameters()에 별도 인수가 없는 이유는 입력이 이미 _hirCallable과 _hirArtifact 필드에 저장되어 있기 때문입니다.
이 예제에서는 Next에 스칼라 매개변수 하나가 있고 Work에는 매개변수가 없습니다.
아래 전체 함수에서 실제로 선택되는 경로를 주석으로 표시했습니다. 

private void LowerParameters()
{
    // Next와 Work 모두 배열 매개변수 요구가 없으므로 null입니다.
    var requiredArrayLengths =
        _hirArtifact.Model.RequiredArgLengths(_hirCallable.Id);

    for (var hirParameterIndex = 0;
         hirParameterIndex < _hirCallable.Parameters.Count;
         hirParameterIndex++)
    {
        // Next 첫 반복: hirParameterIndex = 0, hirParameter = value:int
        // Work: Parameters.Count = 0이므로 for 본문에 들어오지 않습니다.
        var hirParameter = _hirCallable.Parameters[hirParameterIndex];
        var hirParameterSymbol = RequireHirDeclarationSymbol(
            hirParameter.Id,
            $"parameter `{hirParameter.Name}`");
        var mirParameterOrigin = MirOriginFor(hirParameter);
        _currentFlowState.TrackDeclaredHirSymbol(hirParameterSymbol.Id);

        if (hirParameter.Type == QType.Qubit)
        {
            var mirQubitId = AllocateMirQubitId();
            var mirQubitParameter = hirParameter.IsArray
                ? MirQubitParameter.Array(
                    mirQubitId,
                    hirParameter.Name,
                    hirParameter.RegisterSize,
                    hirParameter.Ownership,
                    mirParameterOrigin)
                : MirQubitParameter.Single(
                    mirQubitId,
                    hirParameter.Name,
                    hirParameter.Ownership,
                    mirParameterOrigin);
            RegisterInitialMirQubit(
                hirParameterSymbol.Id,
                mirQubitParameter);
            _currentFlowState.CurrentMirQubitByHirSymbolId[
                    hirParameterSymbol.Id] =
                mirQubitParameter;
            _mirParameters.Add(mirQubitParameter);
            continue;
        }

        // Next의 value는 IsArray = false이므로 Scalar(Int)입니다.
        var mirParameterType = hirParameter.IsArray
            ? MirType.Array(hirParameter.Type, hirParameter.RegisterSize)
            : MirType.Scalar(hirParameter.Type);
        var mirParameterValue = CreateMirValue(
            mirParameterType,
            hirParameterSymbol.Id,
            mirParameterOrigin);
        MirArrayStorage? mirArrayStorage = null;
        if (hirParameter.IsArray)
        {
            mirArrayStorage = new MirArrayStorage(
                AllocateMirStorageId(),
                hirParameter.Name,
                mirParameterOrigin);
            _traceSink?.LinkStorage(
                hirParameterSymbol.Id,
                _mirCallableId,
                mirArrayStorage.Id);
        }
        var minimumLength = hirParameter.IsArray ? 1 : 0;
        if (hirParameter.IsArray
            && requiredArrayLengths is not null
            && requiredArrayLengths.TryGetValue(
                hirParameter.Name,
                out var requiredLength))
        {
            if (requiredLength < 0 || requiredLength > int.MaxValue)
            {
                throw MirLoweringError(
                    $"array parameter `{hirParameter.Name}` has invalid "
                    + $"minimum length {requiredLength}");
            }

            minimumLength = Math.Max(minimumLength, (int)requiredLength);
        }
        _currentFlowState.CurrentMirValueByHirSymbolId[
                hirParameterSymbol.Id] =
            mirParameterValue.Id;
        var mirParameter = mirArrayStorage is null
            ? MirClassicalParameter.Scalar(
                hirParameter.Name,
                mirParameterValue,
                hirParameter.Ownership,
                hirParameter.Access)
            : MirClassicalParameter.Array(
                hirParameter.Name,
                mirParameterValue,
                mirArrayStorage,
                hirParameter.Ownership,
                hirParameter.Access,
                minimumLength);
        _mirParameters.Add(mirParameter);
    }
}

Next lowerer의 _mirValues는 비어 있었으므로 CreateMirValue()가 %v0을 만듭니다.
이어서 현재 흐름 dictionary에 Symbol(value) → %v0을 기록하고, 같은 값을 가진 MirClassicalParameter를 _mirParameters에 추가합니다. 

Next의 LowerParameters() 종료 상태
├─ _mirValues = [%v0 : int]
├─ _mirParameters = [value -> %v0]
└─ CurrentMirValueByHirSymbolId
   └─ Symbol(value) -> %v0

Work의 LowerParameters() 종료 상태
├─ _mirValues = []
├─ _mirParameters = []
└─ CurrentMirValueByHirSymbolId = {}

4. 본문 문장을 소스 순서대로 분기

다음 소비처는 LowerStatements(_hirCallable.Body.Statements)입니다. Next의 목록에는 return 하나가 있고, Work의 목록에는 선언, 큐비트 할당, 대입, if, H 호출이 차례로 들어 있습니다.
목록 순회 함수와 문장 종류를 고르는 함수의 전체 코드는 다음과 같습니다. 

private void LowerStatements(IReadOnlyList<HirStatement> hirStatements)
{
    for (var hirStatementIndex = 0;
         hirStatementIndex < hirStatements.Count;
         hirStatementIndex++)
    {
        if (_currentMirBlockBuilder is null)
        {
            for (;
                 hirStatementIndex < hirStatements.Count;
                 hirStatementIndex++)
            {
                MarkUnreachableDeclarations(
                    hirStatements[hirStatementIndex]);
            }
            return;
        }

        // Next: index 0 = HirReturnStatement
        // Work: index 0..4 = declaration, use, assignment, if, H call
        LowerStatement(hirStatements[hirStatementIndex]);
    }
}

private void LowerStatement(HirStatement hirStatement)
{
    switch (hirStatement)
    {
        case HirQubitDeclarationStatement hirQubitDeclaration:
            LowerQubitDeclaration(hirQubitDeclaration);
            return;

        case HirVariableDeclarationStatement hirDeclaration:
            LowerDeclaration(hirDeclaration);
            return;

        case HirAssignmentStatement hirAssignment:
            LowerAssignment(hirAssignment);
            return;

        case HirCallStatement hirCallStatement:
            LowerStatementCall(hirCallStatement);
            return;

        case HirIfStatement hirIf:
            LowerIf(hirIf);
            return;

        case HirForStatement hirFor:
            LowerFor(hirFor);
            return;

        case HirWhileStatement hirWhile:
            LowerWhile(hirWhile);
            return;

        case HirRepeatStatement hirRepeat:
            LowerRepeat(hirRepeat);
            return;

        case HirReturnStatement hirReturn:
            LowerReturn(hirReturn);
            return;

        default:
            throw MirLoweringError(
                $"unsupported HIR statement {hirStatement.GetType().Name}");
    }
}

Next에서는 HirReturnStatement 분기가 선택되어 LowerReturn()으로 들어갑니다.
value + 1을 처리한 결과 %v2가 생기고 b0의 terminator가 return %v2로 정해집니다.
block이 닫히면 _currentMirBlockBuilder는 null이 됩니다.
이 값이 만들어지는 정확한 호출 순서는 11장 첫 절에서 이어서 추적합니다. 

Next의 문장 처리 결과
└─ b0
   ├─ i0: %v1 = const int 1
   ├─ i1: %v2 = add %v0, %v1
   └─ return %v2

상태
├─ _mirValues = [%v0, %v1, %v2]
├─ _nextMirInstructionIdValue = 2
└─ _currentMirBlockBuilder = null

Work에서는 같은 switch가 다섯 번 호출됩니다.
첫 선언은 %v0, %v1, $s0을 만들고, 큐비트 선언은 q0.v0을 할당하며, 대입은 배열의 현재 연결을 %v1에서 %v6으로 바꿉니다.
이어서 if가 b1, b2, b3을 만들고 현재 block을 합류점 b3으로 옮깁니다.
마지막 H(q[0])은 그 b3에 i14와 i15를 추가합니다. 

Work의 소스 문장별 결과
├─ var values = [0]                  -> %v0, %v1, $s0, i0..i1
├─ use q = Qubit[1]                  -> q0.v0, i2
├─ values[0] = Next(values[0])       -> %v2..%v6, i3..i7
├─ if (values[0] == 1) { X(q[0]); }  -> %v7..%v11, i8..i13, b1..b3
└─ H(q[0])                           -> %v12, i14..i15

문장 처리 직후
├─ _mirBlockBuilders = [b0, b1, b2, b3]
├─ _currentMirBlockBuilder = b3
├─ CurrentMirValueByHirSymbolId[Symbol(values)] = %v6
└─ CurrentMirQubitByHirSymbolId[Symbol(q)] = q0.v3
여기서 이어지는 세부 추적 고전 값 %v0…%v12과 명령 i0…i15의 생성 순서는 11장에서 같은 입력을 그대로 사용하여 추적합니다.
배열의 $s0과 상태값 %v1/%v6 관계는 12장, 큐비트 q0.v0…v3 관계는 13장에서 이어집니다.

5. Work의 열린 b3 닫기

Next는 소스의 return이 이미 b0을 닫았으므로 _currentMirBlockBuilder is not null 조건이 거짓입니다.
반면에 Work는 반환값이 없는 operation이고 마지막 H 뒤의 b3이 열려 있습니다.
따라서 ReturnFromCurrentMirBlock(value: null, generatedOrigin)을 호출합니다. 

private void ReturnFromCurrentMirBlock(
    MirValueId? value,
    MirOrigin mirOrigin)
{
    // Work 예제값: currentMirBlock = b3, value = null
    var currentMirBlock = RequireCurrentMirBlock();
    currentMirBlock.Return(value, mirOrigin);
}

MirBlockBuilder.Return()은 MirReturn(null, generatedOrigin)을 terminator로 저장합니다.
이어서 OnMirBlockTerminated(b3)가 현재 block을 null로 바꾸므로, 이제 Work에도 열린 제어 흐름 경로가 남지 않습니다.

6. 임시 builder를 불변 block으로 완성

문장 처리 중에는 instruction과 terminator를 추가해야 하므로 MirBlockBuilder를 사용했습니다.
모든 경로를 닫은 다음에는 LowerToMirCallable()의 두 번째 foreach가 각 builder의 Build()를 호출합니다. 

public MirBlock Build()
{
    // 예제의 b0..b3은 모두 return, branch, jump 중 하나를 가집니다.
    if (_terminator is null)
    {
        throw new InvalidOperationException(
            $"QINTERNAL: MIR block {Id} has no terminator");
    }

    return new MirBlock(
        Id,
        _arguments,
        Instructions,
        _terminator,
        Origin,
        QubitPhis);
}

Next에서는 b0 builder 하나가 MirBlock b0 하나가 됩니다.
Work에서는 등록 순서대로 b0, b1, b2, b3가 완성됩니다.
첫 builder는 앞에서 보관한 mirEntryBlockBuilder와 같은 객체이므로, 그 결과인 MirBlock b0이 mirEntryBlock으로 선택됩니다.

7. 두 MirCallable 반환

첫 반복의 마지막 생성자 호출에는 c6, 이름 "Next", 반환 타입 int, 매개변수 [%v0 value], 진입 block b0, 전체 block [b0]이 들어갑니다.
반환된 Next c6은 9장의 mirCallables 목록 첫 원소로 바로 소비됩니다. 

function @c6 Next(%v0 value: int) -> int
  entry ^b0
  ^b0():
    %v1: int = const int 1
    %v2: int = add %v0, %v1
    return %v2

둘째 반복의 생성자 호출에는 c44, 이름 "Work", 반환 타입 null, 빈 매개변수 목록, 진입 block b0, 전체 block [b0,b1,b2,b3]가 들어갑니다.
반환된 Work c44은 목록 둘째 원소가 되며, 동시에 HIR 진입점 Work h44에 대응하는 MIR 진입점으로 선택됩니다. 

operation @c44 Work()
  entry ^b0
  blocks = [^b0, ^b1, ^b2, ^b3]
  values = [%v0 .. %v12]
  instructions = [i0 .. i15]
  final terminator = ^b3의 implicit return

추적 뒤에 정리하는 로컬 ID 규칙

값·block·instruction 번호는 각 HirCallableToMirLowerer가 독립적으로 발급합니다.
따라서 %v0이나 i0만으로 프로그램 전체 위치를 나타낼 수는 없습니다.
예를 들어 Next c6의 %v0은 매개변수 value이고, Work c44의 %v0은 배열 리터럴 원소 0입니다. 

Next c6
├─ b0
├─ %v0 = parameter value
└─ i0 = const int 1

Work c44
├─ b0
├─ %v0 = const int 0
└─ i0 = const int 0

프로그램 전체에서 instruction을 가리킬 때는 callable ID와 로컬 instruction ID를 함께 가진 MirInstructionSite를 사용합니다.
이 예제의 X와 H는 각각 c44/i13, c44/i15입니다.
값의 정의 위치를 역으로 조회하는 방식은 11장의 정의 위치 절에서 확인할 수 있습니다.

이번 장에서 확인한 실행 foreach는 Next h6과 Work h44마다 새 lowerer를 만듭니다.
각 lowerer는 생성 직후 빈 작업 상태에서 시작하여 이름·진입 block·매개변수·본문·종료·block build 순서로 처리하고, 완성된 Next c6 또는 Work c44 하나만 바깥 목록에 반환합니다.

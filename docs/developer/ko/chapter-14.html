Basic Block와 Terminator

하나의 if가 b0부터 b3까지 나뉘는 과정

← 이전: 큐비트 버전전체 목차
다음: 조건문 lowering →

MIR은 if를 중첩된 문장 트리 그대로 보관하지 않습니다.
끊기지 않고 차례대로 실행되는 명령들을 Basic Block으로 묶고, 각 block의 마지막에 다음 이동 위치를 적습니다.
공통 예제의 if는 b0, b1, b2, b3 네 block으로 바뀝니다.

살펴볼 Qora 코드

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

조건이 참이면 X를 실행하고, 거짓이면 아무 일도 하지 않습니다.
어느 경로를 택하더라도 if가 끝나면 H를 실행해야 합니다.
MIR은 이 세 구간을 분리해 제어 흐름을 명시적으로 나타냅니다.

네 block의 전체 연결

                    ┌─ 참 ─▶ b1: X 실행 ─┐
b0: 조건 계산과 branch                    ├─▶ b3: H 실행과 return
                    └─ 거짓 ▶ b2: 빈 경로 ─┘

b0는 조건을 계산하고 두 경로 중 하나를 고릅니다.
b1은 참일 때의 본문을, b2는 거짓일 때의 경로를 나타냅니다.
두 경로는 b3에서 다시 합쳐지고, 그 뒤에 공통으로 실행할 H가 이어집니다.

b0: 조건을 계산하고 경로를 선택합니다

b0에는 if 전에 실행할 배열 선언과 갱신도 들어 있지만, 여기서는 마지막 부분만 보면 충분합니다.
MIR은 values[0] == 1을 계산하여 %v10을 만들고, branch가 그 값을 보고 다음 block을 결정합니다. 

b0
├─ %v10 = values[0] == 1
└─ branch %v10
   ├─ true  → b1
   └─ false → b2

block의 마지막에서 다음 이동을 정하는 명령을 Terminator라고 합니다.
b0의 Terminator는 두 목적지를 가진 branch입니다.
조건이 참이면 b1, 거짓이면 b2로 이동하므로 실행이 두 갈래로 나뉩니다.

b1과 b2: 각 경로를 실행하고 합류점으로 갑니다

b1
├─ X(q0.v0) → q0.v1
└─ jump b3

b2
└─ jump b3

b1은 참 본문에 있던 X(q[0])을 실행합니다.
실행을 마치면 더 처리할 참 본문이 없으므로 jump b3으로 합류점에 이동합니다.

원본 소스에는 else가 없지만 b2는 필요합니다.
조건이 거짓일 때 X를 건너뛰고 어디로 갈지를 나타내야 하기 때문입니다.
이 경로에는 실행할 본문이 없으므로 곧바로 jump b3만 가집니다.

jump도 block을 끝내는 Terminator입니다.
branch가 조건에 따라 목적지를 고르는 반면, jump는 정해진 목적지 하나로 이동합니다.

b3: 경로를 합치고 남은 코드를 실행합니다

b3
├─ q0.v2 = phi(b1: q0.v1, b2: q0.v0)
├─ H(q0.v2) → q0.v3
└─ return

b3에는 b1과 b2가 모두 도착합니다.
참 경로에서는 X를 지난 q0.v1이 오고, 거짓 경로에서는 원래 버전 q0.v0이 옵니다.
Phi는 두 입력을 q0.v2라는 하나의 합류 버전으로 묶습니다.

원본 코드의 H(q[0])은 if 다음에 있으므로 b3에서 실행됩니다.
H가 합류 버전 q0.v2을 받아 q0.v3을 만든 뒤, Work에 남은 문장이 없으므로 MIR이 붙인 암시적 return이 block과 callable을 끝냅니다.

MIR에는 두 경로가 모두 남습니다

MIR 안에는 네 block이 모두 존재하지만, 한 번의 실행은 조건에 맞는 경로 하나만 지납니다.
lowering은 Next의 호출 결과를 미리 계산하지 않으므로 다음 두 가능성을 모두 표현합니다. 

참 경로
b0 → b1 → b3 → return

거짓 경로
b0 → b2 → b3 → return

앞 장에서 확인했듯 이 정확한 예제를 실행하면 참 경로를 택합니다.
거짓 경로 b2는 실행 결과를 예측해 제거한 경로가 아니라, lowering 단계가 보존한 제어 흐름의 다른 가능성입니다.

정리

한 문장으로 보는 제어 흐름 b0가 branch로 경로를 고르고, b1과 b2가 각 경로를 처리한 뒤 jump로 b3에 모입니다.
b3는 경로별 큐비트 버전을 합치고 H를 실행한 다음 return으로 끝납니다.

구현 함수·생성자 따라가기

10장의 실제 C# 함수 하나를 선택해 입력값부터 반환 결과까지 따라가는 페이지

← 10장으로 돌아가기전체 목차

LowerHirArtifact()

최종 HIR의 callable을 하나씩 MIR로 바꾸고, 결과를 최초 MirSnapshot으로 묶는 함수입니다.
이번 추적에서는 foreach가 Next와 Work를 차례로 처리합니다.

이 함수가 처음 받는 Qora 프로그램

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

이 함수는 아직 배열 선언이나 if 같은 개별 문장을 직접 처리하지 않습니다.
먼저 프로그램에서 두 선언을 꺼내 Next h6과 Work h44라는 두 callable로 봅니다. Work 안의 Next(values[0])은 새로운 세 번째 callable이 아니라, 이미 목록에 있는 Next h6을 호출하는 표현식입니다.
또한 실행을 시작할 수 있는 operation은 Work이므로 EntryCallable도 Work h44입니다.

공통 예제의 호출 직전 hirArtifact.Source.Program.Callables = [Next h6, Work h44]
hirArtifact.Source.Program.EntryCallable = Work h44
traceSink = null 
private static MirSnapshot LowerHirArtifact(
    HirSemanticArtifact hirArtifact,
    IMirLoweringTraceSink? traceSink)
{
    // hirArtifact에는 의미 분석이 끝난 최종 HIR이 들어 있습니다.
    // Callables = [Next h6, Work h44]
    // EntryCallable = Work h44
    ArgumentNullException.ThrowIfNull(hirArtifact);

    var hirSnapshot = hirArtifact.Source;
    var hirProgram = hirSnapshot.Program;

    // 예제값: hirEntryCallable = Work h44
    var hirEntryCallable = hirProgram.EntryCallable
        ?? throw new InvalidOperationException(
            "validated HIR must contain an operation before MIR lowering");

    // 아직 변환한 callable이 없으므로 두 값 모두 비어 있습니다.
    var mirCallables = new List<MirCallable>();
    MirCallable? mirEntryCallable = null;

    foreach (var hirCallable in hirProgram.Callables)
    {
        // 첫 반복: hirCallable = Next h6
        // 둘째 반복: hirCallable = Work h44
        // 반복마다 새 lowerer를 만들기 때문에 두 callable의 작업 상태는 섞이지 않습니다.
        var mirCallableLowerer = new HirCallableToMirLowerer(
            hirCallable,
            hirArtifact,
            traceSink);

        // 첫 반복 결과: mirCallable = Next c6
        // 둘째 반복 결과: mirCallable = Work c44
        var mirCallable = mirCallableLowerer.LowerToMirCallable();

        // 첫 반복 뒤: mirCallables = [Next c6]
        // 둘째 반복 뒤: mirCallables = [Next c6, Work c44]
        mirCallables.Add(mirCallable);

        // Next는 진입 operation이 아니므로 첫 반복에서는 false입니다.
        // Work는 hirEntryCallable과 같은 객체이므로 둘째 반복에서 true입니다.
        if (ReferenceEquals(hirCallable, hirEntryCallable))
            mirEntryCallable = mirCallable;
    }

    // 최종 결과:
    // Callables  = [Next c6, Work c44]
    // EntryPoint = Work c44
    var mirProgram = new MirProgram(
        mirEntryCallable
            ?? throw new InvalidOperationException(
                "validated HIR entry callable must be lowered into MIR"),
        mirCallables);

    return MirSnapshot.CreateLowered(mirProgram);
}

코드 순서대로 따라가기

  1. 입력을 확인합니다. callable 목록은 [Next h6, Work h44]이고 진입 callable은 Work h44입니다.
  2. 첫 반복에서 Next h6을 처리합니다. 새 lowerer가 Next c6을 반환하며 결과 목록은 [Next c6]이 됩니다.
  3. 둘째 반복에서 Work h44을 처리합니다. 새 lowerer가 Work c44을 반환하며 결과 목록은 [Next c6, Work c44]이 됩니다.
  4. 진입점을 연결합니다. 둘째 반복의 HIR 객체가 EntryCallable과 같으므로 mirEntryCallable = Work c44가 됩니다.
  5. 프로그램과 snapshot을 만듭니다. 두 callable과 진입점을 가진 mirProgram을 MirSnapshot.CreateLowered(mirProgram)에 전달합니다.
반환 결과 MirSnapshot
Program.Callables = [Next c6, Work c44]
Program.EntryPoint = Work c44

HirCallableToMirLowerer(...) 생성자

HIR callable 하나를 담당할 lowerer에 변환 대상과 최종 의미 정보를 보관하고, MIR callable ID를 준비하는 생성자입니다.
공통 예제에서는 Next h6과 Work h44를 대상으로 각각 한 번씩 실행됩니다. 

public HirCallableToMirLowerer(
    HirCallable hirCallable,
    HirSemanticArtifact hirArtifact,
    IMirLoweringTraceSink? traceSink)
{
    // 첫 번째 호출:
    // hirCallable = Next h6
    // hirArtifact = 최종 HIR artifact([Next h6, Work h44])
    // traceSink = null
    //
    // 두 번째 호출:
    // hirCallable = Work h44
    // hirArtifact = 최종 HIR artifact([Next h6, Work h44])
    // traceSink = null

    _hirCallable = hirCallable;
    _hirArtifact = hirArtifact;

    // 첫 번째 호출: hirCallable.Id.Value = 6  → _mirCallableId = c6
    // 두 번째 호출: hirCallable.Id.Value = 44 → _mirCallableId = c44
    _mirCallableId = new MirCallableId(hirCallable.Id.Value);
    _traceSink = traceSink;
}

LowerToMirCallable()

하나의 HIR callable을 진입 block, 매개변수, 본문, 종료를 가진 MirCallable로 완성하는 중심 함수입니다.
공통 예제에서는 Next h6을 가진 lowerer와 Work h44을 가진 lowerer에서 각각 한 번씩 실행됩니다.

1. Next h6 처리

function Next(value: int): int
{
    return value + 1;
}

Next 원본 코드가 만든 매개변수와 MIR 본문

아래 도식은 LowerToMirCallable()이 callable 하나를 처음부터 MirCallable 반환까지 처리하는 과정을 단계별로 보여줍니다.
왼쪽은 실제 C# 코드이고, 오른쪽은 각 코드 범위가 Next 실행에서 만든 상태입니다.
이 실행의 시작값은 _hirCallable = Next h6, _mirCallableId = c6입니다.

Next의 명시적 return이 b0를 닫으므로 본문 처리 뒤의 현재 block은 null입니다.
따라서 열린 operation 경로에 implicit return을 붙이는 분기는 실행되지 않습니다.

2. Work h44 처리

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

Work 원본 코드가 만든 MIR builder

같은 LowerToMirCallable()을 이번에는 Work 입력으로 다시 따라갑니다.
이 실행의 시작값은 _hirCallable = Work h44, _mirCallableId = c44입니다.

LowerParameters()

현재 HIR callable의 매개변수를 앞에서부터 읽어 MIR 매개변수로 등록하는 함수입니다.
공통 예제에서는 매개변수 하나를 가진 Next h6에서 한 번 실행되고, 매개변수가 없는 Work h44에서도 한 번 실행됩니다.

코드에 나오는 _mirValues, _mirParameters, _currentMirBlockBuilder, _currentFlowState는 지역 변수가 아니라 현재 lowerer 객체의 필드입니다.
실제 선언은 private readonly List<MirValue> _mirValues = new();, private readonly List<IMirParameter> _mirParameters = new();, private MirBlockBuilder? _currentMirBlockBuilder;, private LoweringFlowState _currentFlowState = new();입니다.

1. Next h6의 value 등록

function Next(value: int): int
{
    return value + 1;
}

이 실행에서 읽는 대상은 괄호 안의 value: int 하나입니다.
진입 block b0는 이미 만들어져 있지만 아직 비어 있으며, 매개변수와 MIR 값을 담을 목록도 빈 상태에서 시작합니다.

보라색 이름이 가리키는 값

보라색 표기는 lowerer의 필드명 또는 그 필드에서 시작한 프로퍼티 경로입니다.

_hirCallable
HirCallable현재 변환하는 HIR callable 선언 하나
_mirCallableId
MirCallableId현재 만들 MIR callable의 식별자
_hirCallable.Parameters
IReadOnlyList<HirParameter>HIR 매개변수를 선언 순서대로 담은 목록
_mirParameters
List<IMirParameter>지금까지 등록한 MIR 매개변수 목록
_mirValues
List<MirValue>현재 callable에서 생성한 MIR 값 목록
_currentFlowState
LoweringFlowState현재 경로의 심벌별 값·큐비트와 수명 상태
_currentMirBlockBuilder
MirBlockBuilder?현재 instruction을 추가할 block builder

2. 매개변수가 없는 Work h44 처리

Work()의 괄호 안에는 매개변수가 없습니다.
따라서 같은 LowerParameters()에 들어오지만, 이번에는 for 본문을 한 번도 실행하지 않습니다.

즉 Work 실행에서는 새 매개변수 객체도, 새 MIR 값도 만들어지지 않습니다.
다만 b0가 비어 있는 이유는 Work에 매개변수가 없기 때문만은 아닙니다. 이 함수는 callable 매개변수를 등록할 뿐 block argument나 instruction을 추가하지 않으므로, Next와 Work 모두 b0를 변경하지 않습니다.

LowerClassicalParameter()

HIR의 고전 매개변수 하나를 MIR 값과 MirClassicalParameter로 등록하는 함수입니다.
아래 실행에서는 Next(value: int)의 value h0 하나를 처리합니다.

실제 인수 hirParameter = value h0
hirParameterSymbolId = SymbolId(value)
mirParameterOrigin = MirHirOrigin(HIR h0, value의 source span)
requiredArrayLengths = null 
private void LowerClassicalParameter(
    HirParameter hirParameter,
    SymbolId hirParameterSymbolId,
    MirOrigin mirParameterOrigin,
    IReadOnlyDictionary<string, long>? requiredArrayLengths)
{
    /* value는 배열이 아닌 int입니다.
    mirParameterType = MirType.Scalar(int) */
    var mirParameterType = hirParameter.IsArray
        ? MirType.Array(hirParameter.Type, hirParameter.RegisterSize)
        : MirType.Scalar(hirParameter.Type);

    /* 아직 실제 정수는 정해지지 않았습니다.
    %v0는 호출할 때 value로 들어올 int 값을 나타냅니다.

    _mirValues
    └─ [0] MirValue %v0
       ├─ Id = v0
       ├─ Type = int
       └─ Origin = MirHirOrigin(value h0) */
    var mirParameterValue = CreateMirValue(
        mirParameterType,
        hirParameterSymbolId,
        mirParameterOrigin);

    /* scalar이므로 결과는 (null, 0)입니다. */
    var (mirArrayStorage, minimumLength) =
        CreateMirParameterStorage(
            hirParameter,
            hirParameterSymbolId,
            mirParameterOrigin,
            requiredArrayLengths);

    /* SymbolId(value) ──▶ MirValueId v0 */
    _currentFlowState.CurrentMirValueByHirSymbolId[hirParameterSymbolId] = mirParameterValue.Id;

    /* mirArrayStorage = null이므로 Scalar를 호출합니다.
    Name, Ownership, Access는 hirParameter에서 직접 읽습니다. */
    var mirParameter = mirArrayStorage is null
        ? MirClassicalParameter.Scalar(
            hirParameter,
            mirParameterValue)
        : MirClassicalParameter.Array(
            hirParameter,
            mirParameterValue,
            mirArrayStorage,
            minimumLength);

    /* _mirParameters
    └─ [0] MirClassicalParameter value
       ├─ Value ──▶ _mirValues[0] (%v0)
       ├─ Storage = null
       ├─ Ownership = Borrowed
       ├─ Access = ReadOnly
       └─ MinimumLength = 0 */
    _mirParameters.Add(mirParameter);
}

CreateMirParameterStorage()

고전 매개변수 하나가 scalar인지 array인지 확인하고, 그 매개변수에 필요한 MirArrayStorage?와 MinimumLength를 함께 반환하는 함수입니다.
scalar이면 (null, 0)을 반환하고, array이면 새 storage를 만든 뒤 최소 길이를 계산해 반환합니다.

Next(value: int) 처리

실제 인수 hirParameter = value h0
hirParameterSymbolId = value 선언의 SymbolId
mirParameterOrigin = MirHirOrigin(HIR h0, value의 source span)
requiredArrayLengths = null 
private (MirArrayStorage? Storage, int MinimumLength)
    CreateMirParameterStorage(
        HirParameter hirParameter,
        SymbolId hirParameterSymbolId,
        MirOrigin mirParameterOrigin,
        IReadOnlyDictionary<string, long>? requiredArrayLengths)
{
    /* value는 scalar이므로 이 분기를 선택합니다.
    반환값 = (Storage: null, MinimumLength: 0) */
    if (!hirParameter.IsArray) return (null, 0);

    /* 아래는 array 매개변수일 때만 실행됩니다.
    새 storage를 만들고 HIR 심벌과 MIR storage의 연결을 기록합니다. */
    var mirArrayStorage = new MirArrayStorage(
        AllocateMirStorageId(),
        hirParameter.Name,
        mirParameterOrigin);
    _traceSink?.LinkStorage(
        hirParameterSymbolId,
        _mirCallableId,
        mirArrayStorage.Id);

    /* array 매개변수의 기본 최소 길이는 1입니다.
    호출 계약에 더 큰 길이가 기록되어 있으면 그 길이를 사용합니다. */
    var minimumLength = 1;
    if (requiredArrayLengths is not null
        && requiredArrayLengths.TryGetValue(
            hirParameter.Name,
            out var requiredLength))
    {
        if (requiredLength < 0 || requiredLength > int.MaxValue)
        {
            throw MirLoweringError(
                $"array parameter `{hirParameter.Name}` has invalid "
                + $"minimum length {requiredLength}");
        }

        minimumLength = Math.Max(minimumLength, (int)requiredLength);
    }

    return (mirArrayStorage, minimumLength);
}

LowerQubitParameter()

HIR의 큐비트 매개변수 하나를 최초 버전의 MirQubitParameter로 만들고, 현재 lowerer의 큐비트 상태에 등록하는 함수입니다.
기존 Next와 Work에는 큐비트 매개변수가 없으므로, 아래의 작은 보조 프로그램에서 target 하나가 처리되는 과정을 따라갑니다.

실행에 사용할 callable

operation Apply(target: Qubit)
{
    X(target);
}

operation Main()
{
    use q = Qubit[1];
    Apply(q[0]);
}

현재 CLI에서 두 callable은 Apply h7/c7과 Main h17/c17입니다.
지금 처리할 대상은 Apply의 target h0 하나이며, Main은 프로그램의 진입 operation을 제공하기 위해 함께 있습니다.
LowerParameters()가 먼저 target의 선언 심벌을 root lifetime frame에 등록한 다음, 아래의 LowerQubitParameter()를 호출합니다.

이 함수가 변경하는 컬렉션

각 컬렉션은 같은 큐비트 매개변수를 서로 다른 목적으로 참조합니다.

_initialMirQubitsById
Dictionary<MirQubitId, MirQubit>큐비트 ID별 최초 버전
_nextMirQubitVersionById
Dictionary<MirQubitId, int>다음에 할당할 버전 번호
CurrentMirQubitByHirSymbolId
Dictionary<SymbolId, MirQubit>HIR 심벌이 현재 가리키는 큐비트 버전
_mirParameters
List<IMirParameter>callable의 MIR 매개변수 목록

_initialMirQubitsById[q0], CurrentMirQubitByHirSymbolId[SymbolId(target)], _mirParameters[0]에는 동일한 MirQubitParameter target q0.v0 객체가 들어갑니다.
이 함수는 매개변수를 등록할 뿐 instruction을 방출하지 않으므로 b0는 그대로 비어 있습니다.
q0.v1은 이 함수에서 만들지 않으며, 본문의 X(target)이 큐비트 상태를 변경할 때 생성됩니다.

LowerStatements()

HIR 문장 목록을 앞에서부터 순회하며 각 문장을 LowerStatement()에 전달하는 함수입니다.
아래에서는 Next 처리를 먼저 끝까지 확인한 다음, Work 처리로 넘어갑니다.

1. Next 본문 처리

function Next(value: int): int
{
    return value + 1;
}

hirStatements에는 return value + 1; 한 문장만 들어 있으며, 시작할 때 현재 block은 b0입니다.
따라서 바깥 for는 한 번만 실행됩니다. 

private void LowerStatements(IReadOnlyList<HirStatement> hirStatements)
{
    /* Next 본문을 처리할 때의 실제 입력
    ├─ hirStatements = [return value + 1]
    ├─ hirStatements.Count = 1
    └─ _currentMirBlockBuilder = b0 */
    for (var hirStatementIndex = 0;
         hirStatementIndex < hirStatements.Count;
         hirStatementIndex++)
    {
        /* 첫 반복
        ├─ hirStatementIndex = 0
        ├─ hirStatements[0] = return value + 1
        └─ 현재 block = b0

        b0이 열려 있으므로 아래 null 분기는 실행하지 않습니다. */
        if (_currentMirBlockBuilder is null)
        {
            /* 앞 문장이 현재 경로를 끝냈는데 남은 문장이 있을 때만 실행합니다.
               남은 문장은 MIR로 만들지 않으며, traceSink가 있으면
               그 안의 선언 symbol을 '도달 불가'로 기록합니다. */
            for (;
                 hirStatementIndex < hirStatements.Count;
                 hirStatementIndex++)
            {
                MarkUnreachableDeclarations(
                    hirStatements[hirStatementIndex]);
            }
            return;
        }

        /* return 문장을 LowerStatement()에 전달합니다.

        호출 전                       호출 후
        현재 block = b0               b0.Terminator = return %v2
                                      현재 block = null */
        LowerStatement(hirStatements[hirStatementIndex]);
    }

    /* hirStatementIndex가 1로 증가합니다.
       1 < hirStatements.Count(1)가 false이므로 for가 끝납니다.
       따라서 현재 block이 null인 상태로 이 함수를 종료합니다. */
}

2. Work 본문 처리

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

먼저 Work의 최상위 다섯 문장을 입력으로 한 번 실행합니다.
이 실행이 if 문장을 처리할 때 참 본문과 빈 거짓 본문을 각각 다시 전달하므로, Work 처리 안에서는 LowerStatements()가 모두 세 번 실행됩니다. 

private void LowerStatements(IReadOnlyList<HirStatement> hirStatements)
{
    /* Work를 처리하는 동안 같은 LowerStatements() 본문에 세 번 진입합니다.

    첫 번째 호출 — Work 최상위 본문
    ├─ hirStatements = [var values, use q, 배열 대입, if, H]
    ├─ 시작 block = b0
    ├─ 반복 5회
    └─ index 3의 if를 처리하는 동안 아래 두 호출을 실행합니다.

       LowerStatement(if)
       └─ LowerIf()
          ├─ LowerScopedBranch(b1, 참 본문)
          │  └─ 두 번째 호출: LowerStatements([X(q[0])])
          └─ LowerScopedBranch(b2, 거짓 본문)
             └─ 세 번째 호출: LowerStatements([])

    두 번째 호출 — if 참 본문
    ├─ hirStatements = [X(q[0])]
    ├─ 시작 block = b1
    └─ 반복 1회

    세 번째 호출 — if 거짓 본문
    ├─ hirStatements = []
    ├─ 시작 block = b2
    └─ 반복 0회 */
    for (var hirStatementIndex = 0;
         hirStatementIndex < hirStatements.Count;
         hirStatementIndex++)
    {
        /* 첫 번째 호출과 두 번째 호출은 현재 block이 열려 있으므로
           아래 null 분기를 실행하지 않습니다.

        첫 번째 호출
        ├─ index 0~3을 시작할 때 현재 block = b0
        └─ index 4를 시작할 때 현재 block = b3

        두 번째 호출
        └─ index 0을 시작할 때 현재 block = b1

        세 번째 호출은 hirStatements.Count가 0이므로
        for 본문 자체를 한 번도 실행하지 않습니다. */
        if (_currentMirBlockBuilder is null)
        {
            /* 앞 문장이 현재 경로를 끝냈는데 남은 문장이 있을 때만 실행합니다.
               남은 문장은 MIR로 만들지 않으며, traceSink가 있으면
               그 안의 선언 symbol을 '도달 불가'로 기록합니다. */
            for (;
                 hirStatementIndex < hirStatements.Count;
                 hirStatementIndex++)
            {
                MarkUnreachableDeclarations(
                    hirStatements[hirStatementIndex]);
            }
            return;
        }

        /* 첫 번째 호출의 실행 흐름
        ├─ index 0: var       처리 후 현재 block = b0
        ├─ index 1: use       처리 후 현재 block = b0
        ├─ index 2: 배열 대입 처리 후 현재 block = b0
        ├─ index 3: if를 LowerStatement()에 전달합니다.
        │
        │  이 LowerStatement(if) 호출이 끝나기 전에
        │  첫 번째 LowerStatements() 호출은 여기서 잠시 멈춥니다.
        │
        │  두 번째 호출
        │  ├─ hirStatementIndex = 0
        │  ├─ X(q[0])을 LowerStatement()에 전달합니다.
        │  └─ 현재 block = b1인 상태로 종료합니다.
        │
        │  세 번째 호출
        │  ├─ hirStatements.Count = 0
        │  ├─ for 본문을 실행하지 않습니다.
        │  └─ 현재 block = b2인 상태로 종료합니다.
        │
        │  두 호출이 끝나면 LowerIf()가 b1과 b2를 b3에 연결합니다.
        │  현재 block을 b3으로 바꾼 뒤 첫 번째 호출의 index 3으로 돌아옵니다.
        └─ index 4: H를 처리한 뒤 현재 block = b3 */
        LowerStatement(hirStatements[hirStatementIndex]);
    }

    /* 호출이 반환되는 순서
    1. 두 번째 호출이 b1을 남기고 반환합니다.
    2. 세 번째 호출이 b2를 남기고 반환합니다.
    3. 첫 번째 호출이 b3을 남기고 반환합니다. */
}

Work 최상위 목록에서 hirStatementIndex가 가리키는 문장

Work 처리에서 현재 block이 이동하는 경로

LowerStatement()

HIR 문장 하나의 종류를 확인하고 그 종류를 담당하는 lowering 함수로 전달합니다.
이 함수 자체의 일은 아래 switch에서 정확히 한 분기를 선택하고, 그 분기의 helper를 한 번 호출한 뒤 종료하는 것입니다.

공통 예제에서 이 함수가 받는 모든 문장

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

LowerStatement()은 위 프로그램 전체를 한꺼번에 받지 않고, 호출될 때마다 문장 하나만 받습니다.
공통 예제에서는 Next의 return 한 번과 Work의 문장 여섯 번을 합쳐 모두 일곱 번 실행됩니다.
아래 switch는 현재 인수 hirStatement의 실제 HIR 타입만 확인합니다. case가 적힌 순서는 실행 순서가 아니며, 한 번 호출될 때 일치하는 case 하나만 실행됩니다. 

1. Next: return value + 1

2. Work: var values = [0]
3. Work: use q = Qubit[1]
4. Work: values[0] = Next(values[0])
5. Work: if (values[0] == 1)
   6. 참 본문: X(q[0])
7. Work: H(q[0])

6번 X(q[0])은 5번 if을 처리하는 도중 발생하는 중첩 실행입니다.
반면에 4번 대입문 안의 Next(values[0])은 표현식이므로 별도의 LowerStatement() 실행으로 세지 않습니다. 

private void LowerStatement(HirStatement hirStatement)
{
    switch (hirStatement)
    {
        // Work의 use q 문장이 선택합니다.
        case HirQubitDeclarationStatement hirQubitDeclaration:
            LowerQubitDeclaration(hirQubitDeclaration);
            return;

        // Work의 var values 문장이 선택합니다.
        case HirVariableDeclarationStatement hirDeclaration:
            LowerDeclaration(hirDeclaration);
            return;

        // Work의 values[0] 대입문이 선택합니다.
        case HirAssignmentStatement hirAssignment:
            LowerAssignment(hirAssignment);
            return;

        // Work의 H 호출이 선택합니다.
        // if 안의 X 호출도 중첩 본문을 처리할 때 같은 분기를 선택합니다.
        case HirCallStatement hirCallStatement:
            LowerStatementCall(hirCallStatement);
            return;

        // Work의 if 문장이 선택합니다.
        case HirIfStatement hirIf:
            LowerIf(hirIf);
            return;

        case HirForStatement hirFor:
            LowerFor(hirFor);
            return;

        case HirWhileStatement hirWhile:
            LowerWhile(hirWhile);
            return;

        case HirRepeatStatement hirRepeat:
            LowerRepeat(hirRepeat);
            return;

        // Next의 return 문장은 이 분기를 선택합니다.
        case HirReturnStatement hirReturn:
            LowerReturn(hirReturn);
            return;

        default:
            throw MirLoweringError(
                $"unsupported HIR statement {hirStatement.GetType().Name}");
    }
}

코드 순서대로 따라가기

  1. hirStatement의 실제 타입을 확인합니다. 일곱 번의 실행마다 현재 문장에 해당하는 HIR 타입이 들어 있습니다.
  2. 일치하는 case 하나를 선택합니다. 실제 문장과 선택되는 helper는 아래 표와 같습니다.
  3. helper 호출 직후 바로 종료합니다. 각 case 끝의 return 때문에 같은 문장을 다른 case에서 다시 처리하지 않습니다.

공통 예제에서 선택되는 분기

실행받은 Qora 문장일치하는 HIR 타입호출하는 helper
1return value + 1HirReturnStatementLowerReturn()
2var values = [0]HirVariableDeclarationStatementLowerDeclaration()
3use q = Qubit[1]HirQubitDeclarationStatementLowerQubitDeclaration()
4values[0] = Next(values[0])HirAssignmentStatementLowerAssignment()
5if (values[0] == 1)HirIfStatementLowerIf()
6, 7X(q[0]), H(q[0])HirCallStatementLowerStatementCall()

일곱 번의 실행은 모두 helper 하나를 호출한 뒤 값을 반환하지 않고 종료됩니다.

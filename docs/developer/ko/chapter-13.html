큐비트 identity와 버전

use, X, 분기 합류, H가 만드는 q0.v0~v3 추적

← 이전: 배열 Storage전체 목차
다음: Basic Block →

공통 소스의 use q = Qubit[1];이 LowerQubitDeclaration에 들어가면 첫 큐비트 상태 q0.v0이 등록됩니다.
바로 그 호출에서 출발하여 분기 안팎에서 같은 큐비트가 어떤 객체로 이어지는지 따라갑니다.
그 뒤 분기마다 복제된 dictionary, X 호출의 operand와 effect 판정, q0.v1 생성, 거짓 경로의 q0.v0 유지, Phi q0.v2, 마지막 H 결과 q0.v3을 순서대로 연결합니다.

이번 장에서 실제로 처리할 소스

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

추적 대상은 Work h44 → c44입니다.
LowerStatements(_hirCallable.Body.Statements)가 위 본문을 소스 순서대로 순회하며, 큐비트와 관련하여 처음 전달하는 인수는 use q = Qubit[1];을 나타내는 HirQubitDeclarationStatement입니다.

첫 큐비트 문장: use q = Qubit[1]

이 문장 직전에는 배열 선언만 끝났습니다.
따라서 b0에는 i0과 i1이 있고, 다음 instruction ID는 i2입니다.
큐비트 ID를 아직 하나도 할당하지 않았으므로 _initialMirQubitsById, 버전 counter, 현재 큐비트 dictionary는 모두 비어 있습니다. 

use 처리 직전
├─ _currentMirBlockBuilder = b0
├─ b0.Instructions         = [i0 MirConstant, i1 MirArrayCreate]
├─ 다음 instruction ID     = i2
├─ 다음 qubit ID           = q0
├─ _initialMirQubitsById   = {}
├─ _nextMirQubitVersionById = {}
└─ CurrentMirQubitByHirSymbolId = {}

LowerStatement은 인수의 실제 타입이 HirQubitDeclarationStatement이므로 아래 case를 선택합니다. 

case HirQubitDeclarationStatement hirQubitDeclaration:
    // hirQubitDeclaration = use q = Qubit[1];
    LowerQubitDeclaration(hirQubitDeclaration);
    return;

LowerQubitDeclaration 전체 코드와 상태 변경

private void LowerQubitDeclaration(
    HirQubitDeclarationStatement hirQubitDeclaration)
{
    var hirQubitSymbol = RequireHirDeclarationSymbol(
        hirQubitDeclaration.Id,
        $"qubit allocation `{hirQubitDeclaration.Name}`");
    _currentFlowState.TrackDeclaredHirSymbol(hirQubitSymbol.Id);
    // hirQubitDeclaration = use q = Qubit[1];
    // hirQubitSymbol      = 최종 HIR model의 Symbol(q)

    var mirOrigin = MirOriginFor(hirQubitDeclaration);
    var mirAllocatedQubit = new MirQubitFromUse(
        AllocateMirQubitId(),
        hirQubitDeclaration.Name,
        hirQubitDeclaration.Size,
        mirOrigin);
    // AllocateMirQubitId()      = q0
    // hirQubitDeclaration.Name = "q"
    // hirQubitDeclaration.Size = 1
    // mirAllocatedQubit        = q0.v0

    RegisterInitialMirQubit(hirQubitSymbol.Id, mirAllocatedQubit);
    // _initialMirQubitsById[q0]    = q0.v0
    // _nextMirQubitVersionById[q0] = 1

    EmitMirInstruction(new MirQubitAllocate(
        AllocateMirInstructionId(),
        mirAllocatedQubit,
        mirOrigin));
    // AllocateMirInstructionId() = i2
    // b0.Instructions에 i2 MirQubitAllocate(Result=q0.v0) 추가

    _currentFlowState.CurrentMirQubitByHirSymbolId[hirQubitSymbol.Id] =
        mirAllocatedQubit;
    // dictionary 변경: SymbolId(q) → q0.v0
}

MirQubitFromUse 생성자는 최초 버전을 v0으로 고정합니다.
RegisterInitialMirQubit는 그 객체를 q0의 권위 있는 최초 정의로 등록하고 다음 버전 번호를 1로 설정합니다.
마지막 dictionary 대입이 끝난 뒤부터 소스의 q 사용은 q0.v0을 찾을 수 있습니다. 

use 처리 직후
├─ i2 MirQubitAllocate.Result = q0.v0
├─ _initialMirQubitsById[q0] = q0.v0
├─ _nextMirQubitVersionById[q0] = 1
└─ CurrentMirQubitByHirSymbolId
   └─ SymbolId(q) → q0.v0

분기 직전 상태와 경로별 dictionary 복제

use 뒤의 배열 대입은 큐비트 dictionary를 변경하지 않습니다.
배열 대입까지 끝난 다음 LowerStatements가 if의 HIR 문장을 꺼내 LowerStatement(hirIf)에 전달하고, HirIfStatement case가 LowerIf(hirIf)을 호출합니다.
이 호출 직전에는 조건식을 아직 lowering하지 않았으므로 %v10, flowStateBeforeBranch, b1, b2가 존재하지 않습니다. 

LowerIf(hirIf) 호출 직전
├─ hirIf.Condition       = values[0] == 1
├─ hirIf.Then.Statements = [X(q[0]);]
├─ hirIf.Else.Statements = []
├─ _currentMirBlockBuilder = b0
├─ b0.Instructions         = [i0, i1, i2, i3, i4, i5, i6, i7]
├─ CurrentMirValueByHirSymbolId
│  └─ SymbolId(values) → %v6
├─ CurrentMirQubitByHirSymbolId
│  └─ SymbolId(q) → q0.v0
├─ 다음 instruction ID = i8
└─ 다음 value ID       = %v7

LowerIf 안에 들어간 뒤에는 다음 순서가 고정되어 있습니다.
먼저 LowerExpressionAs가 조건식을 끝까지 처리하여 i8~i11과 %v7~%v10을 만들고, 그 다음 RequireCurrentMirBlock()가 현재 builder b0를 반환합니다.
이어 현재 flow state를 clone한 뒤 b1과 b2를 만들며, 마지막으로 준비된 여섯 인수를 BranchTo에 전달합니다. 

LowerIf 내부의 실제 생성 순서
1. LowerExpressionAs(hirIf.Condition, bit)
   ├─ i8  MirConstant       → %v7
   ├─ i9  MirArrayLoad      → %v8
   ├─ i10 MirConstant       → %v9
   └─ i11 MirBinary(Equal)  → %v10
      └─ mirConditionValueId = %v10

2. RequireCurrentMirBlock()
   └─ mirBranchBlock = b0

3. _currentFlowState.Clone()
   └─ flowStateBeforeBranch = {values→%v6, q→q0.v0}

4. CreateMirBlock(mirOrigin)
   └─ mirThenBlock = b1

5. CreateMirBlock(mirOrigin)
   └─ mirElseBlock = b2

6. b0.BranchTo(%v10, b1, [], b2, [], mirOrigin)

b0.BranchTo(%v10, b1, [], b2, [], mirOrigin)가 b0를 닫은 뒤, LowerIf은 같은 flowStateBeforeBranch를 두 번 LowerScopedBranch에 전달합니다.
그러나 두 경로가 같은 mutable dictionary를 공유하지는 않습니다.
아래 전체 함수의 두 번째 줄이 인수로 받은 상태를 다시 Clone()하기 때문입니다. 

private (
    MirBlockBuilder? ExitBlock,
    LoweringFlowState ExitFlowState) LowerScopedBranch(
    MirBlockBuilder mirBranchBlock,
    LoweringFlowState entryFlowState,
    IReadOnlyList<HirStatement> hirStatements)
{
    _currentMirBlockBuilder = mirBranchBlock;
    _currentFlowState = entryFlowState.Clone();
    _currentFlowState.PushHirSymbolLifetimeFrame();
    LowerStatements(hirStatements);
    _currentFlowState.PopHirSymbolLifetimeFrame();
    return (_currentMirBlockBuilder, _currentFlowState);
}

// 첫 호출
// mirBranchBlock = b1
// entryFlowState = {values→%v6, q→q0.v0}
// hirStatements  = [X(q[0]);]

// 둘째 호출
// mirBranchBlock = b2
// entryFlowState = {values→%v6, q→q0.v0}
// hirStatements  = []

참 경로: X(q[0])이 q0.v1을 만드는 과정

첫 LowerScopedBranch는 현재 block을 b1로, 현재 큐비트 dictionary를 SymbolId(q) → q0.v0으로 설정합니다.
그 뒤 LowerStatements([X(q[0]);])가 HirCallStatement을 전달하고, LowerStatementCall에 진입합니다.

LowerStatementCall에서 현재 q 조회

아래는 예제값 주석을 덧붙인 LowerStatementCall 전체 함수입니다.
의미 model이 X를 SymbolKind.BuiltinGate로 결합했으므로 user callable 분기는 건너뛰고 built-in gate 경로를 선택합니다. 

private void LowerStatementCall(
    HirCallStatement hirCallStatement)
{
    var mirCallOrigin = MirOriginFor(hirCallStatement);
    var hirCall = hirCallStatement.Call;
    var semanticCallTargetSymbol =
        RequireHirCallTargetSymbol(hirCall);
    // hirCallStatement         = X(q[0]);
    // hirCall                  = X(q[0])
    // semanticCallTargetSymbol = BuiltinGate symbol "X"

    if (semanticCallTargetSymbol.Kind == SymbolKind.Callable)
    {
        // X는 BuiltinGate이므로 이 분기를 선택하지 않음
        var hirUserCallable = RequireHirCallableDeclaration(
            semanticCallTargetSymbol);
        if (hirUserCallable.IsFunction)
        {
            LowerPureCall(hirCall);
            return;
        }

        LowerUserOperationCall(
            hirCallStatement,
            hirUserCallable);
        return;
    }

    if (semanticCallTargetSymbol.Kind
        != SymbolKind.BuiltinGate)
    {
        throw MirLoweringError(
            $"statement call `{hirCall.Name}` targets semantic symbol kind "
            + semanticCallTargetSymbol.Kind);
    }
    // Kind가 BuiltinGate이므로 검사를 통과함

    var builtinGateName =
        semanticCallTargetSymbol.SourceName;
    var builtinGateSignature = QoraGates.SigOf(
        builtinGateName,
        hirCallStatement.Modifiers.Count(
            modifier => modifier == QGateModifier.Controlled))
        ?? throw MirLoweringError(
            $"validated built-in gate `{builtinGateName}` has no signature");
    var mirCallOperands =
        new List<MirCallOperand>(hirCall.Arguments.Count);
    // builtinGateName      = "X"
    // builtinGateSignature = X의 매개변수 계약
    // mirCallOperands      = []

    for (var argumentIndex = 0;
         argumentIndex < hirCall.Arguments.Count;
         argumentIndex++)
    {
        var hirArgument =
            hirCall.Arguments[argumentIndex];
        var builtinParameterSpec =
            builtinGateSignature.Parameters[argumentIndex];
        // argumentIndex            = 0
        // hirArgument.Expression   = q[0]
        // builtinParameterSpec.Type = QType.Qubit

        if (builtinParameterSpec.Type == QType.Qubit)
        {
            mirCallOperands.Add(new MirQubitCallOperand(
                LowerQubitAccess(hirArgument.Expression),
                hirArgument.Ownership,
                hirArgument.Access));
            // 이 분기를 선택함
        }
        else
        {
            var mirArgumentValueId = LowerExpressionAs(
                hirArgument.Expression,
                MirType.Scalar(builtinParameterSpec.Type));
            mirCallOperands.Add(new MirClassicalCallOperand(
                mirArgumentValueId,
                hirArgument.Ownership,
                hirArgument.Access));
        }
    }

    EmitMirQuantumApply(
        new MirBuiltinGateTarget(builtinGateName),
        mirCallOperands,
        Array.Empty<MirMutableArrayResult>(),
        LowerModifiersToMirFunctors(hirCallStatement.Modifiers),
        mirCallOrigin);
    // Target="X", Operands=[q0.v0[%v11]], MutableArrayResults=[], Functors=[]
}

LowerStatementCall의 for loop가 만든 지역 변수 hirArgument은 X의 첫 인수이며, hirArgument.Expression은 q[0]입니다.
이 값이 LowerQubitAccess(hirArgument.Expression)에 전달되어 함수 매개변수 hirExpression이 됩니다.
따라서 아래 코드는 LowerQubitAccess(HirExpression hirExpression)의 switch (hirExpression) 가운데 실제로 선택된 index-expression case입니다.
index expression case가 SymbolIdOf(q)를 얻고, 현재 참 경로 dictionary에서 q0.v0을 꺼냅니다.
이어 index 리터럴 0이 i12 MirConstant → %v11을 만들고, 반환값은 MirQubitAccess(q0.v0, %v11)입니다. 

case HirIndexExpression
{
    Receiver: HirNameExpression hirReceiverName,
    Index: { } hirIndex,
}:
{
    var hirSymbolId = SymbolIdOf(
        hirReceiverName,
        $"qubit name `{hirReceiverName.Name}`");
    // hirReceiverName = "q"
    // hirSymbolId     = SymbolId(q)

    if (!_currentFlowState.CurrentMirQubitByHirSymbolId
        .TryGetValue(
            hirSymbolId,
            out var currentMirQubit))
    {
        throw MirLoweringError(
            $"name `{hirReceiverName.Name}` does not denote a qubit");
    }
    // 참 경로 dictionary 조회 결과: currentMirQubit = q0.v0

    var mirIndexValueId = LowerExpressionAs(
        hirIndex,
        MirType.Scalar(QType.Int));
    // hirIndex = 정수 리터럴 0
    // i12 MirConstant → %v11

    return new MirQubitAccess(
        currentMirQubit,
        mirIndexValueId,
        MirOriginFor(hirExpression));
    // 반환 = q0.v0[%v11]
}

호출 operand 완성

mirCallOperands[0]
└─ MirQubitCallOperand
   ├─ Qubit
   │  ├─ Qubit = MirQubitKey(q0, v0)
   │  ├─ Index = %v11
   │  └─ Origin = 소스의 q[0]
   ├─ Ownership = Borrowed
   └─ Access    = ReadOnly

q0의 숫자 0은 callable 안에서 큐비트 binding에 할당한 MirQubitId입니다.
반면에 q[0]의 index 0은 레지스터 원소 위치이며, 일반 고전 SSA 값 %v11로 전달됩니다.
따라서 q[0]에 접근해도 원소 전용 큐비트 ID를 새로 만들지는 않습니다.

effect 판정과 q0.v1 생성

EmitMirQuantumApply는 operand를 받자마자 무조건 새 버전을 만들지 않습니다.
먼저 WrittenQubitOperandIndexes를 호출하며, X에서는 AngleFirst=false, Unitary=true, Diagonal=false, control 수 0이므로 결과는 [0]입니다.
즉 유일한 큐비트 operand가 write 대상입니다. 

WrittenQubitOperandIndexes의 선택 결과
├─ mirCallTarget             = MirBuiltinGateTarget("X")
├─ firstQubitOperandIndex    = 0
├─ qubitOperandIndexes       = [0]
├─ !builtinGateInfo.Unitary  = false → 건너뜀
├─ builtinGateInfo.Diagonal  = false → 건너뜀
├─ controlQubitCount         = 0
└─ Skip(0)                   = [0]

아래 전체 함수에서 첫 instruction 할당은 i13입니다.
write operand 0에서 q0을 얻고, CreateQubitAfterInstruction(q0, origin)이 counter의 현재값 1을 사용하여 q0.v1을 만듭니다. 

private void EmitMirQuantumApply(
    MirCallTarget mirCallTarget,
    IReadOnlyList<MirCallOperand> mirCallOperands,
    IReadOnlyList<MirMutableArrayResult> mirMutableArrayResults,
    IReadOnlyList<MirFunctor> mirFunctors,
    MirOrigin mirOrigin)
{
    var mirInstructionId = AllocateMirInstructionId();
    var mirQubitResults =
        new List<MirQubitAfterInstruction>();
    var writtenMirQubitIds = new HashSet<MirQubitId>();
    var writtenQubitOperandIndexes = WrittenQubitOperandIndexes(
        mirCallTarget,
        mirCallOperands,
        mirFunctors);
    // mirInstructionId            = i13
    // writtenQubitOperandIndexes  = [0]

    foreach (var operandIndex in writtenQubitOperandIndexes)
    {
        if (operandIndex < 0
            || operandIndex >= mirCallOperands.Count)
        {
            throw MirLoweringError(
                $"quantum write operand {operandIndex} "
                + "is outside the operand list");
        }

        if (mirCallOperands[operandIndex]
            is not MirQubitCallOperand mirQubitOperand)
        {
            throw MirLoweringError(
                $"quantum write operand {operandIndex} is not a qubit");
        }

        var mirQubitId = mirQubitOperand.Qubit.Qubit.Id;
        // operandIndex = 0, mirQubitId = q0

        if (!writtenMirQubitIds.Add(mirQubitId))
            continue;

        mirQubitResults.Add(
            CreateQubitAfterInstruction(mirQubitId, mirOrigin));
        // counter 1을 소비하여 q0.v1 생성, 다음 counter는 2
    }

    EmitMirInstruction(new MirQuantumApply(
        mirInstructionId,
        mirCallTarget,
        mirCallOperands,
        mirQubitResults,
        mirMutableArrayResults,
        mirFunctors,
        mirOrigin));
    // b1.Instructions에 i13 MirQuantumApply("X") 추가
    // QubitResults = [q0.v1]

    foreach (var mirQubitResult in mirQubitResults)
        UpdateCurrentQubitAfterWrite(mirQubitResult);
    // 참 경로 dictionary 변경: SymbolId(q) → q0.v1
}
X 처리 직후의 참 경로
├─ b1.Instructions
│  ├─ i12 MirConstant → %v11
│  └─ i13 MirQuantumApply("X")
│     ├─ Operands     = [q0.v0[%v11]]
│     └─ QubitResults = [q0.v1]
├─ _nextMirQubitVersionById[q0] = 2
└─ CurrentMirQubitByHirSymbolId
   └─ SymbolId(q) → q0.v1

거짓 경로: q0.v0 유지

두 번째 LowerScopedBranch는 b2와 분기 전 상태의 새 clone으로 시작합니다.
hirStatements = []이므로 LowerStatements는 아무 instruction도 방출하지 않습니다.
따라서 거짓 경로의 exit dictionary는 입력과 같은 SymbolId(q) → q0.v0입니다. 

두 branch의 반환 상태
├─ thenBranchExit
│  ├─ ExitBlock = b1
│  └─ SymbolId(q) → q0.v1
└─ elseBranchExit
   ├─ ExitBlock = b2
   └─ SymbolId(q) → q0.v0

합류: 두 버전에서 q0.v2 생성

LowerIf은 두 경로를 모두 내린 다음에 CreateMirBlock(mirOrigin)을 호출하여 b3를 만듭니다.
고전 dictionary의 values는 양쪽 모두 %v6이므로 block argument를 만들지 않습니다.
이어 b1.JumpTo(b3, [], origin)과 b2.JumpTo(b3, [], origin)이 각각 정확한 incoming edge를 반환합니다. 

MergeQubitStatesAtJoin의 실제 인수
├─ mergedFlowState                = 분기 전 상태 clone, q→q0.v0
├─ firstPredecessorFlowState      = b1 exit, q→q0.v1
├─ firstIncomingEdge              = (Source=b1, SuccessorOrdinal=0)
├─ secondPredecessorFlowState     = b2 exit, q→q0.v0
├─ secondIncomingEdge             = (Source=b2, SuccessorOrdinal=0)
└─ mirJoinBlock                   = b3

merge 함수가 얻는 두 현재 key는 q0.v1과 q0.v0이므로 equality 분기는 거짓입니다.
따라서 CreateQubitPhi를 호출하며, 현재 counter 2가 새 버전 q0.v2에 사용됩니다. 

if (firstIncomingMirQubit.Key == secondIncomingMirQubit.Key)
{
    // q0.v1 != q0.v0이므로 실행하지 않음
    mergedFlowState.CurrentMirQubitByHirSymbolId[hirSymbolId] =
        firstIncomingMirQubit;
}
else
{
    var mirQubitPhi = CreateQubitPhi(
        hirSymbolId,
        mirMergeBlock,
        new[]
        {
            new MirQubitPhiInput(
                firstIncomingEdge,
                firstIncomingMirQubit),
            new MirQubitPhiInput(
                secondIncomingEdge,
                secondIncomingMirQubit),
        });
    // 입력 1 = Edge(b1,0), q0.v1
    // 입력 2 = Edge(b2,0), q0.v0
    // mirQubitPhi = q0.v2

    mergedFlowState.CurrentMirQubitByHirSymbolId[hirSymbolId] =
        mirQubitPhi;
    // 합류 dictionary: SymbolId(q) → q0.v2
}
b3.QubitPhis[0]
└─ MirQubitPhi q0.v2
   ├─ Input(Edge(b1,0), MirQubitKey(q0,v1))
   └─ Input(Edge(b2,0), MirQubitKey(q0,v0))

합류 완료 후
├─ _currentMirBlockBuilder = b3
├─ SymbolId(q) → q0.v2
└─ _nextMirQubitVersionById[q0] = 3

다음 소비처: H(q[0])이 q0.v3 생성

LowerIf이 반환하면 바깥 LowerStatements는 다음 소스 문장 H(q[0]);을 처리합니다.
현재 block은 b3이고 dictionary는 SymbolId(q) → q0.v2이므로, 앞에서 본 같은 LowerStatementCall 경로가 이번에는 q0.v2을 읽습니다. 

H(q[0])의 실제 생성 순서
├─ LowerQubitAccess(q[0])
│  ├─ dictionary 조회                  → q0.v2
│  ├─ i14 MirConstant(index 0)         → %v12
│  └─ MirQubitAccess                   → q0.v2[%v12]
├─ WrittenQubitOperandIndexes("H")     → [0]
├─ i15 MirQuantumApply("H")
│  ├─ Operands                         = [q0.v2[%v12]]
│  └─ QubitResults                     = [q0.v3]
├─ dictionary 변경                     → SymbolId(q) → q0.v3
└─ _nextMirQubitVersionById[q0]        = 4

이로써 q0.v2의 바로 다음 소비처는 i15의 operand이고, i15가 만든 q0.v3이 callable 종료 시점의 현재 버전이 됩니다.

추적을 마친 뒤 읽는 q0.v0의 의미

q0.v0
│  │
│  └─ v0: 같은 identity의 데이터 흐름 버전
└──── q0: Work 안에서 q binding에 할당된 큐비트 identity

q0는 use q에서 한 번 할당된 뒤 X, Phi, H를 지나도 유지됩니다.
반면에 버전은 write나 경로 합류가 발생할 때 v0 → v1 → v2 → v3으로 진행합니다.
이 버전은 실제 진폭이나 상태 벡터를 저장하지 않으며, 어느 instruction과 어느 경로의 결과를 다음 명령이 사용하는지 나타내는 symbolic identity입니다.

Phi는 양자 게이트가 아닙니다 q0.v2는 두 큐비트를 복제하거나 섞지 않습니다.
이미 선택된 실행 경로가 b1이면 q0.v1, b2이면 q0.v0을 이어받도록 MIR의 정의·사용 관계를 하나로 연결합니다.

소스 문장에서 다음 소비처까지의 전체 연결

use q = Qubit[1];
└─ i2 MirQubitAllocate → q0.v0
   └─ SymbolId(q) → q0.v0

if (%v10)                              // b0에서 분기
├─ 참 b1: X(q[0]);
│  ├─ i12 MirConstant → %v11
│  ├─ q0.v0[%v11]
│  └─ i13 MirQuantumApply("X") → q0.v1
│     └─ 참 경로 SymbolId(q) → q0.v1
│
└─ 거짓 b2: 본문 없음
   └─ 거짓 경로 SymbolId(q) → q0.v0

b3 합류
├─ Edge(b1,0), q0.v1 ─┐
│                     ├─ MirQubitPhi → q0.v2
├─ Edge(b2,0), q0.v0 ─┘
└─ SymbolId(q) → q0.v2

H(q[0]);
├─ i14 MirConstant → %v12
├─ q0.v2[%v12]
└─ i15 MirQuantumApply("H") → q0.v3
   └─ SymbolId(q) → q0.v3
이 장의 결론 use가 q0.v0을 등록하고, 참 경로의 X가 q0.v1을 만듭니다.
거짓 경로는 q0.v0을 유지하므로 합류점은 두 incoming edge를 q0.v2로 묶습니다.
마지막 H는 합류 dictionary에서 q0.v2을 읽어 q0.v3을 만듭니다.

다음 장에서는 같은 if 문장이 b0의 branch, b1과 b2의 jump, b3의 return으로 만들어지는 순서를 block builder 호출과 함께 추적합니다.

큐비트 identity와 버전

q0는 유지되고 v0 → v1 → v2 → v3이 생기는 이유

← 이전: 배열 Storage전체 목차
다음: Basic Block →

큐비트에 게이트를 적용해도 소스의 q 선언이 새 자원으로 바뀌는 것은 아닙니다.
MIR은 같은 논리적 큐비트 자원이라는 사실을 q0로 유지하면서, 게이트를 지나며 달라진 계산 상태를 v0, v1처럼 구분합니다.
아래 코드에서 길이 1인 큐비트 자원 q가 네 버전으로 이어지는 흐름만 살펴봅니다.

살펴볼 Qora 코드

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

q는 큐비트 하나를 가진 길이 1의 논리적 자원입니다.
조건이 참이면 먼저 X를 적용하고, 조건과 관계없이 마지막에는 H를 적용합니다.
이 예제를 실행하면 조건은 참이지만, MIR lowering은 Next 호출 결과를 미리 계산하지 않으므로 참·거짓 경로를 모두 보존합니다.

전체 버전 흐름

use q = Qubit[1]
        ↓
      q0.v0
       ├─────────────────┐
       │ 조건 참          │ 조건 거짓
       ↓                  │
  X 적용 → q0.v1          │ q0.v0 유지
       └─────────┬────────┘
                 ↓
        Phi 합류 → q0.v2
                 ↓
          H 적용 → q0.v3

모든 항목의 앞부분이 q0인 이유는 처음 선언한 논리적 큐비트 자원 q를 계속 사용하기 때문입니다.
뒷부분의 버전만 달라지는 이유는 각 지점에서 어느 게이트까지 거쳤는지를 구분해야 하기 때문입니다.

할당: 첫 상태 q0.v0

첫 문장 use q = Qubit[1];이 길이 1의 큐비트 자원을 할당하면 MIR은 그 자원에 q0이라는 identity를 부여합니다.
q0는 개별 원소 q[0]의 번호가 아니라, callable 안의 q 선언 전체를 구분하는 번호입니다. 실제 원소는 q0.v0[0]처럼 별도 인덱스로 선택합니다.
따라서 하드웨어의 물리 큐비트 번호를 뜻하지 않습니다.
동시에 아직 어떤 게이트도 지나지 않은 최초 버전 v0가 붙어 q0.v0이 됩니다. 

q0.v0
│  └─ v0: 할당 직후의 최초 버전
└──── q0: 이 논리적 큐비트 자원의 변하지 않는 identity

이후에 보이는 q0.v1, q0.v2, q0.v3은 모두 같은 논리적 자원 q0에 관한 기록입니다.
큐비트 자원을 세 개 더 할당한다는 뜻이 아닙니다.

분기: 참 경로만 X를 지납니다

if 분기에 들어올 때 두 경로 모두 같은 입력 q0.v0에서 시작합니다.
참 경로에서는 X가 q0.v0을 입력으로 받고, 게이트를 지난 결과를 새 버전 q0.v1로 기록합니다.
반면에 거짓 경로는 X를 실행하지 않으므로 그대로 q0.v0을 유지합니다. 

참 경로    q0.v0 ── X ──▶ q0.v1
거짓 경로  q0.v0 ─────────▶ q0.v0

이렇게 버전을 나누면 MIR을 읽는 분석기는 “이 값이 X를 지난 상태인가?”를 명령 순서를 다시 추측하지 않고도 알 수 있습니다.

합류: 두 가능성을 q0.v2로 묶습니다

if가 끝난 뒤에는 참 경로와 거짓 경로가 다시 하나로 합쳐집니다.
하지만 한쪽은 q0.v1이고 다른 쪽은 q0.v0이므로, 합류 지점에서 어느 버전 하나를 무조건 선택할 수는 없습니다.
MIR은 이 두 가능성을 Phi로 묶어 q0.v2를 만듭니다. 

참 경로 b1  → q0.v1 ─┐
                       ├─ Phi → q0.v2
거짓 경로 b2 → q0.v0 ─┘

Phi는 새 게이트가 아니며 새 큐비트를 할당하지도 않습니다.
실행이 b1에서 왔다면 q0.v1, b2에서 왔다면 q0.v0이라는 제어 흐름의 선택을 하나의 이름 q0.v2로 표현합니다.

합류 뒤 H: q0.v3

마지막 문장 H(q[0]);은 if 바깥에 있으므로 두 경로가 합쳐진 뒤 실행됩니다.
따라서 입력은 특정 경로의 q0.v0이나 q0.v1이 아니라, 두 가능성을 대표하는 q0.v2입니다.
H를 지난 결과는 다시 새 버전 q0.v3이 됩니다. 

q0.v2 ── H ──▶ q0.v3

정리

identity와 version q0는 처음 할당한 논리적 큐비트 자원 q의 identity이므로 유지됩니다.
v0 → v1 → v2 → v3은 그 자원이 어떤 게이트와 분기 합류를 거쳤는지 나타내는 계산 버전입니다.
따라서 q0.v3은 네 번째 자원이 아니라, 같은 q0의 최신 상태입니다.

다음 장에서는 이 버전들이 놓이는 그릇인 Basic Block을 살펴봅니다.
같은 if가 b0, b1, b2, b3으로 나뉘는 이유를 전체 흐름만 따라가며 확인합니다.

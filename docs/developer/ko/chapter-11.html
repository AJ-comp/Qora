고전 값과 SSA 버전

같은 변수의 값이 바뀔 때 MIR이 새 값 번호를 만드는 이유

← 이전: Callable lowering전체 목차
다음: Storage와 배열 상태 →

소스에서는 같은 변수 이름에 새 값을 대입할 수 있습니다.
MIR은 이전 값과 새 값을 구분하기 위해 값을 덮어쓰지 않고, 새 MIR 값이 생길 때마다 새로운 번호를 붙입니다. 이번 장에서는 이 규칙이 공통 예제에 어떻게 적용되는지만 살펴봅니다.

값이 바뀌는 소스 문장

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

이 장에서는 위 소스 가운데 values와 조건식의 고전 값만 따라갑니다.
values라는 이름은 하나뿐이지만 그 안의 값은 달라집니다.
선언 직후의 0번 원소는 0이고, 대입 뒤에는 Next가 반환한 값으로 바뀝니다. 조건문은 반드시 갱신된 두 번째 상태를 읽어야 합니다.

이름은 유지하고 값에 새 번호를 붙입니다

MIR의 %v1과 %v6은 서로 다른 소스 변수가 아닙니다.
둘 다 소스 변수 values와 관련된 값이지만, 서로 다른 시점의 배열 상태를 나타냅니다.

%v 뒤의 숫자는 값이 만들어진 순서를 구분하는 ID입니다.
각 ID는 한 번만 정의되며 나중에 다른 값으로 덮어쓰지 않습니다. 한 값이 한 번만 정의된다는 것은 SSA의 핵심 규칙입니다.

Next 안에서는 입력과 결과가 분리됩니다

function Next(value: int): int

%v0 = 매개변수 value
%v1 = 상수 1
%v2 = %v0 + %v1
return %v2

value + 1을 계산해도 매개변수 %v0 자체는 바뀌지 않습니다.
상수 1은 %v1, 덧셈 결과는 %v2라는 새 값이 됩니다. 따라서 어느 값이 어디에서 왔는지 계산선을 거꾸로 따라갈 수 있습니다.

값 번호는 callable 안에서만 구분하면 됩니다.
따라서 Next의 %v1과 아래에 나오는 Work의 %v1은 서로 다른 값이며 충돌하지 않습니다.

배열 선언에서 첫 상태가 만들어집니다

var values: int[] = [0];

%v0 = 상수 0
%v1 = [%v0]

현재 values → %v1

먼저 배열 원소로 넣을 숫자 0이 만들어지고, 그 값을 사용해 길이 1인 배열 상태 %v1이 만들어집니다.
이 시점부터 소스 이름 values를 읽으면 현재 값인 %v1을 사용합니다.

배열에는 값 버전과 별도로 storage 정체성도 있습니다.
쉽게 말해 storage는 “어느 배열 자리인가”를 나타내고, %v1 같은 SSA 값은 “그 배열이 지금 어떤 내용을 가지는가”를 나타냅니다. 이 구분은 12장에서 더 자세히 살펴봅니다.

배열 대입은 새 배열 상태를 만듭니다

values[0] = Next(values[0]);

%v2 = 저장할 위치 0
%v3 = 읽을 위치 0
%v4 = %v1[%v3]에서 읽은 값
%v5 = Next(%v4)의 반환값
%v6 = %v1의 %v2 위치를 %v5로 바꾼 새 배열 상태

현재 values: %v1 → %v6

중요한 부분은 %v1을 덮어쓰지 않는다는 점입니다.
원소를 갱신한 결과는 새 배열 상태 %v6이 되고, lowerer가 기억하는 “현재 values 값”만 %v6으로 바뀝니다.

따라서 대입 이전 계산은 계속 %v1을 가리킬 수 있고, 대입 이후 계산은 %v6을 읽습니다.
컴파일러는 값이 바뀐 시점을 잃지 않으면서도, 소스의 변수 이름은 하나로 유지할 수 있습니다.

조건문은 가장 최근 값을 읽습니다

조건식은 처음 배열 상태 %v1이 아니라 최신 상태 %v6을 읽습니다.
MIR은 Next의 결과를 미리 숫자 1로 바꾸지 않고 %v5라는 호출 결과로 보존합니다.
따라서 조건 비교 결과도 미리 true로 고정하지 않으며, 실행할 때 계산되는 %v10이 어느 block으로 이동할지 결정합니다.

정리

같은 이름, 서로 다른 시점의 값 소스 이름 values는 그대로 유지됩니다.
반면 현재 배열 상태는 선언 직후 %v1에서 대입 뒤 %v6으로 바뀌며, 두 MIR 값은 각각 한 번만 정의됩니다.

다음 장에서는 여기서 잠깐 언급한 배열 storage를 확대합니다.
같은 배열 자리와 시간에 따라 달라지는 배열 값이 MIR에서 어떻게 함께 표현되는지 살펴봅니다.

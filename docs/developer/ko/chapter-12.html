배열 Storage와 값 상태

values 선언부터 갱신된 배열을 조건식이 읽을 때까지의 실제 호출 추적

← 이전: 고전 SSA 값전체 목차
다음: 큐비트 버전 →

공통 예제에서 배열과 직접 관련된 첫 실행은 var values: int[] = [0];을 처리하는 LowerDeclaration입니다.
이 호출이 $s0, %v0, %v1을 만드는 순간부터 출발하여, 다음 대입이 %v2부터 %v6까지 만든 뒤 조건식이 정확히 %v6을 다시 읽는 지점까지 실제 실행 순서대로 이어갑니다.

이번 장에서 실제로 처리할 소스

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

HIR 단계가 끝난 시점에 Next는 h6, Work는 h44입니다.
MIR lowering은 같은 숫자를 보존하여 각각 c6과 c44를 사용합니다.
따라서 이 장에서 Next(c6)라고 쓰면 위의 Next h6을 가리키며, 추적 대상 callable은 Work(c44)입니다.

첫 문장 직전의 실제 상태와 진입 함수

LowerToMirCallable()은 Work의 진입 block builder를 먼저 만들었습니다.
이것이 b0이며, 아직 본문 문장을 하나도 처리하지 않았으므로 값·instruction·storage·큐비트 dictionary는 모두 비어 있습니다. 

Work(c44) 본문 처리 직전
├─ _currentMirBlockBuilder = b0
├─ b0.Instructions         = []
├─ _mirValues              = []
├─ 다음 instruction ID     = i0
├─ 다음 storage ID         = $s0
├─ CurrentMirValueByHirSymbolId = {}
└─ CurrentMirQubitByHirSymbolId = {}

여기서 hirStatements는 LowerToMirCallable()이 _hirCallable.Body.Statements를 그대로 LowerStatements에 전달한 값입니다.
따라서 이 목록의 각 원소는 별도의 재구성 결과가 아니라 Work의 HIR 본문 문장과 직접 대응합니다.
아래는 예제값 주석만 덧붙인 두 진입 함수의 전체 코드입니다. 

private void LowerStatements(IReadOnlyList<HirStatement> hirStatements)
{
    for (var hirStatementIndex = 0;
         hirStatementIndex < hirStatements.Count;
         hirStatementIndex++)
    {
        if (_currentMirBlockBuilder is null)
        {
            for (;
                 hirStatementIndex < hirStatements.Count;
                 hirStatementIndex++)
            {
                MarkUnreachableDeclarations(
                    hirStatements[hirStatementIndex]);
            }
            return;
        }
        LowerStatement(hirStatements[hirStatementIndex]);
        // 첫 반복의 인수 = HirVariableDeclarationStatement("values")
    }
}

private void LowerStatement(HirStatement hirStatement)
{
    switch (hirStatement)
    {
        case HirQubitDeclarationStatement hirQubitDeclaration:
            LowerQubitDeclaration(hirQubitDeclaration);
            return;

        case HirVariableDeclarationStatement hirDeclaration:
            LowerDeclaration(hirDeclaration);
            // 첫 문장은 이 case를 선택함
            // hirDeclaration = var values: int[] = [0];
            return;

        case HirAssignmentStatement hirAssignment:
            LowerAssignment(hirAssignment);
            return;

        case HirCallStatement hirCallStatement:
            LowerStatementCall(hirCallStatement);
            return;

        case HirIfStatement hirIf:
            LowerIf(hirIf);
            return;

        case HirForStatement hirFor:
            LowerFor(hirFor);
            return;

        case HirWhileStatement hirWhile:
            LowerWhile(hirWhile);
            return;

        case HirRepeatStatement hirRepeat:
            LowerRepeat(hirRepeat);
            return;

        case HirReturnStatement hirReturn:
            LowerReturn(hirReturn);
            return;

        default:
            throw MirLoweringError(
                $"unsupported HIR statement {hirStatement.GetType().Name}");
    }
}

첫 문장: var values: int[] = [0]

var values: int[] = [0];

LowerStatement의 실제 인수는 이 선언을 나타내는 HirVariableDeclarationStatement입니다.
따라서 HirVariableDeclarationStatement case가 선택되고, 호출은 LowerDeclaration(hirDeclaration)으로 이어집니다.

LowerDeclaration 전체 호출 흐름

아래 코드는 현재 구현의 LowerDeclaration 전체 함수에 공통 예제의 지역 변수값과 선택 여부를 주석으로 표시한 것입니다.
배열 분기를 처리한 뒤 return하므로 마지막 스칼라 경로는 이 예제에서 실행되지 않습니다. 

private void LowerDeclaration(HirVariableDeclarationStatement hirDeclaration)
{
    var hirDeclaredSymbol = RequireHirDeclarationSymbol(
        hirDeclaration.Id,
        $"declaration `{hirDeclaration.Name}`");
    var mirOrigin = MirOriginFor(hirDeclaration);
    // hirDeclaration    = var values: int[] = [0];
    // hirDeclaredSymbol = 최종 HIR model의 Symbol(values)
    // mirOrigin         = 이 선언의 HIR node와 source span

    if (hirDeclaration.IsArray)
    {
        // IsArray = true이므로 이 분기를 선택함
        var declaredElementQType = hirDeclaration.Type
            ?? hirDeclaredSymbol.Type
            ?? throw MirLoweringError(
                $"array `{hirDeclaration.Name}` has no element type");
        int declaredArrayLength;
        MirArrayInitialization mirArrayInitialization;
        List<MirValueId> mirElementValueIds;
        // declaredElementQType = QType.Int

        switch (hirDeclaration.Value)
        {
            case HirArrayCreationExpression hirArrayCreation:
                declaredArrayLength = hirArrayCreation.Length;
                mirArrayInitialization =
                    MirArrayInitialization.ZeroInitialized;
                mirElementValueIds = new List<MirValueId>();
                break;

            case HirArrayLiteralExpression hirArrayLiteral:
                // Value가 [0]이므로 이 case를 선택함
                declaredArrayLength = hirArrayLiteral.Elements.Count;
                mirArrayInitialization =
                    MirArrayInitialization.ExplicitElements;
                mirElementValueIds =
                    new List<MirValueId>(hirArrayLiteral.Elements.Count);
                foreach (var hirElementExpression in hirArrayLiteral.Elements)
                {
                    var mirElementValueId = LowerExpressionAs(
                        hirElementExpression,
                        MirType.Scalar(declaredElementQType));
                    mirElementValueIds.Add(mirElementValueId);
                    // hirElementExpression = 정수 리터럴 0
                    // EmitConstant가 i0과 %v0을 만들고 b0에 i0을 추가함
                    // mirElementValueId = %v0
                }
                break;

            default:
                throw MirLoweringError(
                    $"validated array `{hirDeclaration.Name}` "
                    + "has a non-array initializer");
        }

        // declaredArrayLength    = 1
        // mirArrayInitialization = ExplicitElements
        // mirElementValueIds     = [%v0]
        var mirArrayCreationInstructionId =
            AllocateMirInstructionId();
        var mirArrayStorage = new MirArrayStorage(
            AllocateMirStorageId(),
            hirDeclaration.Name,
            mirOrigin);
        var mirArrayType = MirType.Array(
            declaredElementQType,
            declaredArrayLength);
        var mirArrayValue = CreateMirValue(
            mirArrayType,
            hirDeclaredSymbol.Id,
            mirOrigin);
        // mirArrayCreationInstructionId = i1
        // mirArrayStorage              = $s0, Name = "values"
        // mirArrayType                 = int[1]
        // mirArrayValue                = %v1 : int[1]

        _traceSink?.LinkStorage(
            hirDeclaredSymbol.Id,
            _mirCallableId,
            mirArrayStorage.Id);
        EmitMirInstruction(new MirArrayCreate(
            mirArrayCreationInstructionId,
            mirArrayValue,
            mirArrayStorage,
            mirArrayInitialization,
            mirElementValueIds,
            mirOrigin));
        // b0.Instructions에 i1 MirArrayCreate를 추가함
        // i1.Result = %v1, i1.Storage = $s0, i1.Elements = [%v0]

        _currentFlowState.TrackDeclaredHirSymbol(
            hirDeclaredSymbol.Id);
        _currentFlowState.CurrentMirValueByHirSymbolId[
                hirDeclaredSymbol.Id] =
            mirArrayValue.Id;
        // dictionary 변경: SymbolId(values) → %v1
        return;
    }

    var declaredScalarQType = hirDeclaredSymbol.Type
        ?? hirDeclaration.Type
        ?? throw MirLoweringError(
            $"scalar `{hirDeclaration.Name}` has no inferred type");
    var mirInitialValueId = LowerExpressionAs(
        hirDeclaration.Value,
        MirType.Scalar(declaredScalarQType));
    TraceMirValueForHirSymbol(
        mirInitialValueId,
        hirDeclaredSymbol.Id);
    _currentFlowState.TrackDeclaredHirSymbol(hirDeclaredSymbol.Id);
    _currentFlowState.CurrentMirValueByHirSymbolId[
            hirDeclaredSymbol.Id] =
        mirInitialValueId;
}

선택된 경로를 실행 순서로 줄이면 다음과 같습니다.
리터럴 0이 먼저 i0 MirConstant → %v0을 만들고, 그 다음에 i1, $s0, %v1이 할당됩니다.
EmitMirInstruction이 i1 MirArrayCreate를 b0에 넣은 뒤에야 flow-state dictionary가 SymbolId(values) → %v1로 갱신됩니다. 

첫 문장 처리 직후
├─ b0.Instructions
│  ├─ i0 MirConstant    (Result=%v0, LiteralText="0")
│  └─ i1 MirArrayCreate (Result=%v1, Storage=$s0, Elements=[%v0])
├─ $s0 = MirArrayStorage(Name="values")
├─ CurrentMirValueByHirSymbolId
│  └─ SymbolId(values) → %v1
├─ 다음 value ID       = %v2
└─ 다음 instruction ID = i2

바로 다음 문장 use q = Qubit[1];이 i2 MirQubitAllocate를 추가합니다.
따라서 배열 대입을 시작할 때의 다음 instruction ID는 i3이며, 배열의 현재값은 여전히 %v1입니다.

두 번째 배열 문장 직전 상태

values[0] = Next(values[0]);
호출 직전
├─ _currentMirBlockBuilder = b0
├─ 다음 instruction ID     = i3
├─ 다음 value ID           = %v2
├─ SymbolId(values)        → %v1
└─ %v1                     = int[1] 배열의 현재 SSA 상태

LowerStatements의 셋째 반복은 이 문장을 HirAssignmentStatement로 전달합니다.
LowerStatement은 HirAssignmentStatement case를 선택하여 LowerAssignment(hirAssignment)을 호출합니다.

1. 왼쪽 index 계산

LowerAssignment은 target이 단순 이름인지 먼저 검사하지만, 실제 target은 HirIndexExpression(values[0])이므로 첫 if를 건너뜁니다.
이어지는 indexed-target 패턴은 성공하며, SymbolIdOf(hirArrayReceiver)가 HIR model에 이미 결합된 SymbolId(values)를 반환합니다.
dictionary 조회 결과는 currentMirArrayValueId = %v1이고, 왼쪽 index 리터럴 0을 내리면 i3 MirConstant → %v2가 생성됩니다.

2. 오른쪽 values[0] 읽기

다음 호출은 오른쪽 전체 식을 받는 LowerExpressionAs(hirAssignment.Value, int)입니다.
이 호출은 Next의 인수를 먼저 내려야 하므로 오른쪽 values[0]으로 재귀 진입합니다.
receiver인 values는 dictionary에서 %v1을 얻고, 오른쪽 index 리터럴은 별도의 i4 MirConstant → %v3을 만듭니다.
두 값을 받은 indexed-expression 분기는 i5 MirArrayLoad(Array=%v1, Index=%v3) → %v4를 방출합니다.

3. Next 호출

LowerPureCall의 실제 인수는 Next(values[0]) HIR call이며, 의미 model에서 찾은 대상은 Next h6입니다.
new MirCallableId(hirUserFunction.Id.Value)가 이 대상을 c6으로 보존합니다.
방금 만든 %v4가 유일한 MirClassicalCallOperand가 되고, i6 MirPureCall(Target=c6, Operands=[%v4]) → %v5가 생성됩니다.
실행 결과는 1이지만 lowering은 호출을 상수로 접지 않고 %v5라는 결과로 보존합니다.

4. MirArrayStore 생성

오른쪽 식 전체가 끝난 뒤에야 mirStoredValueId = %v5가 반환됩니다.
이제 store의 세 입력은 갱신 전 배열 %v1, 왼쪽 index %v2, 새 원소값 %v5로 모두 확정되었습니다.
LowerAssignment은 i7과 새 배열값 %v6을 할당하고, i7 MirArrayStore(Array=%v1, Index=%v2, Value=%v5) → %v6을 b0에 추가합니다.

5. 현재 배열 상태 교체

MirArrayStore는 %v1을 수정하지 않습니다.
대신 갱신된 전체 배열을 나타내는 %v6을 새로 만들며, 마지막 dictionary 대입이 SymbolId(values) → %v1을 SymbolId(values) → %v6으로 교체합니다.
이 대입이 바로 다음 조건식의 소비처를 결정합니다.

LowerAssignment 전체 코드와 예제값

private void LowerAssignment(HirAssignmentStatement hirAssignment)
{
    var mirOrigin = MirOriginFor(hirAssignment);
    // hirAssignment = values[0] = Next(values[0]);

    if (hirAssignment.Target is HirNameExpression hirNameTarget)
    {
        // Target은 HirIndexExpression이므로 이 경로를 선택하지 않음
        var hirTargetSymbolId = SymbolIdOf(
            hirNameTarget,
            $"assignment target `{hirNameTarget.Name}`");
        var mirTargetType =
            _currentFlowState.CurrentMirValueByHirSymbolId.TryGetValue(
                hirTargetSymbolId,
                out var currentMirValueId)
            ? MirTypeOf(currentMirValueId)
            : throw MirLoweringError(
                $"assignment target `{hirNameTarget.Name}` "
                + "has no SSA state");
        var mirAssignedValueId = LowerExpressionAs(
            hirAssignment.Value,
            mirTargetType);
        TraceMirValueForHirSymbol(
            mirAssignedValueId,
            hirTargetSymbolId);
        _currentFlowState.CurrentMirValueByHirSymbolId[
                hirTargetSymbolId] =
            mirAssignedValueId;
        return;
    }

    if (hirAssignment.Target is not HirIndexExpression
        {
            Receiver: HirNameExpression hirArrayReceiver,
        } hirIndexedTarget)
    {
        throw MirLoweringError(
            "unsupported assignment target "
            + $"`{HirExpressions.Render(hirAssignment.Target)}`");
    }
    // hirArrayReceiver = HirNameExpression("values")
    // hirIndexedTarget = 왼쪽 values[0]

    var hirArraySymbolId = SymbolIdOf(
        hirArrayReceiver,
        $"assignment target `{hirArrayReceiver.Name}`");
    if (!_currentFlowState.CurrentMirValueByHirSymbolId.TryGetValue(
            hirArraySymbolId,
            out var currentMirArrayValueId))
    {
        throw MirLoweringError(
            $"indexed assignment target `{hirArrayReceiver.Name}` "
            + "has no array state");
    }
    var mirArrayType = MirTypeOf(currentMirArrayValueId);
    if (!mirArrayType.IsArray)
    {
        throw MirLoweringError(
            $"indexed assignment target `{hirArrayReceiver.Name}` "
            + "is not an array");
    }
    // hirArraySymbolId       = SymbolId(values)
    // currentMirArrayValueId = %v1
    // mirArrayType           = int[1]

    var mirIndexValueId = LowerExpressionAs(
        hirIndexedTarget.Index,
        MirType.Scalar(QType.Int));
    // 왼쪽 index 0 → i3 MirConstant → %v2

    var mirStoredValueId = LowerExpressionAs(
        hirAssignment.Value,
        MirType.Scalar(mirArrayType.ElementType));
    // 오른쪽 Next(values[0])을 재귀적으로 모두 처리함
    // i4/%v3 → i5/%v4 → i6/%v5 순서
    // mirStoredValueId = %v5

    var mirIndexedTargetOrigin = MirOriginFor(hirIndexedTarget);
    var mirArrayStoreInstructionId = AllocateMirInstructionId();
    var mirUpdatedArrayValue = CreateMirValue(
        mirArrayType,
        hirArraySymbolId,
        mirOrigin);
    // mirArrayStoreInstructionId = i7
    // mirUpdatedArrayValue       = %v6 : int[1]

    EmitMirInstruction(new MirArrayStore(
        mirArrayStoreInstructionId,
        mirUpdatedArrayValue,
        currentMirArrayValueId,
        mirIndexValueId,
        mirStoredValueId,
        mirIndexedTargetOrigin));
    // b0에 i7 추가: Result=%v6, Array=%v1, Index=%v2, Value=%v5

    _currentFlowState.CurrentMirValueByHirSymbolId[
            hirArraySymbolId] =
        mirUpdatedArrayValue.Id;
    // dictionary 변경: SymbolId(values) → %v6
}

바로 다음 조건식이 %v6을 읽는 과정

if (values[0] == 1)
조건식 처리 직전
├─ CurrentMirValueByHirSymbolId[SymbolId(values)] = %v6
├─ 다음 instruction ID = i8
└─ 다음 value ID       = %v7

LowerIf은 먼저 LowerExpressionAs(hirIf.Condition, bit)을 호출합니다.
equality의 왼쪽 values[0]을 처리할 때 HirNameExpression 분기가 SymbolId(values)로 dictionary를 조회하므로 receiver는 %v6이 됩니다.
이후 index와 load, 상수, 비교가 순서대로 이어집니다. 

선택되는 expression 분기와 실제 결과

HirNameExpression("values")
└─ CurrentMirValueByHirSymbolId[SymbolId(values)] → %v6

HirIndexExpression(values[0])
├─ Receiver = %v6
├─ index 0  → i8 MirConstant → %v7
└─ load     → i9 MirArrayLoad(Array=%v6, Index=%v7) → %v8

HirIntegerLiteralExpression(1)
└─ i10 MirConstant → %v9

HirBinaryExpression(Equal)
└─ i11 MirBinary(Left=%v8, Right=%v9) → %v10

따라서 조건식은 배열 선언 때의 %v1을 다시 찾지 않습니다.
대입이 갱신한 dictionary에서 %v6을 얻고, i9이 바로 그 값을 배열 입력으로 소비합니다.
이렇게 선언에서 조건식까지의 실행 연결이 닫힙니다.

추적을 마친 뒤 정리하는 Storage와 provenance

이제 예제에서 실제로 필요해진 두 정보를 구분할 수 있습니다.
$s0는 소스의 values 선언에서 시작한 배열 identity이며, %v1과 %v6은 그 배열의 서로 다른 시점에 존재하는 전체 SSA 값입니다.
$s0는 실행 중인 메모리 주소가 아니며, %v1을 제자리에서 수정하는 포인터도 아닙니다. 

같은 배열의 실제 정의 연결

%v1
└─ i1 MirArrayCreate
   └─ Storage = $s0

%v6
└─ i7 MirArrayStore
   └─ 이전 Array = %v1
      └─ i1 MirArrayCreate
         └─ Storage = $s0

lowering은 위 연결을 MIR에 남기는 일까지만 담당합니다.
완성된 MIR에서 %v6의 정의를 %v1까지 거꾸로 따라 PossibleStorages = [$s0], IsComplete = true를 계산하는 작업이 storage provenance 분석입니다.
이 분석은 lowering 중 dictionary가 아니며, 16장에서 설명하는 MirSnapshot.Analyses가 요청할 때 계산하는 파생 결과입니다.

선언·갱신·다음 소비처의 전체 연결

var values: int[] = [0];
├─ i0  MirConstant                         → %v0
├─ $s0 MirArrayStorage(Name="values")
├─ i1  MirArrayCreate($s0, [%v0])          → %v1
└─ SymbolId(values) → %v1
use q = Qubit[1];
└─ i2  MirQubitAllocate                    → q0.v0
values[0] = Next(values[0]);
├─ i3  MirConstant(왼쪽 index 0)           → %v2
├─ i4  MirConstant(오른쪽 index 0)         → %v3
├─ i5  MirArrayLoad(%v1, %v3)              → %v4
├─ i6  MirPureCall(Next c6, [%v4])         → %v5
├─ i7  MirArrayStore(%v1, %v2, %v5)        → %v6
└─ SymbolId(values) → %v6
if (values[0] == 1)
├─ 이름 조회                                   → %v6
├─ i8  MirConstant(index 0)                → %v7
├─ i9  MirArrayLoad(%v6, %v7)              → %v8
├─ i10 MirConstant(1)                      → %v9
└─ i11 MirBinary(Equal, %v8, %v9)          → %v10
                                               └─ 다음 소비처: MirBranch 조건
이 장의 결론 배열 선언은 $s0와 최초 상태 %v1을 만들고, indexed assignment는 이전 상태를 입력으로 받는 새 상태 %v6을 만듭니다.
마지막 dictionary 갱신 때문에 바로 다음 조건식의 MirArrayLoad i9은 %v1이 아니라 %v6을 읽습니다.

다음 장에서는 같은 소스의 use q = Qubit[1];부터 시작하여 X, 분기 합류, H가 q0.v0부터 q0.v3까지 만드는 순서를 추적합니다.

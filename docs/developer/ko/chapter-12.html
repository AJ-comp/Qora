배열 Storage와 값 상태

$s0와 %v1, %v6이 서로 다른 이유

← 이전: 고전 SSA 값전체 목차
다음: 큐비트 버전 →

이 예제의 지역 배열을 MIR에서 보면 번호가 두 종류 나옵니다.
$s0는 “어느 배열인가”를 구분하고, %v1과 %v6은 “그 배열의 값이 지금 어떤 상태인가”를 나타냅니다.
이 장에서는 아래 코드에서 배열을 만들고, 갱신하고, 다시 읽는 흐름만 따라가며 둘의 차이를 확인합니다.

살펴볼 Qora 코드

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

첫 문장은 길이 1인 배열 values를 만듭니다.
두 번째 문장은 현재 values[0]을 Next에 전달하고, 반환된 값을 다시 0번 원소에 저장합니다.
소스에서는 계속 같은 이름 values를 사용하지만, MIR은 갱신 전과 갱신 후를 서로 다른 값으로 구분합니다.

MIR 결과를 먼저 한눈에 보기

$s0와 %v1은 같은 정보를 두 번 저장한 것이 아닙니다.
$s0는 배열 자체를 구분하는 이름표이고, %v1은 그 배열이 처음 가졌던 값입니다.
원소를 갱신하면 이름표는 그대로 남지만 값 상태는 %v6으로 바뀝니다.

선언: $s0와 %v1이 함께 생깁니다

첫 문장 var values: int[] = [0];을 내리면 MIR에는 다음 두 정보가 생깁니다. 

storage $s0 values: int[1]

%v0: int    = const 0
%v1: int[1] = array.create $s0 {%v0}

storage $s0는 Work 안에 선언된 배열 values의 정체성입니다.
쉽게 말하면 “이 값들은 모두 values 배열에 관한 기록이다”라고 묶어 주는 이름표입니다.
배열 원소가 바뀌어도 values가 다른 배열로 교체된 것은 아니므로 $s0는 유지됩니다.

반면에 %v0은 리터럴 0이고, %v1은 그 0을 원소로 가진 최초 배열 상태입니다.
따라서 이 시점의 관계는 간단합니다.

갱신: 같은 $s0에 새 값 상태가 생깁니다

values[0] = Next(values[0]);

이 문장은 먼저 기존 배열에서 0번 원소를 읽습니다.
현재 배열 상태는 %v1이므로 MIR은 그 배열의 0번 원소를 읽어 %v4에 둡니다.
이어서 Next(%v4)의 반환값을 %v5에 받고, 그 값을 0번 위치에 저장한 새 배열 상태 %v6을 만듭니다.
번호 사이의 %v2와 %v3은 각각 0번 위치를 나타내는 MIR 값이며, 이 장에서는 배열 상태인 %v1과 %v6에만 집중합니다.

여기서 중요한 점은 %v1을 고쳐 쓰지 않는다는 것입니다.
MIR 값은 한 번 만들어지면 바뀌지 않으므로, 갱신은 기존 상태를 입력으로 받는 새 상태 %v6을 만듭니다.
그래서 나중의 분석은 %v1을 보면 갱신 전 배열을, %v6을 보면 갱신 후 배열을 정확히 알 수 있습니다.

다음 문장은 최신 상태 %v6을 읽습니다

다음 조건식 if (values[0] == 1)에도 여전히 values라고만 적혀 있습니다.
하지만 앞선 대입이 끝난 뒤 values의 현재 상태는 %v6입니다.
따라서 조건식은 최초 상태 %v1이 아니라 갱신된 상태 %v6의 0번 원소를 읽습니다.

이 예제를 실행하면 Next(0)의 결과는 1입니다.
다만 MIR은 그 결과를 미리 1로 단정하지 않고 %v5라는 호출 결과로 보존합니다. 여기서 중요한 점은 숫자 자체를 미리 아는지가 아니라, 다음 문장이 최신 배열 상태 %v6을 읽는다는 것입니다.

정리

두 번호가 답하는 질문 $s0는 “어느 배열인가?”에 답합니다.
%v1, %v6은 “그 배열이 이 시점에 어떤 값을 가졌는가?”에 답합니다.
배열 원소를 갱신하면 $s0는 유지되고, 값 상태만 %v1 → %v6으로 바뀝니다.

다음 장에서는 같은 원리를 큐비트에 적용합니다.
큐비트도 q0이라는 정체성은 유지하지만, 이 예제의 X와 H처럼 큐비트에 쓰는 명령을 지나면 현재 상태를 나타내는 버전이 달라집니다.

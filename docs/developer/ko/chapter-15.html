조건문 lowering과 분기 합류

소스의 if가 조건·참·거짓·합류 block과 Phi로 바뀌는 과정을 한 줄씩 따라가기

다음: MIR snapshot →

아래 예제의 if 문장이 LowerStatement에 전달되면 조건 계산, 참·거짓 block 생성, 두 경로의 lowering, 합류 순서로 실행이 이어집니다.
그 첫 호출부터 다음 문장 H(q[0])이 합류 결과 q0.v2를 읽는 지점까지 실제 지역 변수와 생성 객체를 따라갑니다.

이번 장에서 처리할 소스

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)       // 이번 장의 진입 문장
    {
        X(q[0]);
    }

    H(q[0]);                  // 합류 결과의 첫 소비자
}

최종 HIR에서 이 operation은 Work h44이고, 현재 lowering 객체가 만드는 callable은 Work c44입니다.
이번 장에서 계속 사용하는 b0, %v10, q0.v2는 모두 이 Work c44 안의 ID입니다.

if 직전의 실제 상태

LowerToMirCallable은 Work h44의 본문을 소스 순서대로 처리합니다.
따라서 if에 도착했을 때 앞의 선언과 대입은 이미 끝났으며, 현재 block과 두 심벌의 값은 다음과 같습니다. 

// Work h44의 네 번째 문장을 처리하기 직전
_currentMirBlockBuilder = b0

_currentFlowState.CurrentMirValueByHirSymbolId
└─ Symbol(values) → %v6

_currentFlowState.CurrentMirQubitByHirSymbolId
└─ Symbol(q) → q0.v0

// %v6의 출처
%v5 = call @c6:Next(%v4)           // Next(values[0])의 반환값
%v6 = array.store %v1[%v2], %v5    // values[0] 대입 뒤의 배열 상태

// q0.v0의 출처
i2: qubit.allocate q0.v0           // use q = Qubit[1]

여기서 Symbol(values)와 Symbol(q)는 이름 문자열이 아니라 HIR 의미 모델이 확정한 SymbolId입니다.
lowering은 이름을 다시 해석하지 않고 이 두 dictionary에서 현재 MIR 값만 읽고 바꿉니다.

소스 문장에서 LowerIf까지

위 상태를 만든 호출은 LowerToMirCallable → LowerStatements입니다.
다음 코드는 실제 구현에 예제값 주석만 덧붙인 것이며, hirStatements[3]이 이번 if 문장입니다. 

private void LowerStatements(IReadOnlyList<HirStatement> hirStatements)
{
    for (var hirStatementIndex = 0;
         hirStatementIndex < hirStatements.Count;
         hirStatementIndex++)
    {
        if (_currentMirBlockBuilder is null)
        {
            for (;
                 hirStatementIndex < hirStatements.Count;
                 hirStatementIndex++)
            {
                MarkUnreachableDeclarations(
                    hirStatements[hirStatementIndex]);
            }
            return;
        }

        // 예제값: index=3, current block=b0,
        // hirStatements[3]=HirIfStatement(values[0] == 1)
        LowerStatement(hirStatements[hirStatementIndex]);
    }
}

_currentMirBlockBuilder가 b0이므로 도달 불가 분기는 선택되지 않습니다.
이어서 LowerStatement의 switch가 런타임 타입 HirIfStatement을 확인하고 LowerIf(hirIf)를 호출합니다. 

private void LowerStatement(HirStatement hirStatement)
{
    switch (hirStatement)
    {
        case HirQubitDeclarationStatement hirQubitDeclaration:
            LowerQubitDeclaration(hirQubitDeclaration);
            return;
        case HirVariableDeclarationStatement hirDeclaration:
            LowerDeclaration(hirDeclaration);
            return;
        case HirAssignmentStatement hirAssignment:
            LowerAssignment(hirAssignment);
            return;
        case HirCallStatement hirCallStatement:
            LowerStatementCall(hirCallStatement);
            return;

        // 이번 호출에서 선택되는 분기
        // hirIf.Condition = values[0] == 1
        // hirIf.Then.Statements = [X(q[0])]
        // hirIf.Else.Statements = []
        case HirIfStatement hirIf:
            LowerIf(hirIf);
            return;
        case HirForStatement hirFor:
            LowerFor(hirFor);
            return;
        case HirWhileStatement hirWhile:
            LowerWhile(hirWhile);
            return;
        case HirRepeatStatement hirRepeat:
            LowerRepeat(hirRepeat);
            return;
        case HirReturnStatement hirReturn:
            LowerReturn(hirReturn);
            return;
        default:
            throw MirLoweringError(
                $"unsupported HIR statement {hirStatement.GetType().Name}");
    }
}

LowerIf의 첫 실행은 조건식 lowering입니다.
현재 배열 값 %v6을 읽어 %v7부터 %v10까지를 b0.Instructions 뒤에 추가하고, 마지막 비교 결과 %v10을 반환합니다. 

// LowerExpressionAs(hirIf.Condition, bit)의 실제 결과
%v7  = const 0                 // values[0]의 인덱스
%v8  = array.load %v6[%v7]    // 갱신된 배열의 원소
%v9  = const 1                 // == 오른쪽 피연산자
%v10 = eq %v8, %v9            // MirBranch가 읽을 bit

mirConditionValueId = %v10
_currentFlowState   = { values → %v6, q → q0.v0 }

LowerIf 전체 호출 흐름

이제 조건값과 진입 상태의 출처가 모두 확인되었습니다.
아래는 실제 LowerIf 전체 함수이며, 주석에는 공통 예제에서 각 지역 변수에 들어가는 값을 기록했습니다. 

private void LowerIf(HirIfStatement hirIf)
{
    var mirOrigin = MirOriginFor(hirIf);
    var mirConditionValueId = LowerExpressionAs(
        hirIf.Condition,
        MirType.Scalar(QType.Bit));
    // 예제값: mirConditionValueId=%v10, current block=b0

    var mirBranchBlock = RequireCurrentMirBlock();       // b0
    var flowStateBeforeBranch = _currentFlowState.Clone();
    // { values → %v6, q → q0.v0 }
    var mirThenBlock = CreateMirBlock(mirOrigin);         // b1
    var mirElseBlock = CreateMirBlock(mirOrigin);         // b2
    mirBranchBlock.BranchTo(
        mirConditionValueId,                              // %v10
        mirThenBlock, Array.Empty<MirValueId>(),          // b1, []
        mirElseBlock, Array.Empty<MirValueId>(),          // b2, []
        mirOrigin);

    var thenBranchExit = LowerScopedBranch(
        mirThenBlock,
        flowStateBeforeBranch,
        hirIf.Then.Statements);                           // [X(q[0])]
    var elseBranchExit = LowerScopedBranch(
        mirElseBlock,
        flowStateBeforeBranch,
        hirIf.Else.Statements);                           // []

    if (thenBranchExit.ExitBlock is null
        && elseBranchExit.ExitBlock is null)
    {
        // 예제에서는 b1과 b2가 모두 살아 있으므로 선택되지 않음
        _currentMirBlockBuilder = null;
        _currentFlowState = flowStateBeforeBranch;
        return;
    }

    var mirMergeBlock = CreateMirBlock(mirOrigin);        // b3
    if (thenBranchExit.ExitBlock is null
        || elseBranchExit.ExitBlock is null)
    {
        // 예제에서는 두 ExitBlock이 모두 있으므로 선택되지 않음
        var survivingBranchExit =
            thenBranchExit.ExitBlock is not null
                ? thenBranchExit
                : elseBranchExit;
        survivingBranchExit.ExitBlock!.JumpTo(
            mirMergeBlock,
            Array.Empty<MirValueId>(),
            mirOrigin);
        _currentMirBlockBuilder = mirMergeBlock;
        _currentFlowState = survivingBranchExit.ExitFlowState;
        return;
    }

    // 이번 예제는 여기부터 계속 실행됨
    var mergedFlowState = flowStateBeforeBranch.Clone();
    var mirThenPhiArguments = new List<MirValueId>();     // []
    var mirElsePhiArguments = new List<MirValueId>();     // []
    foreach (var hirSymbolId in
             flowStateBeforeBranch.CurrentMirValueByHirSymbolId.Keys.OrderBy(
                 id => id.Value))
    {
        // 유일한 고전 심벌 values:
        // mirThenValueId=%v6, mirElseValueId=%v6
        if (!thenBranchExit.ExitFlowState
                .CurrentMirValueByHirSymbolId.TryGetValue(
                hirSymbolId,
                out var mirThenValueId)
            || !elseBranchExit.ExitFlowState
                .CurrentMirValueByHirSymbolId.TryGetValue(
                hirSymbolId,
                out var mirElseValueId))
        {
            continue;
        }
        if (mirThenValueId == mirElseValueId)
        {
            // %v6 == %v6이므로 이번에 선택되는 분기
            mergedFlowState.CurrentMirValueByHirSymbolId[hirSymbolId] =
                mirThenValueId;
            continue;
        }

        var mirValueType = MirTypeOf(mirThenValueId);
        if (MirTypeOf(mirElseValueId) != mirValueType)
        {
            throw MirLoweringError(
                $"branch values for symbol {hirSymbolId} "
                + "have different MIR types");
        }
        var mirPhiValueId = AddBlockArgument(
            mirMergeBlock,
            mirValueType,
            hirSymbolId);
        mirThenPhiArguments.Add(mirThenValueId);
        mirElsePhiArguments.Add(mirElseValueId);
        mergedFlowState.CurrentMirValueByHirSymbolId[hirSymbolId] =
            mirPhiValueId;
    }

    var mirThenEdge = thenBranchExit.ExitBlock.JumpTo(
        mirMergeBlock, mirThenPhiArguments, mirOrigin);    // (b1, 0), []
    var mirElseEdge = elseBranchExit.ExitBlock.JumpTo(
        mirMergeBlock, mirElsePhiArguments, mirOrigin);    // (b2, 0), []
    MergeQubitStatesAtJoin(
        mergedFlowState,                                  // values=%v6, q=q0.v0
        thenBranchExit.ExitFlowState, mirThenEdge,         // q=q0.v1, (b1,0)
        elseBranchExit.ExitFlowState, mirElseEdge,         // q=q0.v0, (b2,0)
        mirMergeBlock);                                    // b3
    _currentMirBlockBuilder = mirMergeBlock;               // b3
    _currentFlowState = mergedFlowState;                   // values=%v6, q=q0.v2
}

b0을 닫는 조건 분기

RequireCurrentMirBlock()은 조건 instruction을 방금 추가한 b0을 반환합니다.
이어서 CreateMirBlock을 두 번 호출하여 b1과 b2를 만들고, BranchTo가 b0의 Terminator를 다음 값으로 확정합니다. 

b0.Terminator = MirBranch
├─ Condition      = %v10
├─ TrueTarget     = b1
├─ TrueArguments  = []
├─ FalseTarget    = b2
└─ FalseArguments = []

// 즉시 바뀐 제어 흐름
b0.Terminator.Successors = [b1, b2]

이 시점부터 CFG의 갈림길은 소스의 if가 아니라 MirBranch가 권위 있는 원본입니다.
17장의 분석기는 이 Terminator를 읽을 뿐, 조건문 lowering을 다시 수행하지 않습니다.

b1에서 실행되는 참 본문

첫 LowerScopedBranch 호출은 b1, 분기 전 상태, 문장 목록 [X(q[0])]을 받습니다.
함수 전체의 실행 순서는 다음과 같습니다. 

private (
    MirBlockBuilder? ExitBlock,
    LoweringFlowState ExitFlowState) LowerScopedBranch(
    MirBlockBuilder mirBranchBlock,                  // b1
    LoweringFlowState entryFlowState,                // values=%v6, q=q0.v0
    IReadOnlyList<HirStatement> hirStatements)       // [X(q[0])]
{
    _currentMirBlockBuilder = mirBranchBlock;         // current=b1
    _currentFlowState = entryFlowState.Clone();
    _currentFlowState.PushHirSymbolLifetimeFrame();
    LowerStatements(hirStatements);                  // LowerStatement → LowerStatementCall
    _currentFlowState.PopHirSymbolLifetimeFrame();
    return (_currentMirBlockBuilder, _currentFlowState);
    // (ExitBlock=b1, ExitFlowState={values=%v6, q=q0.v1})
}

X(q[0])은 HirCallStatement이므로 LowerStatementCall 분기가 선택됩니다.
LowerQubitAccess가 Symbol(q) → q0.v0을 읽고 인덱스 %v11을 만든 뒤, X의 write 결과로 새 버전 q0.v1을 발급합니다. 

// b1 종료 직전
b1.Instructions
├─ i12: %v11 = const 0
└─ i13: X(q0.v0[%v11]) → q0.v1

thenBranchExit.ExitBlock = b1
thenBranchExit.ExitFlowState
├─ Symbol(values) → %v6
└─ Symbol(q)      → q0.v1

b2에서 실행되는 빈 거짓 본문

두 번째 LowerScopedBranch는 같은 분기 전 상태를 다시 복제하되, 문장 목록으로 빈 []를 받습니다.
따라서 LowerStatements([])은 아무 instruction도 만들지 않으며, 거짓 경로의 큐비트는 q0.v0 그대로 남습니다. 

LowerScopedBranch(
    mirBranchBlock: b2,
    entryFlowState: { values → %v6, q → q0.v0 },
    hirStatements: [])

elseBranchExit.ExitBlock = b2
elseBranchExit.ExitFlowState
├─ Symbol(values) → %v6
└─ Symbol(q)      → q0.v0

실제로 선택되는 합류 경로

참 경로의 ExitBlock은 b1이고 거짓 경로의 ExitBlock은 b2입니다.
그러므로 “둘 다 종료됨” 조건은 거짓이고 “한쪽만 종료됨” 조건도 거짓입니다. LowerIf은 두 경로를 합치는 본 경로를 계속 실행하며 세 번째 새 block b3을 만듭니다. 

thenBranchExit.ExitBlock is null && elseBranchExit.ExitBlock is null
false && false → false

mirMergeBlock = CreateMirBlock(mirOrigin) → b3

thenBranchExit.ExitBlock is null || elseBranchExit.ExitBlock is null
false || false → false

// 다음 실행 위치: 고전값 비교 루프

고전 상태 %v6의 합류

분기 전에 살아 있던 고전 심벌은 values 하나입니다.
참 경로와 거짓 경로 모두 현재값이 정확히 같은 %v6이므로 mirThenValueId == mirElseValueId 분기가 선택됩니다. 따라서 b3.Arguments에는 새 고전 Phi 값이 생기지 않습니다. 

hirSymbolId       = Symbol(values)
mirThenValueId   = %v6
mirElseValueId   = %v6
%v6 == %v6       = true

mergedFlowState.CurrentMirValueByHirSymbolId
└─ Symbol(values) → %v6

mirThenPhiArguments = []
mirElsePhiArguments = []
b3.Arguments          = []

b3로 들어오는 두 edge

고전 인수 목록이 확정되면 JumpTo가 b1과 b2를 각각 b3에 연결합니다.
두 출발 block 모두 목적지가 하나뿐이므로 반환되는 MirControlFlowEdge의 successor 순번은 0입니다. 

mirThenEdge = b1.JumpTo(b3, [], mirOrigin)
├─ Source           = b1
└─ SuccessorOrdinal = 0

mirElseEdge = b2.JumpTo(b3, [], mirOrigin)
├─ Source           = b2
└─ SuccessorOrdinal = 0

b1.Terminator = MirJump(Target=b3, Arguments=[])
b2.Terminator = MirJump(Target=b3, Arguments=[])

이 edge는 목적지 ID 하나가 아닙니다.
출발 block과 그 Terminator 안의 successor 순번을 함께 저장하므로, 뒤에서 큐비트 Phi 입력이 어느 실행 경로에서 왔는지 구분할 수 있습니다.

q0.v1과 q0.v0의 Phi

이제 MergeQubitStatesAtJoin은 mergedFlowState의 큐비트를 ID별로 묶습니다.
이 예제에는 Symbol(q) 하나가 q0을 가리키므로 alias group도 하나뿐입니다. 이어서 두 종료 상태에서 같은 q0의 현재 버전을 읽습니다. 

mirQubitAliasGroup
├─ MirQubitId  = q0
└─ HirSymbolIds = [Symbol(q)]

firstIncomingMirQubit  = q0.v1    // b1, X 실행 뒤
secondIncomingMirQubit = q0.v0    // b2, X를 거치지 않음

firstIncomingMirQubit.Key == secondIncomingMirQubit.Key
q0.v1 == q0.v0 → false             // CreateQubitPhi 경로 선택

선택된 CreateQubitPhi 호출의 실제 인수와 결과는 다음과 같습니다.
버전 allocator의 다음 값이 2이므로 q0.v2가 생성되고, 이 객체는 일반 instruction이 아니라 b3.QubitPhis에 추가됩니다. 

CreateQubitPhi(
    hirSymbolId: Symbol(q),
    mirJoinBlock: b3,
    mirPhiInputs:
    [
        MirQubitPhiInput(Edge=(b1,0), Qubit=q0.v1),
        MirQubitPhiInput(Edge=(b2,0), Qubit=q0.v0),
    ])

_nextMirQubitVersionById[q0]: 2 → 3

b3.QubitPhis
└─ MirQubitPhi
   ├─ Key = q0.v2
   ├─ Input[0] = ((b1,0), q0.v1)
   └─ Input[1] = ((b2,0), q0.v0)

mergedFlowState.CurrentMirQubitByHirSymbolId
└─ Symbol(q) → MirQubitPhi(Key=q0.v2)

q0.v2는 새 물리 큐비트가 아닙니다.
같은 identity q0의 현재 버전을 “b1에서 왔으면 v1, b2에서 왔으면 v0”으로 정하는 합류 정의입니다.

현재 flow 교체와 다음 문장

LowerIf의 마지막 두 대입은 새로 만든 합류 block과 합류 상태를 현재값으로 교체합니다.
함수가 반환되면 바깥 LowerStatements의 반복 인덱스가 다음 문장 H(q[0])으로 이동합니다. 

// LowerIf 마지막 상태 변경
_currentMirBlockBuilder = b3
_currentFlowState
├─ Symbol(values) → %v6
└─ Symbol(q)      → MirQubitPhi(Key=q0.v2)

// LowerStatements 다음 반복
hirStatementIndex = 4
hirStatements[4]  = HirCallStatement(H(q[0]))

LowerStatement(H call)
→ case HirCallStatement
→ LowerStatementCall
→ LowerQubitAccess(q[0])
→ CurrentMirQubitByHirSymbolId[Symbol(q)] = q0.v2
→ %v12 = const 0
→ i15: H(q0.v2[%v12]) → q0.v3

한 문장에서 다음 소비자까지의 결과

if (values[0] == 1)                    H(q[0])
        │                                 ▲
        ▼                                 │ q0.v2 소비
b0: %v10 계산, branch b1/b2               │
        │                 │               │
        ▼                 ▼               │
b1: X(q0.v0)→q0.v1    b2: q0.v0 유지      │
        │                 │               │
        └──── jump b3 ────┘               │
                  │                       │
                  ▼                       │
b3: q0.v2 = phi((b1,0):q0.v1, (b2,0):q0.v0)
    %v12 = const 0
    H(q0.v2[%v12]) → q0.v3
    return
예제 뒤의 일반 원리 조건문 lowering은 소스의 한 문장을 조건값, 명시적인 Terminator, 경로별 flow 복제, 합류 상태로 바꿉니다.
두 고전 현재값이 다르면 합류 block argument를 만들지만, 이 예제의 values는 양쪽 모두 %v6이므로 만들지 않습니다.
반면 큐비트 버전은 q0.v1과 q0.v0으로 다르므로 MirQubitPhi q0.v2가 필요합니다.

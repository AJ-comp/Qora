조건문에서 상태 나누고 합치기

참 경로의 변경이 거짓 경로에 섞이지 않는 이유

← 이전: Basic Block전체 목차
다음: MIR snapshot →

14장에서 if가 네 block으로 나뉘는 모습은 확인했습니다.
이번 장에서는 두 경로의 현재 큐비트 버전을 따로 유지한 뒤 다시 합치는 과정만 살펴봅니다.

살펴볼 Qora 코드

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

values[0] == 1이 참이면 q[0]에 X가 적용되고, 거짓이면 아무 일도 일어나지 않습니다.
MIR에는 두 경로가 모두 남아 있으므로, if 뒤의 H(q[0])은 어느 경로에서도 이어질 수 있어야 합니다.

이 장에서 답할 질문 참 경로에서 X가 현재 버전을 바꾸더라도, 거짓 경로는 왜 원래 버전을 그대로 유지할 수 있습니까?
MIR은 경로별 현재 상태를 따로 관리한 뒤 합류점에서 비교합니다.

두 경로는 같은 입력에서 따로 시작합니다

if 직전에는 현재 q가 q0.v0을 가리킵니다.
lowerer는 이 기록을 참 경로와 거짓 경로에 각각 복사한 뒤, 두 경로를 서로 독립적으로 처리합니다. 

분기 직전 기록: q → q0.v0
        │
        ├─ 참 경로 기록: q → q0.v0 ── X ──▶ q0.v1
        └─ 거짓 경로 기록: q → q0.v0 ─────────▶ q0.v0

따라서 참 경로에서 X를 처리해도 참 경로의 기록만 q0.v1로 바뀝니다.
거짓 경로는 별도 기록을 사용하므로 계속 q0.v0을 가리킵니다.

합류점에서 두 기록을 한 번 비교합니다

합류점에서는 두 경로가 기록한 현재 버전을 비교합니다.
두 버전이 같으면 그대로 사용하고, 이 예제처럼 q0.v1과 q0.v0으로 다르면 Phi 버전 q0.v2를 만듭니다. 

참 경로의 현재 q: q0.v1 ──┐
                           ├─ 서로 다름 → 합류 뒤 현재 q: q0.v2
거짓 경로의 현재 q: q0.v0 ─┘

비교가 끝나면 합류 뒤의 현재 q 기록은 q0.v2 하나가 됩니다.
뒤의 H(q[0])은 경로별 기록을 다시 확인하지 않고 이 합류 기록만 사용합니다.

정리 조건문 lowering의 핵심은 경로별 현재 상태를 따로 기록하는 것입니다.
그래서 한 경로의 변경이 다른 경로에 섞이지 않으며, 합류점에서만 두 기록을 비교해 하나로 연결합니다.

다음 장에서는 이렇게 완성된 Next와 Work를 하나의 MirProgram으로 묶는 과정을 살펴봅니다.

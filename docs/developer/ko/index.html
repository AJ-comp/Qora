컴파일 파이프라인 설계 컴파일러 데이터시트

이 매뉴얼은 하나의 Qora 예제가 실제 컴파일러 구현을 통과하는 순서를 추적합니다.
각 장은 현재 소스 문장에서 출발하여 어느 함수로 들어가는지, 실제 인수값으로 어떤 분기를 타는지, 그 결과 어떤 객체·ID·상태가 만들어져 다음 코드에 전달되는지를 실행 순서대로 설명합니다.

현재 문서 상태 전체 학습 경로는 28개 장으로 구성되어 있습니다.
현재 상세 본문이 작성된 범위는 실제 코드와 대조한 9–17장이며, 나머지 장에는 이후 작성 범위를 나타내는 목차만 있습니다.

끝까지 따라갈 두 callable

상세 본문이 준비된 9–17장은 아래의 같은 예제를 계속 추적합니다.
따라서 Symbol 연결, SSA 값, CallGraph, Basic Block, CFG, 큐비트 버전이 서로 다른 예제에서 단절되지 않고 하나의 컴파일 흐름으로 이어집니다. 

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}
Source → AST → HIR + SemanticModel → SSA/CFG MIR → MIR Analyses → Target IR → OpenQASM
설명 규칙 각 장은 현재 소스 문장 → 실제 진입 함수 → 예제 인수값 → 선택된 분기 → 생성 객체와 상태 변경 → 다음 소비처 순서를 따릅니다.
자료구조의 일반 정의와 구조적 계약은 예제 흐름을 완료한 뒤 정리하며, 상세 규격은 데이터시트의 정확한 항목으로 연결합니다.

장별 주제

1. 저장소와 컴파일 진입점 현재 구현

질문: 실행 파일, Core, LanguageServices, 테스트는 어디에서 만나며 첫 중단점은 어디에 두는가?

주요 코드: src/Qora, QoraCompiler, src/Qora.Core, tests/Qora.Tests

2. Compilation 요청과 결과 현재 구현

질문: 소스와 출력 계획이 어떻게 하나의 컴파일 결과가 되며 실패 시 어느 단계까지 남는가?

주요 코드: CompilationSession, CompilationOutputPlan, Compilation

3. 문자열에서 AST까지 현재 구현

질문: Janglim이 두 callable을 어떤 구문 트리로 만들고 Qora의 소유 경계는 어디에서 시작되는가?

주요 코드: parser grammar, syntax snapshot, source map

4. AST에서 불변 HIR로 현재 구현

질문: Next와 Work가 어떤 HirCallable과 표현식 트리가 되는가?

주요 코드: AstToHirLowering, expression lowering, HIR builder

5. 노드 ID와 소스 위치 현재 구현

질문: 선언, 호출, 비교식의 HirNodeId가 무엇을 식별하고 진단 위치와 어떻게 연결되는가?

주요 코드: HIR node identity, SourceMap, SourceSpan

6. Scope와 Symbol 현재 구현

질문: Next의 매개변수 value와 Work의 지역 변수 values가 서로 다른 Symbol로 연결되고 블록 안 이름이 어떻게 검색되는가?

주요 코드: HirScopeGraph, ScopeId, SymbolId, HirSemanticModel

7. 이름 해소와 호출 대상 현재 구현

질문: Next(values[0])가 정확히 어느 선언을 호출하는지 한 번만 결정되는 과정은 무엇인가?

주요 코드: Resolver, callable binding, namespace lookup

8. 타입·호출 계약·최종 HIR artifact 현재 구현

질문: 인수와 매개변수, 반환식과 반환형, 조건식의 타입을 누가 검사하고 MIR로 갈 수 있는 최종 상태를 어떻게 봉인하는가?

주요 코드: QoraValidator, ExpressionTypes, HirSemanticArtifact, effect analysis

9. HIR→MIR 경계 현재 구현

질문: 최종 HIR과 정확한 SemanticModel이 어떻게 한 번의 ToMir 호출로 내려가는가?

주요 코드: HirCompilation.ToMir, QoraMirLowering, MirSnapshot.CreateLowered

질문: 사용자 문법에 없는 역연산 요청이 왜 MIR에만 존재하고 역방향 callable이 어떻게 합성되는가?

주요 코드: MirFunctor.Adjoint, MirAdjointMaterializer, generated origin

22. 자동 uncomputation이 들어갈 경계 확장 예정

질문: 고전 witness 안정성, 여러 ancilla의 청소 의존 관계, cleanup 계획과 실제 MIR 주입은 어느 분석 결과를 소비해야 하는가?

예정 경계: exact MIR analyses → cleanup plan → MIR rewrite → 기존 역연산 실체화

23. Target IR lowering 현재 구현

질문: 타깃 독립적인 MIR가 OpenQASM 전용 타입·이름·구조화된 제어 흐름으로 어떻게 바뀌는가?

주요 코드: MirOpenQasmLowering, MirOpenQasmTargetProgram

24. OpenQASM 방출 현재 구현

질문: 의미 판단을 마친 target model이 어떻게 최종 텍스트가 되며 emitter가 하지 않아야 할 일은 무엇인가?

주요 코드: MirQasmEmitter, target declarations, statements, expressions

25. 새 문법과 의미 규칙 추가 개발 절차

질문: 문법, AST lowering, HIR, 이름 해소, 타입 검사 가운데 어디를 변경하고 어느 단계에서는 변경하지 않아야 하는가?

검증: parser, HIR structure, semantic diagnostics, target-independent boundary tests

26. 새 MIR 명령과 분석 추가 개발 절차

질문: 유효한 MIR만 생성하게 경계를 닫고 새 instruction을 verifier·분석·rewrite에 연결하는 순서는 무엇인가?

검증: constructor invariants, lowering tests, CFG/SSA analysis tests, transformation tests

27. Target 기능 추가 개발 절차

질문: OpenQASM 또는 새로운 backend의 제약을 HIR·MIR에 역류시키지 않고 target 경계에서 처리하는 방법은 무엇인가?

검증: target policy diagnostics, typed target model tests, emitter snapshots

28. 테스트·단계 출력·적대적 검증 개발 절차

질문: 정상 예제뿐 아니라 shadowing, 분기, alias, 잘못된 ID, 타깃 경계 같은 반례로 구조적 결함을 어떻게 찾는가?

주요 도구: unit tests, compilation stages, MIR dumps, backend validation, adversarial review

Splitting and Joining State at a Conditional

Why a change on the true path does not leak into the false path

← Previous: Basic blocksAll chapters
Next: MIR snapshots →

Chapter 14 showed how an if is split into four blocks.
This chapter focuses only on keeping the current qubit version separate on each path and joining those versions again.

Qora code under examination

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

If values[0] == 1 is true, X is applied to q[0]; if false, nothing happens.
Because MIR preserves both paths, H(q[0]) after the if must be able to continue from either one.

Question answered in this chapter How can the false path retain its original version when X changes the current version on the true path?
MIR tracks current state independently for each path and compares the states at the join point.

Both paths start independently from the same input

Immediately before the if, current q refers to q0.v0.
The lowerer copies this record into the true and false paths, then processes each path independently. 

before branch: q → q0.v0
        │
        ├─ true-path record:  q → q0.v0 ── X ──▶ q0.v1
        └─ false-path record: q → q0.v0 ─────────▶ q0.v0

Processing X on the true path therefore changes only the true-path record to q0.v1.
The false path uses a separate record and continues to refer to q0.v0.

Compare both records once at the join point

At the join point, the lowerer compares the current versions recorded by both paths.
If they match, it uses that version directly. If they differ as q0.v1 and q0.v0 do here, it creates Phi version q0.v2. 

current q on true path:  q0.v1 ──┐
                                 ├─ different → current q after join: q0.v2
current q on false path: q0.v0 ──┘

After the comparison, the current q record after the join is the single version q0.v2.
The following H(q[0]) uses only this joined record without checking the path-specific records again.

Summary The essential rule of conditional lowering is to record current state independently for each path.
A change on one path cannot leak into another, and the two records are compared and connected only at the join point.

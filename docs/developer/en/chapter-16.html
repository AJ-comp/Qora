MirSnapshot and the Analysis Basis

The boundary that keeps the program and its analyses on the same MIR

← Previous: Conditional joinsAll chapters
Next: CFG edges →

Chapter 9 showed how Next and Work are collected into a MirProgram, which then becomes a MirSnapshot.
This chapter focuses on one role of a snapshot: binding a program and its analyses to the same basis.

MirSnapshot represents the current MIR state

A MirProgram is the executable structure itself. A MirSnapshot is an immutable result that stores that program together with the analysis entry point dedicated to it.
A program initially lowered from HIR becomes the first snapshot through MirSnapshot.CreateLowered(program).

Program is the MIR execution structure lowered from HIR.
Analyses provides the required MIR analyses using that exact Program as its basis.

The snapshot is the basis for MIR analysis

A MirSnapshot contains Analyses, the entry point for analyzing its program.
For example, requesting the control flow of Work computes the CFG from the Work contained in this snapshot.

Analysis results do not create another program.
They are derived information computed from the MIR in the current snapshot. Chapter 17 continues with the construction of the CFG.

The next chapter shows how a request for the control flow of Work computes a CFG from the blocks and terminators already present.

Array Storage and Value State

Why $s0, %v1, and %v6 represent different things

← Previous: Classical SSA valuesAll chapters
Next: Qubit versions →

The local array in this example has two kinds of numbers in MIR.
$s0 identifies which array it is, while %v1 and %v6 represent the current state of that array's value.
This chapter follows only the creation, update, and subsequent read of the array to make this distinction clear.

Qora code under examination

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

The first statement creates an array named values with length 1.
The second passes the current values[0] to Next and stores the returned value back into element 0.
The source keeps using the same name, values, while MIR distinguishes its state before and after the update as separate values.

MIR result at a glance

$s0 and %v1 do not store the same information twice.
$s0 is the identity tag for the array itself, while %v1 is the array's initial value.
Updating an element leaves the identity unchanged but changes the value state to %v6.

Declaration: $s0 and %v1 are created together

Lowering the first statement, var values: int[] = [0];, creates the following two kinds of information in MIR. 

storage $s0 values: int[1]

%v0: int    = const 0
%v1: int[1] = array.create $s0 {%v0}

storage $s0 is the identity of the array values declared inside Work.
In simple terms, it is a label that groups records as referring to the same values array.
Changing an element does not replace values with another array, so $s0 remains unchanged.

In contrast, %v0 is literal 0, and %v1 is the first array state containing that value.
The relationship at this point is therefore straightforward.

Update: the same $s0 receives a new value state

values[0] = Next(values[0]);

This statement first reads element 0 from the existing array.
Because the current array state is %v1, MIR reads element 0 from it into %v4.
It then receives the return value of Next(%v4) as %v5 and creates %v6, a new array state with that value stored at index 0.
The intermediate values %v2 and %v3 each represent index 0. This chapter focuses only on the array states %v1 and %v6.

The important point is that %v1 is never rewritten.
MIR values do not change after creation, so an update creates a new state, %v6, using the previous state as input.
Later analysis can therefore identify the array before the update from %v1 and after the update from %v6.

The next statement reads the latest state, %v6

The next condition, if (values[0] == 1), still uses only the source name values.
After the preceding assignment, however, the current state of values is %v6.
The condition therefore reads element 0 from updated state %v6, not initial state %v1.

Running this example makes Next(0) return 1.
MIR does not assume that result in advance; it preserves it as call result %v5. The important fact here is not whether the number is known ahead of time, but that the next statement reads the latest array state, %v6.

Summary

Questions answered by the two kinds of numbers $s0 answers “Which array is this?”
%v1 and %v6 answer “What value did that array have at this point?”
Updating an array element preserves $s0 and changes only the value state from %v1 to %v6.

The next chapter applies the same principle to qubits.
A qubit keeps the identity q0, but its current-state version changes after a qubit-writing instruction such as X or H in this example.

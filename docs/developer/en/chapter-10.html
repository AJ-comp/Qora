Lowering One Callable to MIR

How one function or operation becomes a MirCallable with parameters, blocks, and a body

← Previous: HIR→MIR boundaryAll chaptersLowerHirArtifact() detailed trace
Next: Classical values and SSA versions →

Chapter 9 established only that Next and Work each become one MirCallable.
This chapter shows what is created first when lowering one callable, where its source body goes, and what the final result looks like.

The two callables compared in this chapter

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

Both declarations are callables, but they have different shapes.
Next is a short function with one parameter and a return value. Work is the entry operation with a local array, a qubit, and a conditional.

With this exact input, the current compiler produces two final HIR callables: Next h6 and Work h44.
MIR preserves the same numeric IDs, producing Next c6 and Work c44. The code comments below continue to use these IDs.

Why lower HIR to MIR?

HIR is a tree that preserves the nested structure of user-written code.
For example, Work contains the array declaration, assignment, if, and H call, while the if contains its condition and the X call. This structure is well suited to checking names and types and understanding the original code.

A tree alone is inconvenient for tracking which value is current at a particular point.
The source repeatedly uses the same name values, while MIR distinguishes the pre-update array %v1, loaded element %v4, result of Next %v5, and updated array %v6 as separate values.

MIR represents execution paths as connections between blocks and records each newly created classical value as a separate SSA value.
Later analyses can therefore follow the graph to inspect value changes and branch joins without reinterpreting the source tree. HIR preserves source meaning, while MIR makes execution flow and value tracking explicit.

Create one dedicated lowerer per callable

A callable lowerer is a transformation object responsible for exactly one callable at a time.
While processing Next, it manages only the parameters, current block, and values of Next. After that work completes, a new lowerer processes Work separately.

The code that takes callables one at a time

The code below is the complete current LowerHirArtifact().
Its executable statements match the implementation; only comments for the Next and Work values used in this chapter were added.
This trace does not supply the optional lowering trace sink, so traceSink = null.
Click an underlined function name in the C# code to open its execution trace. 

private static MirSnapshot LowerHirArtifact(
    HirSemanticArtifact hirArtifact,
    IMirLoweringTraceSink? traceSink)
{
    // hirArtifact contains the final HIR after semantic analysis.
    // Callables = [Next h6, Work h44]
    // EntryCallable = Work h44
    ArgumentNullException.ThrowIfNull(hirArtifact);

    var hirSnapshot = hirArtifact.Source;
    var hirProgram = hirSnapshot.Program;

    // Example value: hirEntryCallable = Work h44
    var hirEntryCallable = hirProgram.EntryCallable
        ?? throw new InvalidOperationException(
            "validated HIR must contain an operation before MIR lowering");

    // No callable has been lowered yet, so both values are empty.
    var mirCallables = new List<MirCallable>();
    MirCallable? mirEntryCallable = null;

    foreach (var hirCallable in hirProgram.Callables)
    {
        // First iteration: hirCallable = Next h6
        // Second iteration: hirCallable = Work h44
        // A new lowerer is created for each iteration, so callable state cannot mix.
        var mirCallableLowerer = new HirCallableToMirLowerer(
            hirCallable,
            hirArtifact,
            traceSink);

        // First result: mirCallable = Next c6
        // Second result: mirCallable = Work c44
        var mirCallable = mirCallableLowerer.LowerToMirCallable();
        mirCallables.Add(mirCallable);

        // Next is not the entry operation, so this is false in the first iteration.
        // Work is the same object as hirEntryCallable, so this is true in the second.
        if (ReferenceEquals(hirCallable, hirEntryCallable))
            mirEntryCallable = mirCallable;
    }

    // Final result:
    // Callables  = [Next c6, Work c44]
    // EntryPoint = Work c44
    var mirProgram = new MirProgram(
        mirEntryCallable
            ?? throw new InvalidOperationException(
                "validated HIR entry callable must be lowered into MIR"),
        mirCallables);

    return MirSnapshot.CreateLowered(mirProgram);
}

After the first iteration, Next c6 is in the list. The second iteration adds Work c44.
Because Work is the entry operation, the same Work c44 object is selected as the entry point of the MirProgram.

The constructor below is the complete lowerer constructor called for each iteration.
It stores the assigned HIR callable, final semantic information, and optional trace sink, and reuses the numeric HIR callable node ID as the corresponding MIR callable ID. 

public HirCallableToMirLowerer(
    HirCallable hirCallable,
    HirSemanticArtifact hirArtifact,
    IMirLoweringTraceSink? traceSink)
{
    // First object: Next h6
    // Second object: Work h44
    _hirCallable = hirCallable;
    _hirArtifact = hirArtifact;

    // h6 becomes c6, and h44 becomes c44.
    _mirCallableId = new MirCallableId(hirCallable.Id.Value);

    // The default CLI run requests no trace, so this is null.
    _traceSink = traceSink;
}

A lowerer created with new starts with empty parameter and block lists and no current block.
Each callable also has its own block ID allocator, so both Next and Work can name their first block b0.

Common sequence for creating one callable

Every function and operation follows this sequence.
Differences come from their parameters and body. A simple function may require one block, while an operation with a conditional splits into multiple blocks.

Tracing the function with Next and Work substituted

LowerToMirCallable() runs once on the lowerer for Next h6 and once on the lowerer for Work h44.
The comments below show how values and branches differ for both inputs within the same code. 

public MirCallable LowerToMirCallable()
{
    // First run: _hirCallable = Next h6
    // Second run: _hirCallable = Work h44
    var mirCallableOrigin = MirOriginFor(_hirCallable);

    // Result: declaration symbol for the current Next or Work
    var hirCallableSymbol = RequireHirDeclarationSymbol(
        _hirCallable.Id,
        $"callable `{_hirCallable.Name}`");

    // HIR name structure that records the namespace containing the current callable.
    var hirScopeGraph = _hirArtifact.Model.ScopeGraph
        ?? throw MirLoweringError(
            "the final HIR semantic model has no scope graph");

    // Next run: qualifiedSourceCallableName = "Next"
    // Work run: qualifiedSourceCallableName = "Work"
    var qualifiedSourceCallableName =
        hirScopeGraph.QualifiedName(hirCallableSymbol);

    // Each lowerer creates its own first block, so each has a distinct b0.
    _currentMirBlockBuilder = CreateMirBlock(mirCallableOrigin);

    // Next run: register parameter value as %v0.
    // Work run: no parameters, so _mirParameters = [].
    LowerParameters();

    /* LowerStatements() processes the complete body of the current callable.

    Next
    - Processing return value + 1; adds calculation instructions and a MirReturn terminator to b0, then closes b0.
    - Because current block b0 is closed, _currentMirBlockBuilder becomes null.
    - _mirBlockBuilders = [b0]

    Work
    - b0 processes the variable declaration, qubit preparation, array assignment, and if condition,
      then closes by branching to b1 or b2.
    - b1 processes X(q[0]); on the true path, then closes by moving to b3.
    - b2 is the false path with no source statement to process; it closes by moving to b3.
    - b3 is the join of b1 and b2 and processes the final H(q[0]);.
    - H(q[0]); does not close the block, and no explicit return follows it,
      so b3 remains the open current block.

    After processing
    ├─ _mirBlockBuilders = [b0, b1, b2, b3]
    └─ _currentMirBlockBuilder = b3 */
    LowerStatements(_hirCallable.Body.Statements);

    // Next: the current block is null, so skip the if below.
    // Work: the current block is b3, so the if below closes b3.
    if (_currentMirBlockBuilder is not null)
    {
        if (_hirCallable.IsFunction)
        {
            // Neither callable in this example selects this branch.
            MarkCurrentMirBlockUnreachable(
                MirOrigin.GeneratedFrom(
                    mirCallableOrigin,
                    "missing validated function return"));
        }
        else
        {
            // Work run: attach a valueless implicit return to b3.
            ReturnFromCurrentMirBlock(
                value: null,
                MirOrigin.GeneratedFrom(
                    mirCallableOrigin,
                    "implicit operation return"));
        }
    }

    // Next run: builder list [b0]
    // Work run: builder list [b0,b1,b2,b3]
    // Finalize each builder as an immutable MirBlock.
    var mirBlocks = new List<MirBlock>(_mirBlockBuilders.Count);
    foreach (var mirBlockBuilder in _mirBlockBuilders)
    {
        var mirBlock = mirBlockBuilder.Build();
        mirBlocks.Add(mirBlock);
    }

    // The first block created, b0, is always the entry block.
    var mirEntryBlock = mirBlocks[0];

    // Next return: c6, "Next", int, [%v0], b0, [b0]
    // Work return: c44, "Work", null, [], b0, [b0,b1,b2,b3]
    return new MirCallable(
        _mirCallableId,
        qualifiedSourceCallableName,
        _hirCallable.ReturnType is { } returns
            ? MirType.Scalar(returns)
            : null,
        _mirParameters,
        mirEntryBlock,
        mirBlocks,
        mirCallableOrigin);
}

This function performs the same sequence shown in the diagram above.
It creates the entry block and processes the body. Next ends with an explicit return; Work closes its remaining operation path with a valueless return. They become MirCallable Next c6 and MirCallable Work c44, respectively.

Where the body statements of both callables go

LowerStatements() above traverses the body from beginning to end, and LowerStatement() selects one lowering helper that matches the current statement kind.
The complete current code of both functions follows. The comments show the actual values supplied by Next and Work. 

private void LowerStatements(IReadOnlyList<HirStatement> hirStatements)
{
    // Next body: [return value + 1], starts at b0
    // Work top level: [var, use, assignment, if, H], starts at b0
    // true body of if: [X(q[0])], starts at b1
    // false body of if: [], starts at b2
    for (var hirStatementIndex = 0;
         hirStatementIndex < hirStatements.Count;
         hirStatementIndex++)
    {
        // If the current path is already closed at the start of an iteration,
        // do not emit the remaining statements. None of the four calls in this example select this branch.
        if (_currentMirBlockBuilder is null)
        {
            for (;
                 hirStatementIndex < hirStatements.Count;
                 hirStatementIndex++)
            {
                MarkUnreachableDeclarations(
                    hirStatements[hirStatementIndex]);
            }
            return;
        }

        LowerStatement(hirStatements[hirStatementIndex]);
    }
}

The loop calls LowerStatement() below each time it takes one statement. 

private void LowerStatement(HirStatement hirStatement)
{
    switch (hirStatement)
    {
        // Selected by Work's use q statement.
        case HirQubitDeclarationStatement hirQubitDeclaration:
            LowerQubitDeclaration(hirQubitDeclaration);
            return;

        // Selected by Work's var values statement.
        case HirVariableDeclarationStatement hirDeclaration:
            LowerDeclaration(hirDeclaration);
            return;

        // Selected by Work's assignment to values[0].
        case HirAssignmentStatement hirAssignment:
            LowerAssignment(hirAssignment);
            return;

        // Selected by Work's H call.
        // The X call inside the if selects the same branch while processing the nested body.
        case HirCallStatement hirCallStatement:
            LowerStatementCall(hirCallStatement);
            return;

        // Selected by Work's if statement.
        case HirIfStatement hirIf:
            LowerIf(hirIf);
            return;

        case HirForStatement hirFor:
            LowerFor(hirFor);
            return;

        case HirWhileStatement hirWhile:
            LowerWhile(hirWhile);
            return;

        case HirRepeatStatement hirRepeat:
            LowerRepeat(hirRepeat);
            return;

        // Selected by Next's return statement.
        case HirReturnStatement hirReturn:
            LowerReturn(hirReturn);
            return;

        default:
            throw MirLoweringError(
                $"unsupported HIR statement {hirStatement.GetType().Name}");
    }
}

This switch does not determine statement meaning again.
It reads the statement kind already classified in HIR, calls the matching helper, and returns immediately.

Next is completed with one block

Next has one int parameter named value.
The lowerer registers it as MIR input value %v0 and processes the body in entry block b0.

Source statement return value + 1; is split into computation and return, but both remain in b0.
The return ends the block, so no additional terminating statement is needed.

Work splits into multiple blocks because of the conditional

Work has no parameters, but it has a local array and a qubit.
It first creates the array and prepares the qubit in the entry block, then updates the array and evaluates the condition.

Encountering the if splits execution into two paths, requiring b1 and b2.
After both paths finish, they join at b3, which contains H(q[0]); from after the conditional in the source.

The source of Work has no return statement.
Because an operation returns no value, the lowerer automatically appends a valueless return to the final b3, closing the block normally. This is called an implicit return.

What the completed MirCallable stores

When callable lowering finishes, the working lists are collected into one MirCallable.
The completed object retains the callable ID and name, return type, parameters, entry block, and complete block list.

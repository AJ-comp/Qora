Basic Blocks and Terminators

How one if is split into b0 through b3

← Previous: Qubit versionsAll chapters
Next: Conditional lowering →

MIR does not preserve an if as a nested statement tree.
It groups uninterrupted sequences of instructions into basic blocks and records the next destination at the end of each block.
The if in the running example becomes four blocks: b0, b1, b2, and b3.

Qora code under examination

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

The program executes X when the condition is true and does nothing when it is false.
Regardless of the selected path, it must execute H after the if.
MIR separates these three regions to make the control flow explicit.

Complete connection of the four blocks

                         ┌─ true ─▶ b1: execute X ─┐
b0: evaluate and branch                            ├─▶ b3: execute H and return
                         └─ false ▶ b2: empty path ─┘

b0 evaluates the condition and selects one of two paths.
b1 represents the true body, while b2 represents the false path.
Both paths join again at b3, followed by the common H operation.

b0: evaluate the condition and select a path

b0 also contains the array declaration and update that execute before the if, but only its final part matters here.
MIR evaluates values[0] == 1 to produce %v10, and branch uses that value to select the next block. 

b0
├─ %v10 = values[0] == 1
└─ branch %v10
   ├─ true  → b1
   └─ false → b2

The instruction that chooses the next destination at the end of a block is called a terminator.
The terminator of b0 is a branch with two destinations.
Execution splits because a true condition selects b1, while a false condition selects b2.

b1 and b2: execute each path and move to the join

b1
├─ X(q0.v0) → q0.v1
└─ jump b3

b2
└─ jump b3

b1 executes X(q[0]) from the true body.
No statements remain on that path, so jump b3 moves execution to the join point.

Although the source has no else, b2 is still required.
MIR must represent where execution goes after skipping X when the condition is false.
This path has no body to execute, so it contains only jump b3.

jump is also a terminator that ends a block.
A branch selects a destination from a condition, while a jump moves to one fixed destination.

b3: join the paths and execute the remaining code

b3
├─ q0.v2 = phi(b1: q0.v1, b2: q0.v0)
├─ H(q0.v2) → q0.v3
└─ return

Both b1 and b2 reach b3.
The true path contributes q0.v1 after X; the false path contributes original version q0.v0.
The Phi combines both inputs into one joined version, q0.v2.

The source statement H(q[0]) follows the if, so it executes in b3.
H takes joined version q0.v2 and creates q0.v3. Because no statements remain in Work, an implicit return added by MIR ends the block and callable.

MIR retains both paths

All four blocks exist in MIR, but one execution follows only the path selected by the condition.
Lowering does not precompute the result of calling Next, so it represents both possibilities below. 

true path
b0 → b1 → b3 → return

false path
b0 → b2 → b3 → return

As shown in the previous chapter, this exact example selects the true path at runtime.
The false path b2 is another control-flow possibility preserved by lowering, not a path removed by predicting the execution result.

Summary

Control flow in one statement b0 uses branch to select a path; b1 and b2 process their respective paths and use jump to meet at b3.
b3 joins the path-specific qubit versions, executes H, and ends with return.

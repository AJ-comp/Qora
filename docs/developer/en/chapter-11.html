Classical Values and SSA Versions

Why MIR assigns a new value number when the value of one variable changes

← Previous: Callable loweringAll chapters
Next: Storage and array state →

Source code can assign a new value to the same variable name.
MIR distinguishes old and new values by never overwriting a value and assigning a new number whenever a new MIR value is created. This chapter shows how that rule applies to the running example.

Source statements that change values

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

This chapter follows only the classical values of values and the condition expression.
There is only one source name, values, but its contents change.
Immediately after declaration, element 0 is 0. After the assignment, it contains the value returned by Next. The conditional must read this updated second state.

Keep the name and assign a new number to each value

Qora source
values = initial array
values = array after updating an element

MIR
%v1 = initial array
%v6 = new array state after updating element 0 of %v1

Value currently referenced by values
%v1  ──after assignment──▶  %v6

MIR values %v1 and %v6 are not different source variables.
Both are associated with the source variable values, but they represent the array state at different points in time.

The number after %v is an ID that distinguishes the order in which values are created.
Each ID is defined once and is never overwritten with another value. This single-definition property is the central rule of SSA.

Next keeps its input separate from its result

function Next(value: int): int

%v0 = parameter value
%v1 = constant 1
%v2 = %v0 + %v1
return %v2

Computing value + 1 does not change the parameter value %v0 itself.
Constant 1 becomes %v1, and the addition result becomes a new value, %v2. Consequently, the compiler can trace every value back to its origin.

Value numbers only need to be unique within one callable.
Therefore, %v1 in Next and %v1 in Work below are different values and do not conflict.

The array declaration creates the first state

var values: int[] = [0];

%v0 = constant 0
%v1 = [%v0]

current values → %v1

First, the compiler creates the number 0 for the array element. It then uses that value to create %v1, an array state of length 1.
From this point on, reading the source name values uses its current value, %v1.

An array also has a storage identity separate from its value versions.
Put simply, storage identifies “which array location this is,” while an SSA value such as %v1 describes “what that array contains now.” Chapter 12 examines this distinction in detail.

An array assignment creates a new array state

values[0] = Next(values[0]);

%v2 = destination index 0
%v3 = source index 0
%v4 = value read from %v1[%v3]
%v5 = return value of Next(%v4)
%v6 = new array state with %v5 stored at index %v2 of %v1

current values: %v1 → %v6

The important point is that %v1 is not overwritten.
Updating the element produces a new array state, %v6. Only the “current value of values” remembered by the lowerer changes to %v6.

Calculations before the assignment can therefore continue to refer to %v1, while calculations after it read %v6.
The compiler preserves the exact point at which the value changed while keeping one variable name in the source.

The conditional reads the latest value

if (values[0] == 1)

current values = %v6
        │
        ├─ create index 0 → %v7
        ├─ read %v6[%v7] → %v8
        └─ create constant 1 → %v9
                  │
                  ▼
             compare values → %v10
                  │
                  ▼
             branch on %v10

The condition reads the latest array state, %v6, rather than the initial state %v1.
MIR preserves the result of Next as call result %v5 instead of replacing it with the number 1 in advance.
The comparison result is therefore not fixed to true ahead of time. At execution, the computed %v10 determines which block is selected.

Summary

One name, values from different points in time The source name values remains unchanged.
Its current array state changes from %v1 immediately after declaration to %v6 after assignment, and each MIR value is defined exactly once.

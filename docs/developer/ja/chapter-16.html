program と解析結果が同じ MIR を参照するための境界

第9章では、Next と Work が MirProgram にまとめられ、その program が MirSnapshot になる流れを確認しました。
この章では、snapshot が program と解析を同じ基準へ結び付けるという一つの役割だけを確認します。

MirSnapshot が現在の MIR 状態を表す

MirProgram が実行構造そのものなら、MirSnapshot はその program と専用の解析窓口を一緒に保持する不変の結果です。
HIR から最初に lower された program は MirSnapshot.CreateLowered(program) によって最初の snapshot になります。

Program は HIR から lower された MIR 実行構造です。
Analyses はその Program を基準に必要な MIR 解析を提供します。

Snapshot は MIR 解析の基準になる

MirSnapshot には、この program を解析する窓口である Analyses があります。
たとえば Work の制御フローを要求すると、この snapshot 内の Work を基準に CFG を求めます。

解析結果は別の program を作りません。
現在の snapshot の MIR から計算した派生情報です。CFG が作られる過程は第17章で続けて確認します。

次の章では、Work の制御フローを要求したとき、すでに作られた block と Terminator から CFG がどう計算されるかだけを確認します。

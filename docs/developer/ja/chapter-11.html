古典値と SSA バージョン

同じ変数の値が変わるとき、MIR が新しい値番号を作る理由

← 前：Callable lowering全章目次
次：Storage と配列状態 →

ソースでは、同じ変数名へ新しい値を代入できます。
MIR は古い値と新しい値を区別するために値を上書きせず、新しい MIR 値が生まれるたびに新しい番号を付けます。この章では、この規則が共通例へどう適用されるかを確認します。

値が変わるソース文

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

この章では、上のソースのうち values と条件式の古典値だけを追跡します。
values という名前は一つだけですが、その内容は変わります。
宣言直後の要素 0 は 0 であり、代入後は Next の戻り値に変わります。条件文は更新後の二つ目の状態を読まなければなりません。

名前は維持し、値に新しい番号を付ける

Qora ソース
values = 最初に作った配列
values = 要素を更新した配列

MIR
%v1 = 最初に作った配列
%v6 = %v1 の要素 0 を更新した新しい配列状態

現在 values が指す値
%v1  ──代入後──▶  %v6

MIR の %v1 と %v6 は、別々のソース変数ではありません。
どちらもソース変数 values に関連する値ですが、異なる時点の配列状態を表します。

%v の後ろの数字は、値が作られた順序を区別する ID です。
各 ID は一度だけ定義され、後から別の値で上書きされません。一つの値が一度だけ定義されることが SSA の中心規則です。

Next では入力と結果を分ける

function Next(value: int): int

%v0 = パラメータ value
%v1 = 定数 1
%v2 = %v0 + %v1
return %v2

value + 1 を計算しても、パラメータ %v0 自体は変わりません。
定数 1 は %v1、加算結果は %v2 という新しい値になります。そのため、各値がどこから来たかを計算経路に沿って逆にたどれます。

値番号は callable 内だけで区別すれば十分です。
したがって、Next の %v1 と、下に出てくる Work の %v1 は別の値であり、衝突しません。

配列宣言で最初の状態を作る

var values: int[] = [0];

%v0 = 定数 0
%v1 = [%v0]

現在の values → %v1

まず配列要素に入れる数値 0 を作り、その値を使って長さ 1 の配列状態 %v1 を作ります。
この時点からソース名 values を読むと、現在値である %v1 を使います。

配列には、値バージョンとは別に storage identity もあります。
簡単に言えば、storage は「どの配列領域か」を表し、%v1 のような SSA 値は「その配列が今どの内容を持つか」を表します。この区別は第12章で詳しく確認します。

配列代入は新しい配列状態を作る

values[0] = Next(values[0]);

%v2 = 保存先インデックス 0
%v3 = 読み取りインデックス 0
%v4 = %v1[%v3] から読んだ値
%v5 = Next(%v4) の戻り値
%v6 = %v1 の %v2 位置を %v5 に変えた新しい配列状態

現在の values: %v1 → %v6

重要なのは、%v1 を上書きしない点です。
要素を更新した結果は新しい配列状態 %v6 になり、lowerer が記憶する「現在の values 値」だけが %v6 に変わります。

したがって、代入前の計算は引き続き %v1 を参照でき、代入後の計算は %v6 を読みます。
コンパイラは値が変わった時点を失わずに、ソースの変数名を一つのまま維持できます。

条件文は最新の値を読む

if (values[0] == 1)

現在の values = %v6
        │
        ├─ インデックス 0 を作る → %v7
        ├─ %v6[%v7] を読む → %v8
        └─ 定数 1 を作る → %v9
                  │
                  ▼
             二つの値を比較 → %v10
                  │
                  ▼
             %v10 に従って分岐

条件式は最初の配列状態 %v1 ではなく、最新状態 %v6 を読みます。
MIR は Next の結果を事前に数値 1 へ置き換えず、%v5 という呼び出し結果として保持します。
したがって比較結果も事前に true へ固定せず、実行時に計算される %v10 が移動先 block を決めます。

まとめ

同じ名前、異なる時点の値 ソース名 values はそのまま維持されます。
一方、現在の配列状態は宣言直後の %v1 から代入後の %v6 へ変わり、二つの MIR 値はそれぞれ一度だけ定義されます。

次の章では、ここで触れた配列 storage を詳しく見ます。
同じ配列領域と、時間とともに変わる配列値を MIR がどう一緒に表現するかを確認します。

条件文で状態を分けて合流する

true 経路の変更が false 経路へ混ざらない理由

第14章では、if が四つの block に分かれる様子を確認しました。
この章では、二つの経路の現在キュービットバージョンを別々に維持し、再び合流する過程だけを確認します。

確認する Qora コード

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

values[0] == 1 が true なら q[0] に X を適用し、false なら何も起こりません。
MIR には両方の経路が残るため、if の後の H(q[0]) はどちらの経路からも続けられる必要があります。

この章で答える問い true 経路で X が現在バージョンを変えても、false 経路はなぜ元のバージョンを維持できるのでしょうか。
MIR は経路別に現在状態を管理し、合流点で比較します。

二つの経路は同じ入力から別々に始まる

if の直前では、現在の q が q0.v0 を指します。
lowerer はこの記録を true 経路と false 経路へそれぞれ複製し、二つの経路を独立して処理します。

したがって true 経路で X を処理しても、true 経路の記録だけが q0.v1 へ変わります。
false 経路は別の記録を使うため、引き続き q0.v0 を指します。

合流点で二つの記録を一度比較する

合流点では、二つの経路が記録した現在バージョンを比較します。
二つのバージョンが同じならそのまま使い、この例の q0.v1 と q0.v0 のように異なるなら Phi バージョン q0.v2 を作ります。

比較後、合流後の現在 q 記録は q0.v2 一つになります。
後の H(q[0]) は経路別の記録を再確認せず、この合流記録だけを使います。

まとめ 条件文 lowering の要点は、経路別に現在状態を記録することです。
そのため一方の経路の変更が他方へ混ざらず、合流点でだけ二つの記録を比較して一つにつなぎます。

次の章では、こうして完成した Next と Work を一つの MirProgram へまとめる過程を確認します。

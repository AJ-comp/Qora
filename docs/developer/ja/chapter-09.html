最終 HIR から最初の MIR へ

意味解析済みのプログラムが MIR 全体へ変わる大きな流れ

この章では、最終 HIR が MIR へ渡る境界だけを確認します。
個々の文や式をどう変換するかは後に回し、プログラム全体がどの入力からどの結果になるかを先に把握します。

使用するサンプルプログラム

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

意味解析が終わると、HIR には Next と Work という二つの callable があります。
Work は実行を開始する operation、Next はその中で呼び出される function です。

HIR → MIR 境界の全体像

最終 HIR compilation
├─ Next
└─ Work  ← entry operation
        │
        │ ToMir()
        ▼
最初の MIR snapshot
└─ MirProgram
   ├─ Next  (MirCallable)
   ├─ Work  (MirCallable)
   └─ EntryPoint = Work

要点は単純です。
ToMir() は最終 HIR の callable を一つずつ MIR callable に変換し、完成した callable を一つの MirProgram にまとめます。その後、その program を最初の MirSnapshot で包んで返します。

二つの callable を MirProgram にまとめる

意味解析済みの最終 HIR で callable 一覧を先頭から順に走査します。
この例では、まず Next を変換し、続いて Work を変換します。 

HIR callable 一覧
├─ Next
│  └─ callable lowering → MirCallable Next
└─ Work
   └─ callable lowering → MirCallable Work

完成した MIR callable 一覧
├─ MirCallable Next
└─ MirCallable Work

ここで callable lowering とは、一つの function または operation のパラメータ、本文、block を MIR 形式にする処理です。
その内部過程は第10章で個別に確認します。この章では、二つの結果が一つの一覧へ集められる点だけ押さえれば十分です。

すべての callable が揃うと MirProgram を作ります。
callable 一覧だけでなく、どの callable から実行を始めるかも同時に決めます。この例の entry point は operation の Work です。

最初の MirSnapshot を作る時点

MirProgram
├─ Callables
│  ├─ Next
│  └─ Work
└─ EntryPoint = Work
        │
        │ CreateLowered(program)
        ▼
MirSnapshot
├─ Program = 上の MirProgram
└─ Analyses = その Program 専用の解析窓口

MirProgram が完成すると、MirSnapshot.CreateLowered(program) が最初の MIR snapshot を作ります。
返された snapshot は、今作った MirProgram と、その program を解析する Analyses を一緒に保持します。

まとめ

ToMir()
→ 意味解析済みの HIR を選択
→ Next と Work を個別の MirCallable へ変換
→ EntryPoint が Work の MirProgram を作成
→ その MirProgram と Analyses を持つ MirSnapshot を返す

以上が HIR から MIR へ移る境界の全体です。
次の章では、この流れのうち一つの callable を変換する部分だけを拡大し、Next と Work がそれぞれどの MirCallable になるかを確認します。

LowerHirArtifact()

最終 HIR の callable を1つずつ MIR へ lower し、その結果を最初の MirSnapshot にまとめる関数です。
このトレースでは、foreach が Next、続いて Work を処理します。

この関数が受け取る Qora プログラム

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

この関数は、配列宣言や if などの個別の文をまだ直接処理しません。
まずプログラムから2つの宣言を取り出し、Next h6 と Work h44 という callable として扱います。Work 内の Next(values[0]) は3つ目の callable ではなく、すでに一覧にある Next h6 を呼び出す式です。
また、実行を開始できる operation は Work なので、EntryCallable も Work h44 です。

共通例での呼び出し直前 hirArtifact.Source.Program.Callables = [Next h6, Work h44]
hirArtifact.Source.Program.EntryCallable = Work h44
traceSink = null 
private static MirSnapshot LowerHirArtifact(
    HirSemanticArtifact hirArtifact,
    IMirLoweringTraceSink? traceSink)
{
    // hirArtifact には意味解析後の最終 HIR が入っています。
    // Callables = [Next h6, Work h44]
    // EntryCallable = Work h44
    ArgumentNullException.ThrowIfNull(hirArtifact);

    var hirSnapshot = hirArtifact.Source;
    var hirProgram = hirSnapshot.Program;

    // 例の値: hirEntryCallable = Work h44
    var hirEntryCallable = hirProgram.EntryCallable
        ?? throw new InvalidOperationException(
            "validated HIR must contain an operation before MIR lowering");

    // まだ callable を lower していないため、両方とも空です。
    var mirCallables = new List<MirCallable>();
    MirCallable? mirEntryCallable = null;

    foreach (var hirCallable in hirProgram.Callables)
    {
        // 1回目: hirCallable = Next h6
        // 2回目: hirCallable = Work h44
        // 反復ごとに新しい lowerer を作るため、2つの作業状態は混ざりません。
        var mirCallableLowerer = new HirCallableToMirLowerer(
            hirCallable,
            hirArtifact,
            traceSink);

        // 1回目の結果: mirCallable = Next c6
        // 2回目の結果: mirCallable = Work c44
        var mirCallable = mirCallableLowerer.LowerToMirCallable();

        // 1回目の後: mirCallables = [Next c6]
        // 2回目の後: mirCallables = [Next c6, Work c44]
        mirCallables.Add(mirCallable);

        // Next はエントリー operation ではないため、1回目は false です。
        // Work は hirEntryCallable と同じオブジェクトのため、2回目は true です。
        if (ReferenceEquals(hirCallable, hirEntryCallable))
            mirEntryCallable = mirCallable;
    }

    // 最終結果:
    // Callables  = [Next c6, Work c44]
    // EntryPoint = Work c44
    var mirProgram = new MirProgram(
        mirEntryCallable
            ?? throw new InvalidOperationException(
                "validated HIR entry callable must be lowered into MIR"),
        mirCallables);

    return MirSnapshot.CreateLowered(mirProgram);
}

コードを実行順に追跡する

  1. 入力を確認します。 callable 一覧は [Next h6, Work h44]、エントリー callable は Work h44 です。
  2. 1回目で Next h6 を処理します。 新しい lowerer が Next c6 を返し、結果一覧は [Next c6] になります。
  3. 2回目で Work h44 を処理します。 新しい lowerer が Work c44 を返し、結果一覧は [Next c6, Work c44] になります。
  4. エントリーポイントを接続します。 2回目の HIR オブジェクトが EntryCallable と同一なので、mirEntryCallable = Work c44 になります。
  5. プログラムと snapshot を作ります。 2つの callable とエントリーポイントを持つ mirProgram を MirSnapshot.CreateLowered(mirProgram) に渡します。
戻り値 MirSnapshot
Program.Callables = [Next c6, Work c44]
Program.EntryPoint = Work c44

HirCallableToMirLowerer(...) コンストラクター

1つの HIR callable 専用の lowerer に変換対象と最終意味情報を保存し、MIR callable ID を準備するコンストラクターです。
共通例では Next h6 と Work h44 を対象に、それぞれ1回ずつ実行されます。 

public HirCallableToMirLowerer(
    HirCallable hirCallable,
    HirSemanticArtifact hirArtifact,
    IMirLoweringTraceSink? traceSink)
{
    // 1回目の呼び出し:
    // hirCallable = Next h6
    // hirArtifact = 最終 HIR artifact([Next h6, Work h44])
    // traceSink = null
    //
    // 2回目の呼び出し:
    // hirCallable = Work h44
    // hirArtifact = 最終 HIR artifact([Next h6, Work h44])
    // traceSink = null

    _hirCallable = hirCallable;
    _hirArtifact = hirArtifact;

    // 1回目: hirCallable.Id.Value = 6  → _mirCallableId = c6
    // 2回目: hirCallable.Id.Value = 44 → _mirCallableId = c44
    _mirCallableId = new MirCallableId(hirCallable.Id.Value);
    _traceSink = traceSink;
}

LowerToMirCallable()

1つの HIR callable を、エントリー block・パラメーター・本体・終了を持つ MirCallable として完成させる中心関数です。
共通例では Next h6 の lowerer と Work h44 の lowerer で、それぞれ1回ずつ実行されます。

1. Next h6 の処理

function Next(value: int): int
{
    return value + 1;
}

Next の元コードから作られるパラメーターと MIR 本体

以下の図は、LowerToMirCallable() が1つの callable を最初から MirCallable の返却まで処理する流れを段階別に示します。
左側は実際の C# コード、右側は各コード範囲が Next の lowering 中に作る状態です。
この実行は _hirCallable = Next h6、_mirCallableId = c6 から始まります。

Next の明示的な return が b0 を閉じるため、本体の lowering 後に現在 block は null です。
したがって、開いた operation 経路へ暗黙の return を追加する分岐は実行されません。

2. Work h44 の処理

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

Work の元コードから作られる MIR builder

同じ LowerToMirCallable() を、今度は Work を入力として追跡します。
この実行は _hirCallable = Work h44、_mirCallableId = c44 から始まります。

LowerParameters()

現在の HIR callable のパラメーターを宣言順に読み、MIR パラメーターとして登録する関数です。
共通例では、パラメーターを1つ持つ Next h6 と、パラメーターを持たない Work h44 でそれぞれ1回実行されます。

コードに現れる _mirValues、_mirParameters、_currentMirBlockBuilder、_currentFlowState はローカル変数ではなく、現在の lowerer オブジェクトのフィールドです。
実際の宣言は private readonly List<MirValue> _mirValues = new();、private readonly List<IMirParameter> _mirParameters = new();、private MirBlockBuilder? _currentMirBlockBuilder;、private LoweringFlowState _currentFlowState = new(); です。

1. Next h6 の value を登録

function Next(value: int): int
{
    return value + 1;
}

この実行で読む対象は、括弧内の value: int 1つです。
エントリー block b0 はすでに作られていますが、まだ空です。パラメーターと MIR 値を入れるリストも空の状態から始まります。

紫色の名前が指す値

紫色の表記は、lowerer のフィールド名、またはそのフィールドから始まるプロパティパスです。

_hirCallable
HirCallable現在 lower している HIR callable 宣言
_mirCallableId
MirCallableId現在作成している MIR callable の識別子
_hirCallable.Parameters
IReadOnlyList<HirParameter>HIR パラメーターを宣言順に保持するリスト
_mirParameters
List<IMirParameter>ここまでに登録した MIR パラメーターのリスト
_mirValues
List<MirValue>現在の callable で生成した MIR 値のリスト
_currentFlowState
LoweringFlowState現在経路のシンボルごとの値・qubit・lifetime 状態
_currentMirBlockBuilder
MirBlockBuilder?次の instruction を追加する block builder

2. パラメーターを持たない Work h44 の処理

Work() の括弧内にはパラメーターがありません。
同じ LowerParameters() に入りますが、今回は for 本体を1回も実行しません。

つまり Work の実行では、新しいパラメーターオブジェクトも MIR 値も作られません。
ただし、b0 が空なのは Work にパラメーターがないためだけではありません。この関数は callable パラメーターを登録するだけで、block argument や instruction は追加しません。そのため Next と Work のどちらでも b0 は変化しません。

LowerClassicalParameter()

HIR の古典パラメーター1つを、MIR 値と MirClassicalParameter として登録する関数です。
以下の実行では、Next(value: int) の value h0 1つを処理します。

実際の引数 hirParameter = value h0
hirParameterSymbolId = SymbolId(value)
mirParameterOrigin = MirHirOrigin(HIR h0, value の source span)
requiredArrayLengths = null 
private void LowerClassicalParameter(
    HirParameter hirParameter,
    SymbolId hirParameterSymbolId,
    MirOrigin mirParameterOrigin,
    IReadOnlyDictionary<string, long>? requiredArrayLengths)
{
    /* value は配列ではなく int です。
    mirParameterType = MirType.Scalar(int) */
    var mirParameterType = hirParameter.IsArray
        ? MirType.Array(hirParameter.Type, hirParameter.RegisterSize)
        : MirType.Scalar(hirParameter.Type);

    /* 実際の整数値はまだ決まっていません。
    %v0 は呼び出し時に value として渡される int 値を表します。

    _mirValues
    └─ [0] MirValue %v0
       ├─ Id = v0
       ├─ Type = int
       └─ Origin = MirHirOrigin(value h0) */
    var mirParameterValue = CreateMirValue(
        mirParameterType,
        hirParameterSymbolId,
        mirParameterOrigin);

    /* scalar なので結果は (null, 0) です。 */
    var (mirArrayStorage, minimumLength) =
        CreateMirParameterStorage(
            hirParameter,
            hirParameterSymbolId,
            mirParameterOrigin,
            requiredArrayLengths);

    /* SymbolId(value) ──▶ MirValueId v0 */
    _currentFlowState.CurrentMirValueByHirSymbolId[hirParameterSymbolId] = mirParameterValue.Id;

    /* mirArrayStorage が null なので Scalar を呼び出します。
    Name、Ownership、Access は hirParameter から直接読みます。 */
    var mirParameter = mirArrayStorage is null
        ? MirClassicalParameter.Scalar(
            hirParameter,
            mirParameterValue)
        : MirClassicalParameter.Array(
            hirParameter,
            mirParameterValue,
            mirArrayStorage,
            minimumLength);

    /* _mirParameters
    └─ [0] MirClassicalParameter value
       ├─ Value ──▶ _mirValues[0] (%v0)
       ├─ Storage = null
       ├─ Ownership = Borrowed
       ├─ Access = ReadOnly
       └─ MinimumLength = 0 */
    _mirParameters.Add(mirParameter);
}

CreateMirParameterStorage()

古典パラメーター1つが scalar か array かを確認し、そのパラメーターに必要な MirArrayStorage? と MinimumLength をまとめて返す関数です。
scalar なら (null, 0) を返します。array なら新しい storage を作り、最小長を計算して両方を返します。

Next(value: int) の処理

実際の引数 hirParameter = value h0
hirParameterSymbolId = value 宣言の SymbolId
mirParameterOrigin = MirHirOrigin(HIR h0, value の source span)
requiredArrayLengths = null 
private (MirArrayStorage? Storage, int MinimumLength)
    CreateMirParameterStorage(
        HirParameter hirParameter,
        SymbolId hirParameterSymbolId,
        MirOrigin mirParameterOrigin,
        IReadOnlyDictionary<string, long>? requiredArrayLengths)
{
    /* value は scalar なので、この分岐を選びます。
    戻り値 = (Storage: null, MinimumLength: 0) */
    if (!hirParameter.IsArray) return (null, 0);

    /* 以下は array パラメーターの場合だけ実行されます。
    新しい storage を作り、HIR シンボルと MIR storage の対応を記録します。 */
    var mirArrayStorage = new MirArrayStorage(
        AllocateMirStorageId(),
        hirParameter.Name,
        mirParameterOrigin);
    _traceSink?.LinkStorage(
        hirParameterSymbolId,
        _mirCallableId,
        mirArrayStorage.Id);

    /* array パラメーターの既定の最小長は 1 です。
    呼び出し契約により大きな長さが記録されていれば、その長さを使います。 */
    var minimumLength = 1;
    if (requiredArrayLengths is not null
        && requiredArrayLengths.TryGetValue(
            hirParameter.Name,
            out var requiredLength))
    {
        if (requiredLength < 0 || requiredLength > int.MaxValue)
        {
            throw MirLoweringError(
                $"array parameter `{hirParameter.Name}` has invalid "
                + $"minimum length {requiredLength}");
        }

        minimumLength = Math.Max(minimumLength, (int)requiredLength);
    }

    return (mirArrayStorage, minimumLength);
}

LowerQubitParameter()

HIR の qubit パラメーター1つを初期バージョンの MirQubitParameter として作り、現在の lowerer の qubit 状態に登録する関数です。
既存の Next と Work には qubit パラメーターがないため、以下の小さな補助プログラムで target 1つを処理する流れを追います。

この実行で使用する callable

operation Apply(target: Qubit)
{
    X(target);
}

operation Main()
{
    use q = Qubit[1];
    Apply(q[0]);
}

現在の CLI 出力では、2つの callable は Apply h7/c7 と Main h17/c17 です。
今回処理する対象は Apply の target h0 1つで、Main はプログラムのエントリー operation を提供するためにあります。
LowerParameters() が先に target の宣言シンボルを root lifetime frame に登録し、その後で以下の LowerQubitParameter() を呼び出します。

この関数が変更するコレクション

各コレクションは、同じ qubit パラメーターを異なる目的で参照します。

_initialMirQubitsById
Dictionary<MirQubitId, MirQubit>qubit ID ごとの初期バージョン
_nextMirQubitVersionById
Dictionary<MirQubitId, int>次に割り当てるバージョン番号
CurrentMirQubitByHirSymbolId
Dictionary<SymbolId, MirQubit>HIR シンボルが現在参照する qubit バージョン
_mirParameters
List<IMirParameter>callable の MIR パラメーターリスト

_initialMirQubitsById[q0]、CurrentMirQubitByHirSymbolId[SymbolId(target)]、_mirParameters[0] には、同じ MirQubitParameter target q0.v0 オブジェクトが入ります。
この関数はパラメーターを登録するだけで instruction を出力しないため、b0 は空のままです。
q0.v1 はこの関数では作らず、本体の X(target) が qubit 状態を変更するときに生成されます。

LowerStatements()

HIR 文リストを先頭から走査し、各文を LowerStatement() に渡す関数です。
以下では Next の処理を最後まで確認してから、Work の処理へ進みます。

1. Next 本体の lowering

function Next(value: int): int
{
    return value + 1;
}

hirStatements には return value + 1; 1文だけが入り、開始時の現在 block は b0 です。
したがって外側の for は1回だけ実行されます。 

private void LowerStatements(IReadOnlyList<HirStatement> hirStatements)
{
    /* Next 本体を lower するときの実際の入力
    ├─ hirStatements = [return value + 1]
    ├─ hirStatements.Count = 1
    └─ _currentMirBlockBuilder = b0 */
    for (var hirStatementIndex = 0;
         hirStatementIndex < hirStatements.Count;
         hirStatementIndex++)
    {
        /* 最初の反復
        ├─ hirStatementIndex = 0
        ├─ hirStatements[0] = return value + 1
        └─ 現在 block = b0

        b0 は開いているため、以下の null 分岐は実行されません。 */
        if (_currentMirBlockBuilder is null)
        {
            /* 前の文が現在経路を終了させ、残りの文がある場合だけ実行されます。
               残りの文は MIR として出力せず、traceSink があれば
               その中の宣言シンボルを到達不能として記録します。 */
            for (;
                 hirStatementIndex < hirStatements.Count;
                 hirStatementIndex++)
            {
                MarkUnreachableDeclarations(
                    hirStatements[hirStatementIndex]);
            }
            return;
        }

        /* return 文を LowerStatement() に渡します。

        呼び出し前                       呼び出し後
        現在 block = b0                  b0.Terminator = return %v2
                                        現在 block = null */
        LowerStatement(hirStatements[hirStatementIndex]);
    }

    /* hirStatementIndex は 1 に増えます。
       1 < hirStatements.Count(1) が false なので、ループは終了します。
       したがって現在 block が null の状態で関数を終了します。 */
}

2. Work 本体の lowering

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

最初の呼び出しは、Work の最上位5文を受け取ります。
その呼び出しが if を lower するとき、true 本体と空の false 本体をそれぞれ同じ関数へ渡します。そのため Work の lowering 中に LowerStatements() は合計3回実行されます。 

private void LowerStatements(IReadOnlyList<HirStatement> hirStatements)
{
    /* Work の lowering 中に、同じ LowerStatements() 本体へ3回入ります。

    1回目 — Work 最上位本体
    ├─ hirStatements = [var values, use q, 配列代入, if, H]
    ├─ 開始 block = b0
    ├─ 5回反復
    └─ index 3 の if を lower している間に、以下の2呼び出しを実行します。

       LowerStatement(if)
       └─ LowerIf()
          ├─ LowerScopedBranch(b1, true 本体)
          │  └─ 2回目: LowerStatements([X(q[0])])
          └─ LowerScopedBranch(b2, false 本体)
             └─ 3回目: LowerStatements([])

    2回目 — if の true 本体
    ├─ hirStatements = [X(q[0])]
    ├─ 開始 block = b1
    └─ 1回反復

    3回目 — if の false 本体
    ├─ hirStatements = []
    ├─ 開始 block = b2
    └─ 0回反復 */
    for (var hirStatementIndex = 0;
         hirStatementIndex < hirStatements.Count;
         hirStatementIndex++)
    {
        /* 1回目と2回目の呼び出しでは現在 block が開いているため、
           以下の null 分岐は実行されません。

        1回目
        ├─ index 0～3 の開始時: 現在 block = b0
        └─ index 4 の開始時: 現在 block = b3

        2回目
        └─ index 0 の開始時: 現在 block = b1

        3回目は hirStatements.Count = 0 なので、
        for 本体自体を1回も実行しません。 */
        if (_currentMirBlockBuilder is null)
        {
            /* 前の文が現在経路を終了させ、残りの文がある場合だけ実行されます。
               残りの文は MIR として出力せず、traceSink があれば
               その中の宣言シンボルを到達不能として記録します。 */
            for (;
                 hirStatementIndex < hirStatements.Count;
                 hirStatementIndex++)
            {
                MarkUnreachableDeclarations(
                    hirStatements[hirStatementIndex]);
            }
            return;
        }

        /* 1回目の実行フロー
        ├─ index 0: var       処理後の現在 block = b0
        ├─ index 1: use       処理後の現在 block = b0
        ├─ index 2: 配列代入  処理後の現在 block = b0
        ├─ index 3: if を LowerStatement() に渡します。
        │
        │  この LowerStatement(if) 呼び出しが戻る前に、
        │  1回目の LowerStatements() 呼び出しはここで一時停止します。
        │
        │  2回目
        │  ├─ hirStatementIndex = 0
        │  ├─ X(q[0]) を LowerStatement() に渡します。
        │  └─ 現在 block = b1 の状態で戻ります。
        │
        │  3回目
        │  ├─ hirStatements.Count = 0
        │  ├─ for 本体を実行しません。
        │  └─ 現在 block = b2 の状態で戻ります。
        │
        │  両方の呼び出しが終わると、LowerIf() が b1 と b2 を b3 へ接続します。
        │  現在 block を b3 に変えた後、1回目の index 3 へ戻ります。
        └─ index 4: H の処理後、現在 block = b3 */
        LowerStatement(hirStatements[hirStatementIndex]);
    }

    /* 戻る順序
    1. 2回目が b1 を現在 block として戻ります。
    2. 3回目が b2 を現在 block として戻ります。
    3. 1回目が b3 を現在 block として戻ります。 */
}

LowerStatement()

HIR 文1つの種別を確認し、その種別を担当する lowering 関数へ渡します。
この関数自体の仕事は、以下の switch で正確に1つの分岐を選び、その helper を1回呼び出して戻ることです。

共通例でこの関数が受け取るすべての文

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

LowerStatement() は上のプログラム全体を一度に受け取らず、呼び出しごとに文を1つだけ受け取ります。
共通例では、Next の return 1回と Work の文6回を合わせ、合計7回実行されます。
以下の switch は、現在の引数 hirStatement の実際の HIR 型だけを確認します。case の記載順は実行順ではなく、1回の呼び出しで一致する case 1つだけが実行されます。 

1. Next: return value + 1

2. Work: var values = [0]
3. Work: use q = Qubit[1]
4. Work: values[0] = Next(values[0])
5. Work: if (values[0] == 1)
    6. true 本体: X(q[0])
7. Work: H(q[0])

6番の X(q[0]) は、5番の if を lower している途中で起こる入れ子の実行です。
一方、4番の代入文内の Next(values[0]) は式なので、別の LowerStatement() 実行には数えません。 

private void LowerStatement(HirStatement hirStatement)
{
    switch (hirStatement)
    {
        // Work の use q 文が選びます。
        case HirQubitDeclarationStatement hirQubitDeclaration:
            LowerQubitDeclaration(hirQubitDeclaration);
            return;

        // Work の var values 文が選びます。
        case HirVariableDeclarationStatement hirDeclaration:
            LowerDeclaration(hirDeclaration);
            return;

        // Work の values[0] 代入文が選びます。
        case HirAssignmentStatement hirAssignment:
            LowerAssignment(hirAssignment);
            return;

        // Work の H 呼び出しが選びます。
        // if 内の X 呼び出しも、入れ子の本体を lower するときに同じ分岐を選びます。
        case HirCallStatement hirCallStatement:
            LowerStatementCall(hirCallStatement);
            return;

        // Work の if 文が選びます。
        case HirIfStatement hirIf:
            LowerIf(hirIf);
            return;

        case HirForStatement hirFor:
            LowerFor(hirFor);
            return;

        case HirWhileStatement hirWhile:
            LowerWhile(hirWhile);
            return;

        case HirRepeatStatement hirRepeat:
            LowerRepeat(hirRepeat);
            return;

        // Next の return 文が選びます。
        case HirReturnStatement hirReturn:
            LowerReturn(hirReturn);
            return;

        default:
            throw MirLoweringError(
                $"unsupported HIR statement {hirStatement.GetType().Name}");
    }
}

コードを実行順に追跡する

  1. hirStatement の実際の型を確認します。 7回の各実行には、現在の文に対応する HIR 型が入ります。
  2. 一致する case を1つ選びます。 実際の文と選択される helper は以下の表のとおりです。
  3. helper 呼び出し直後に戻ります。 各 case 末尾の return により、同じ文を別の case で再処理しません。

共通例で選ばれる分岐

実行受け取る Qora 文一致する HIR 型呼び出す helper
1return value + 1HirReturnStatementLowerReturn()
2var values = [0]HirVariableDeclarationStatementLowerDeclaration()
3use q = Qubit[1]HirQubitDeclarationStatementLowerQubitDeclaration()
4values[0] = Next(values[0])HirAssignmentStatementLowerAssignment()
5if (values[0] == 1)HirIfStatementLowerIf()
6, 7X(q[0]), H(q[0])HirCallStatementLowerStatementCall()

7回の実行はすべて helper を1つ呼び出し、値を返さずに終了します。

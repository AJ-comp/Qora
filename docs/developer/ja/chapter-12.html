配列 Storage と値状態

$s0、%v1、%v6 が異なる理由

← 前：古典 SSA 値全章目次
次：キュービットバージョン →

この例のローカル配列を MIR で見ると、二種類の番号が現れます。
$s0 は「どの配列か」を区別し、%v1 と %v6 は「その配列の値が現在どの状態か」を表します。
この章では、下のコードで配列を作り、更新し、再び読む流れだけを追跡して両者の違いを確認します。

確認する Qora コード

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

最初の文は長さ 1 の配列 values を作ります。
次の文は現在の values[0] を Next へ渡し、返された値を要素 0 へ保存します。
ソースは同じ名前 values を使い続けますが、MIR は更新前と更新後を別の値として区別します。

MIR 結果の全体像

$s0 と %v1 は同じ情報を二重に保存しているわけではありません。
$s0 は配列自体を区別する名前札であり、%v1 はその配列が最初に持った値です。
要素を更新すると名前札は残り、値状態だけが %v6 へ変わります。

宣言：$s0 と %v1 を同時に作る

最初の文 var values: int[] = [0]; を lower すると、MIR に次の二種類の情報が生まれます。 

storage $s0 values: int[1]

%v0: int    = const 0
%v1: int[1] = array.create $s0 {%v0}

storage $s0 は Work 内で宣言された配列 values の identity です。
簡単に言えば、「これらの値はすべて values 配列に関する記録である」とまとめる名前札です。
配列要素が変わっても values が別の配列に置き換わるわけではないため、$s0 は維持されます。

一方、%v0 はリテラル 0、%v1 はその 0 を要素として持つ最初の配列状態です。
したがって、この時点の関係は単純です。

更新：同じ $s0 に新しい値状態を作る

values[0] = Next(values[0]);

この文は、まず既存の配列から要素 0 を読みます。
現在の配列状態は %v1 なので、MIR はその要素 0 を読み、%v4 に置きます。
続いて Next(%v4) の戻り値を %v5 とし、その値を位置 0 へ保存した新しい配列状態 %v6 を作ります。
間にある %v2 と %v3 はそれぞれ位置 0 を表す MIR 値です。この章では配列状態 %v1 と %v6 にだけ集中します。

ここで重要なのは、%v1 を書き換えないことです。
MIR 値は一度作られると変わらないため、更新は既存状態を入力として新しい状態 %v6 を作ります。
後の解析は、%v1 から更新前の配列を、%v6 から更新後の配列を正確に把握できます。

次の文は最新状態 %v6 を読む

次の条件式 if (values[0] == 1) にも、引き続き values とだけ書かれています。
しかし直前の代入後、values の現在状態は %v6 です。
したがって条件式は最初の状態 %v1 ではなく、更新状態 %v6 の要素 0 を読みます。

この例を実行すると Next(0) の結果は 1 です。
ただし MIR はその結果を事前に 1 と決めず、%v5 という呼び出し結果として保持します。ここで重要なのは数値を事前に知ることではなく、次の文が最新の配列状態 %v6 を読むことです。

まとめ

二種類の番号が答える問い $s0 は「どの配列か？」に答えます。
%v1 と %v6 は「その配列がこの時点でどの値を持つか？」に答えます。
配列要素を更新すると $s0 は維持され、値状態だけが %v1 → %v6 へ変わります。

次の章では同じ原理をキュービットへ適用します。
キュービットも q0 という identity は維持しますが、この例の X や H のようなキュービットへ書き込む命令を通ると、現在状態を表すバージョンが変わります。

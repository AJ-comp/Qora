CFG の successor と predecessor

Terminator の移動情報を両方向のグラフとして読む過程

← 前：MIR snapshot全章目次
次のトピック：到達可能性と支配関係 →

CFG は block 間の移動関係を表すグラフです。
Qora は新しい実行構造を作り直さず、各 block の末尾にある Terminator を読んでこのグラフを計算します。

CFG を作る Qora コード

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

第14章では、この条件文を四つの block に分けました。
b0 は条件を判断し、b1 は true 本文を実行し、b2 は false 経路を表します。最後の b3 で両経路が合流し、H を実行します。

矢印の元は Terminator

すべての block は最後に一つの Terminator を持ちます。
一般の MIR 命令が値を計算したりゲートを適用したりするのに対し、Terminator は block の終了後にどこへ移動するかを決めます。

Branch は行き先が二つ、Jump は一つです。
Return は callable 実行を終えるため、次の block はありません。CFG はこれらの事実を表にした結果です。

次の block を集めると successor 表になる

successor は「現在の block の次に進める block」です。
解析は各 block の Terminator が指す行き先を読み、次の表を作ります。

b0 は条件に従って二か所のどちらかへ進めるため、successor が二つあります。
b1 と b2 はどちらも合流 block b3 へ移動し、b3 は return するため空の一覧を持ちます。

注意 successor が二つあっても、両方の block を実行する意味ではありません。
CFG は実行中に選ばれ得る全経路を表し、実際の実行では条件に合う一経路だけを選びます。

矢印を反転すると predecessor 表になる

predecessor は「現在の block へ入れる前の block」です。
別の情報源から再計算せず、完成した successor 矢印の向きだけを反転します。

entry block b0 へ入る block はないため、空の一覧です。
合流 block b3 には true 経路 b1 と false 経路 b2 の両方が入るため、predecessor が二つあります。

predecessor を successor から作ると、二つの表の基準が一つに保たれます。
一方では b1 → b3 なのに、他方では b3 ← b1 が抜けるような不整合を避けられます。

二つの表が callable の CFG snapshot になる

現在の snapshot で Work の CFG を要求すると、解析ストアが Work の block と Terminator を読みます。
その結果、successor と predecessor を含む MirControlFlowSnapshot が作られます。

この CFG snapshot は、実行する二つ目の block ツリーではありません。
元の Work の block をそのまま指しながら、関係を素早く問い合わせられるよう整理した派生情報です。

まとめ Terminator が block 移動の原本であり、successor はその移動を順方向に整理した表です。
predecessor は同じ矢印を反転した表です。両方の結果は一つの callable 専用 CFG snapshot にまとめられ、後の MIR 解析の基盤になります。

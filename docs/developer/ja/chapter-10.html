1つの callable を MIR へ lower する

1つの function または operation が、パラメーター・block・本体を持つ MirCallable になるまで

次章：古典値と SSA バージョン →

第9章では、Next と Work がそれぞれ1つの MirCallable になることだけを確認しました。
この章では、1つの callable を lower するときに最初に何が作られ、ソース本体がどこへ入り、最終結果がどのような形になるかを確認します。

この章で比較する2つの callable

function Next(value: int): int
{
    return value + 1;
}

operation Work()
{
    var values: int[] = [0];
    use q = Qubit[1];

    values[0] = Next(values[0]);

    if (values[0] == 1)
    {
        X(q[0]);
    }

    H(q[0]);
}

どちらの宣言も callable ですが、構造は異なります。
Next は1つのパラメーターと戻り値を持つ短い function です。一方、Work はローカル配列・qubit・条件分岐を持つエントリー operation です。

この入力に対して、現在のコンパイラは Next h6 と Work h44 という2つの最終 HIR callable を生成します。
MIR は同じ数値 ID を保持するため、Next c6 と Work c44 が生成されます。以降のコードコメントでも、この ID を継続して使用します。

なぜ HIR を MIR へ lower するのか

HIR は、ユーザーが書いたコードの入れ子構造を保持するツリーです。
たとえば Work は配列宣言・代入・if・H 呼び出しを含み、その if は条件式と X 呼び出しを含みます。この構造は、名前と型の検査や元コードの理解に適しています。

しかしツリーだけでは、ある地点でどの値が現在値なのかを追跡しにくくなります。
ソースでは同じ values という名前を繰り返し使いますが、MIR は更新前の配列 %v1、読み出した要素 %v4、Next の結果 %v5、更新後の配列 %v6 を別々の値として区別します。

MIR は実行経路を block 間の接続として表現し、新しく作られた古典値を個別の SSA 値として記録します。
そのため後続解析は、ソースツリーを再解釈せずにグラフをたどり、値の変化と分岐の合流を確認できます。HIR はソースの意味を保持し、MIR は実行フローと値の追跡を明示します。

callable ごとに専用 lowerer を1つ作る

callable lowerer は、一度に1つの callable だけを担当する変換オブジェクトです。
Next の処理中は、Next のパラメーター・現在の block・値だけを管理します。その処理が終わると、新しい lowerer が Work を別に処理します。

callable を1つずつ取り出すコード

以下は現在の LowerHirArtifact() の完全なコードです。
実行文は実装と同一で、この章で使う Next と Work の値を示すコメントだけを追加しています。
このトレースでは任意の lowering trace sink を渡さないため、traceSink = null です。
C# コード内の下線付き関数名をクリックすると、実行トレースへ移動します。 

private static MirSnapshot LowerHirArtifact(
    HirSemanticArtifact hirArtifact,
    IMirLoweringTraceSink? traceSink)
{
    // hirArtifact には意味解析後の最終 HIR が入っています。
    // Callables = [Next h6, Work h44]
    // EntryCallable = Work h44
    ArgumentNullException.ThrowIfNull(hirArtifact);

    var hirSnapshot = hirArtifact.Source;
    var hirProgram = hirSnapshot.Program;

    // 例の値: hirEntryCallable = Work h44
    var hirEntryCallable = hirProgram.EntryCallable
        ?? throw new InvalidOperationException(
            "validated HIR must contain an operation before MIR lowering");

    // まだ callable を lower していないため、両方とも空です。
    var mirCallables = new List<MirCallable>();
    MirCallable? mirEntryCallable = null;

    foreach (var hirCallable in hirProgram.Callables)
    {
        // 1回目: hirCallable = Next h6
        // 2回目: hirCallable = Work h44
        // 反復ごとに新しい lowerer を作るため、callable の作業状態は混ざりません。
        var mirCallableLowerer = new HirCallableToMirLowerer(
            hirCallable,
            hirArtifact,
            traceSink);

        // 1回目の結果: mirCallable = Next c6
        // 2回目の結果: mirCallable = Work c44
        var mirCallable = mirCallableLowerer.LowerToMirCallable();
        mirCallables.Add(mirCallable);

        // Next はエントリー operation ではないため、1回目は false です。
        // Work は hirEntryCallable と同じオブジェクトのため、2回目は true です。
        if (ReferenceEquals(hirCallable, hirEntryCallable))
            mirEntryCallable = mirCallable;
    }

    // 最終結果:
    // Callables  = [Next c6, Work c44]
    // EntryPoint = Work c44
    var mirProgram = new MirProgram(
        mirEntryCallable
            ?? throw new InvalidOperationException(
                "validated HIR entry callable must be lowered into MIR"),
        mirCallables);

    return MirSnapshot.CreateLowered(mirProgram);
}

1回目の反復後、リストには Next c6 が入ります。2回目の反復で Work c44 が追加されます。
Work はエントリー operation なので、同じ Work c44 オブジェクトが MirProgram のエントリーポイントとして選ばれます。

以下は各反復で呼ばれる lowerer コンストラクターの完全なコードです。
担当する HIR callable、最終意味情報、任意の trace sink を保存し、HIR callable ノード ID の数値を対応する MIR callable ID として再利用します。 

public HirCallableToMirLowerer(
    HirCallable hirCallable,
    HirSemanticArtifact hirArtifact,
    IMirLoweringTraceSink? traceSink)
{
    // 1つ目のオブジェクト: Next h6
    // 2つ目のオブジェクト: Work h44
    _hirCallable = hirCallable;
    _hirArtifact = hirArtifact;

    // h6 は c6 に、h44 は c44 になります。
    _mirCallableId = new MirCallableId(hirCallable.Id.Value);

    // 既定の CLI 実行では trace を要求しないため null です。
    _traceSink = traceSink;
}

new で作られた lowerer は、空のパラメーターリスト・空の block リスト・現在 block なしの状態から始まります。
callable ごとに独立した block ID allocator を持つため、Next と Work はどちらも最初の block を b0 と名付けられます。

1つの callable を作る共通手順

すべての function と operation がこの手順を通ります。
違いはパラメーターと本体から生じます。単純な function は1つの block で済みますが、条件分岐を持つ operation は複数の block に分かれます。

Next と Work の実値を入れて関数を追跡する

LowerToMirCallable() は Next h6 の lowerer で1回、Work h44 の lowerer で1回実行されます。
以下のコメントは、同じコード内で両方の入力に対する値と分岐がどのように異なるかを示します。 

public MirCallable LowerToMirCallable()
{
    // 1回目: _hirCallable = Next h6
    // 2回目: _hirCallable = Work h44
    var mirCallableOrigin = MirOriginFor(_hirCallable);

    // 結果: 現在の Next または Work の宣言シンボル
    var hirCallableSymbol = RequireHirDeclarationSymbol(
        _hirCallable.Id,
        $"callable `{_hirCallable.Name}`");

    // 現在の callable を含む namespace を記録した HIR の名前構造。
    var hirScopeGraph = _hirArtifact.Model.ScopeGraph
        ?? throw MirLoweringError(
            "the final HIR semantic model has no scope graph");

    // Next 実行: qualifiedSourceCallableName = "Next"
    // Work 実行: qualifiedSourceCallableName = "Work"
    var qualifiedSourceCallableName =
        hirScopeGraph.QualifiedName(hirCallableSymbol);

    // 各 lowerer が自身の最初の block を作るため、それぞれ別の b0 を持ちます。
    _currentMirBlockBuilder = CreateMirBlock(mirCallableOrigin);

    // Next 実行: パラメーター value を %v0 として登録します。
    // Work 実行: パラメーターがないため _mirParameters = [] です。
    LowerParameters();

    /* LowerStatements() は現在の callable の本体全体を処理します。

    Next
    - return value + 1; の処理で計算 instruction と MirReturn terminator を b0 に追加し、b0 を閉じます。
    - 現在 block b0 が閉じられるため、_currentMirBlockBuilder は null になります。
    - _mirBlockBuilders = [b0]

    Work
    - b0 は変数宣言、qubit の準備、配列代入、if 条件を処理し、b1 または b2 への分岐で閉じます。
    - b1 は true 経路の X(q[0]); を処理し、b3 への移動で閉じます。
    - b2 は処理するソース文がない false 経路で、b3 への移動で閉じます。
    - b3 は b1 と b2 の合流点で、最後の H(q[0]); を処理します。
    - H(q[0]); は block を閉じず、その後に明示的な return もないため、
      b3 が開いた現在 block のまま残ります。

    処理後
    ├─ _mirBlockBuilders = [b0, b1, b2, b3]
    └─ _currentMirBlockBuilder = b3 */
    LowerStatements(_hirCallable.Body.Statements);

    // Next: 現在 block が null なので、以下の if を飛ばします。
    // Work: 現在 block が b3 なので、以下の if で b3 を閉じます。
    if (_currentMirBlockBuilder is not null)
    {
        if (_hirCallable.IsFunction)
        {
            // この例のどちらの callable も、この分岐は選びません。
            MarkCurrentMirBlockUnreachable(
                MirOrigin.GeneratedFrom(
                    mirCallableOrigin,
                    "missing validated function return"));
        }
        else
        {
            // Work 実行: 値を持たない暗黙の return を b3 に追加します。
            ReturnFromCurrentMirBlock(
                value: null,
                MirOrigin.GeneratedFrom(
                    mirCallableOrigin,
                    "implicit operation return"));
        }
    }

    // Next 実行: builder リスト [b0]
    // Work 実行: builder リスト [b0,b1,b2,b3]
    // 各 builder を immutable な MirBlock として確定します。
    var mirBlocks = new List<MirBlock>(_mirBlockBuilders.Count);
    foreach (var mirBlockBuilder in _mirBlockBuilders)
    {
        var mirBlock = mirBlockBuilder.Build();
        mirBlocks.Add(mirBlock);
    }

    // 最初に作られた b0 が常にエントリー block です。
    var mirEntryBlock = mirBlocks[0];

    // Next の戻り値: c6, "Next", int, [%v0], b0, [b0]
    // Work の戻り値: c44, "Work", null, [], b0, [b0,b1,b2,b3]
    return new MirCallable(
        _mirCallableId,
        qualifiedSourceCallableName,
        _hirCallable.ReturnType is { } returns
            ? MirType.Scalar(returns)
            : null,
        _mirParameters,
        mirEntryBlock,
        mirBlocks,
        mirCallableOrigin);
}

この関数は、上の図と同じ手順を実行します。
エントリー block を作り、本体を処理します。Next は明示的な return で終了し、Work は残った operation 経路を値なしの return で閉じます。その結果、それぞれ MirCallable Next c6 と MirCallable Work c44 になります。

2つの callable の本体文が渡される先

上の LowerStatements() は本体を先頭から末尾まで走査し、LowerStatement() は現在の文種別に対応する lowering helper を1つ選びます。
以下は両関数の現在の完全なコードです。コメントは Next と Work が実際に渡す値を示します。 

private void LowerStatements(IReadOnlyList<HirStatement> hirStatements)
{
    // Next 本体: [return value + 1]、b0 から開始
    // Work 最上位: [var, use, assignment, if, H]、b0 から開始
    // if の true 本体: [X(q[0])]、b1 から開始
    // if の false 本体: []、b2 から開始
    for (var hirStatementIndex = 0;
         hirStatementIndex < hirStatements.Count;
         hirStatementIndex++)
    {
        // 反復開始時に現在の経路がすでに閉じていれば、残りの文は出力しません。
        // この例の4回の呼び出しでは、この分岐は選ばれません。
        if (_currentMirBlockBuilder is null)
        {
            for (;
                 hirStatementIndex < hirStatements.Count;
                 hirStatementIndex++)
            {
                MarkUnreachableDeclarations(
                    hirStatements[hirStatementIndex]);
            }
            return;
        }

        LowerStatement(hirStatements[hirStatementIndex]);
    }
}

ループは文を1つ取り出すたびに、以下の LowerStatement() を呼び出します。 

private void LowerStatement(HirStatement hirStatement)
{
    switch (hirStatement)
    {
        // Work の use q 文が選びます。
        case HirQubitDeclarationStatement hirQubitDeclaration:
            LowerQubitDeclaration(hirQubitDeclaration);
            return;

        // Work の var values 文が選びます。
        case HirVariableDeclarationStatement hirDeclaration:
            LowerDeclaration(hirDeclaration);
            return;

        // Work の values[0] への代入文が選びます。
        case HirAssignmentStatement hirAssignment:
            LowerAssignment(hirAssignment);
            return;

        // Work の H 呼び出しが選びます。
        // if 内の X 呼び出しも、入れ子の本体を処理するときに同じ分岐を選びます。
        case HirCallStatement hirCallStatement:
            LowerStatementCall(hirCallStatement);
            return;

        // Work の if 文が選びます。
        case HirIfStatement hirIf:
            LowerIf(hirIf);
            return;

        case HirForStatement hirFor:
            LowerFor(hirFor);
            return;

        case HirWhileStatement hirWhile:
            LowerWhile(hirWhile);
            return;

        case HirRepeatStatement hirRepeat:
            LowerRepeat(hirRepeat);
            return;

        // Next の return 文が選びます。
        case HirReturnStatement hirReturn:
            LowerReturn(hirReturn);
            return;

        default:
            throw MirLoweringError(
                $"unsupported HIR statement {hirStatement.GetType().Name}");
    }
}

この switch は文の意味を再判定しません。
HIR ですでに分類された文種別を読み、対応する helper を呼んですぐに戻ります。

Next は1つの block で完成する

Next には value という1つの int パラメーターがあります。
lowerer はこれを MIR 入力値 %v0 として登録し、エントリー block b0 で本体を処理します。

ソース文 return value + 1; は計算と return に分かれますが、どちらも b0 に入ります。
return が block を終了させるため、追加の終了文は必要ありません。

Work は条件分岐によって複数の block に分かれる

Work にはパラメーターがありませんが、ローカル配列と qubit があります。
まずエントリー block で配列を作って qubit を準備し、その後に配列を更新して条件を評価します。

if に到達すると実行が2つの経路に分かれるため、b1 と b2 が必要になります。
両方の経路が終わると b3 で合流し、ソースの条件分岐後にある H(q[0]); がそこへ入ります。

Work のソースには return 文がありません。
operation は値を返さないため、lowerer は最後の b3 に値なしの return を自動で追加し、block を正常に閉じます。これを暗黙の return と呼びます。

完成した MirCallable が保持するもの

callable の lowering が終わると、作業中のリストが1つの MirCallable にまとめられます。
完成したオブジェクトは、callable の ID と名前、戻り値型、パラメーター、エントリー block、完全な block リストを保持します。

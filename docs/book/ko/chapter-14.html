14장. CNOT 게이트는 두 큐비트를 어떻게 연결할까?

CNOT 게이트는 두 큐비트에 작용하는 게이트예요.
두 큐비트 상태는 |00⟩, |01⟩, |10⟩, |11⟩처럼 두 자리로 적었고, 왼쪽 자리가 q[0], 오른쪽 자리가 q[1]이었어요.
CNOT은 두 큐비트를 인수로 받아요. 어느 큐비트가 어떤 역할을 하는지는 인수의 순서로 정해져요.

첫 번째 인수 제어 큐비트라고 불러요.
이 큐비트의 값이 0 쪽이면 아무 일도 하지 않고, 1 쪽이면 대상 큐비트를 뒤집으라는 조건이 돼요.
두 번째 인수 대상 큐비트라고 불러요.
제어 큐비트가 1인 경우에만 이 큐비트가 0에서 1로, 또는 1에서 0으로 바뀌어요.
CNOT 게이트는 제어 큐비트가 1일 때만 대상 큐비트를 뒤집어요.

이 장에서는 CNOT(q[0], q[1])처럼 써요. 그래서 상태의 첫 번째 자리(q[0])를 먼저 보고, 그 값에 따라 두 번째 자리(q[1])를 바꿀지 말지 결정하면 돼요.
인수 순서를 바꿔 CNOT(q[1], q[0])이라고 쓰면 q[1]이 제어 큐비트, q[0]이 대상 큐비트가 돼요. 아래 표는 CNOT(q[0], q[1])의 경우예요.

입력 상태제어 큐비트대상 큐비트 변화출력 상태
|00⟩0그대로|00⟩
|01⟩0그대로|01⟩
|10⟩10이 1로 바뀜|11⟩
|11⟩11이 0으로 바뀜|10⟩

여기서 |10⟩은 첫 번째 큐비트의 측정 결과값이 1이고 두 번째 큐비트의 측정 결과값이 0인 두 큐비트 상태를 뜻해요.
따라서 |10⟩에서 CNOT 게이트를 적용하면 제어 큐비트가 1이므로 대상 큐비트가 뒤집히고, 최종 상태는 |11⟩이 돼요.

제어 큐비트가 중첩이면 어떤 일이 생길까?

첫 번째 큐비트에 H 게이트를 적용하면 첫 번째 큐비트의 진폭이 측정 결과값 0과 1 쪽으로 나뉘어요.
그 상태에서 CNOT 게이트를 적용하면, 제어 큐비트가 0인 가지에서는 대상 큐비트가 그대로 있고 제어 큐비트가 1인 가지에서는 대상 큐비트가 뒤집혀요.
그래서 두 큐비트가 |00⟩과 |11⟩ 두 가능성으로 함께 묶인 상태가 돼요.

|00⟩ → H(q[0]) → (|00⟩ + |10⟩) / √2 → CNOT(q[0], q[1]) → (|00⟩ + |11⟩) / √2
이 상태가 얽힘을 이해하는 출발점이에요 마지막 상태를 측정하면 두 큐비트가 각각 따로 무작위로 나오는 것처럼 보이지 않아요.
측정 결과는 00 또는 11로만 나와요.
첫 번째 큐비트와 두 번째 큐비트의 측정 결과가 서로 맞물려 있기 때문이에요.

CNOT 게이트로 두 큐비트를 연결해보자

operation Main(): int {
    // 큐비트 두 개 준비
    // 준비 직후 q[0]q[1]은 |00⟩ 상태
    use q = Qubit[2];

    // 첫 번째 큐비트에 H 게이트 적용
    // q[0]의 진폭이 측정 결과값 0과 1로 나뉨
    H(q[0]);

    // CNOT 게이트 적용
    // q[0]이 제어 큐비트, q[1]이 대상 큐비트
    CNOT(q[0], q[1]);

    // 이상적인 실행 환경(노이즈 없음): 여러 번 실행하면 00과 11만 약 반반씩 나옴
    var first: bit = M(q[0]);
    var second: bit = M(q[1]);

    // 두 측정 결과값을 정수 하나로 묶어 실행 결과로 돌려줌
    // 왼쪽 자리가 q[0]: 00 → 0, 01 → 1, 10 → 2, 11 → 3
    // 그래서 실행 결과에는 0과 3만 보임
    var result: bit[] = [first, second];
    return AsInt(result);
}

---

**Qora는 양자 프로그래밍을 배우기 위한 학습용 언어입니다.** 양자 코드는 보통 Qiskit이나 Cirq 같은
Python 라이브러리로 작성하거나, 이론을 이미 알고 있다고 전제하는 연구용 언어로 작성하게 되는데,
처음 배우는 입장에서는 빠른 실험과 정확한 개념 사이를 오가기가 쉽지 않습니다.

그래서 Qora는 그 사이를 메우는 데 초점을 맞춥니다. 익숙한 형태의 프로그래밍 문법으로 회로를 작성하면, 컴파일러가 먼저 “이 프로그램이 정말 양자 컴퓨터가 할 수 있는 일인가?”를 확인합니다.
그다음 표준 **OpenQASM 3**를 만들어서, 결과를 한 줄씩 읽어보거나 실제 툴체인에 넘길 수 있게 해줍니다.

이 방향은 설계 기준에도 그대로 이어집니다.

- **에러가 출력보다 먼저 나옵니다.** 컴파일을 통과했다면 그 OpenQASM은 유효합니다.
- **컴파일러 내부를 확인할 수 있습니다.** 명령 하나로 소스, AST, 소스 모양 HIR, 심볼 정보, SSA/CFG MIR, 양자 효과 요약, QASM을 함께 볼 수 있습니다.
- **양자 규칙은 컴파일러가 직접 검사합니다.** 같은 큐비트를 제어와 타깃으로 함께 사용하거나, 이동된 바인딩을 사용하거나, 단일 큐비트 자리에 레지스터를 넘기면 진단을 보고합니다.

## 바로 시작하기

가장 빠른 길은 VS Code 확장으로 시작하는 것입니다.
컴파일러가 확장 안에 통째로 들어 있어서 **따로 설치할 것이 없고**, .NET이나 Python도 필요하지 않습니다.

1. VS Code 마켓플레이스에서 [Qora Language](https://marketplace.visualstudio.com/items?itemName=qora-lang.qora-language)  확장을 설치합니다.
2. `bell.qor` 파일을 만들고 위 예제를 붙여넣습니다.
3. 저장하면 바로 아래 기능을 사용할 수 있습니다.

- **타이핑하는 동안** 에러에 밑줄이 생기고, 밑줄에 마우스를 올리면 이유를 볼 수 있습니다. `CNOT(q[0], q[0])`도 한번 입력해 보세요.
- 게이트나 키워드에 마우스를 올리면 `H`, `use`, `M` 같은 항목의 짧은 설명이 뜹니다.
- **`Ctrl+Shift+P` → `Qora: Transpile to OpenQASM`** 명령을 실행하면 컴파일 결과가 옆 편집기에 열립니다.
- **`Qora: Show Compilation Stages`** 명령은 소스 → AST → HIR/심볼 → SSA/CFG MIR/양자 효과 → QASM 흐름을 저장할 때마다 새로 보여줍니다.

저장소에서 직접 실행하려면 .NET 10 SDK만 있으면 됩니다.

```bash
git clone https://github.com/AJ-comp/Qora.git
cd Qora
dotnet run --project src/Qora          # 데모 프로그램을 파싱하고 OpenQASM을 출력
```

직접 작성한 파일을 컴파일하거나 중간 단계를 확인하려면 다음 명령을 사용합니다.

```bash
dotnet run --project src/Qora -- --json bell.qor
dotnet run --project src/Qora -- --json --stages bell.qor
```

VS Code 확장도 같은 `--json` 인터페이스를 사용합니다. 각 응답에는 `{success, qasm, errors[]}`가 포함되며,
`--stages`를 함께 지정하면 AST, HIR, 심볼, MIR, 양자 효과 요약도 포함됩니다.
파일 경로 없이 `--json`을 실행하면 표준 입력에서 소스를 읽습니다.

## 5분 만에 훑는 Qora

**큐비트와 게이트.** 새 큐비트 레지스터는 `use q = Qubit[N];` 형태로 할당하고, 배열처럼 인덱스로 접근합니다.
여기서 `use`는 C#의 `using`처럼 블록 끝에서 자동 해제를 표현한다기보다, Qora 프로그램 안에 사용할 큐비트 레지스터를 만드는 구문입니다.
보조 연산은 레지스터를 `Qubit[]`로 받으며, 호출자가 넘긴 실제 길이는 `.Count`로 확인할 수 있습니다.
게이트 호출은 함수 호출과 같은 모양입니다.

```
use q = Qubit[3];              // 큐비트 레지스터 q를 할당, 크기는 3
H(q[0]);                       // 중첩
CNOT(q[0], q[1]);              // 얽힘
Rx(pi/2, q[2]);                // 회전 게이트는 각도가 먼저
Reset(q[2]);                   // 다시 |0⟩으로
```

내장 게이트: `H X Y Z S T` · `CNOT/CX CY CZ SWAP CCX` · `Rx Ry Rz` · `Reset ResetAll`.

**측정** 연산 `M`은 큐비트의 결과를 고전 `bit`에 담습니다.
`bit`는 리터럴 `0`이나 `1`로도 초기화할 수 있으며, 측정은 양자 정보를 고전 결과로 얻는 과정입니다.

```
var r: bit = M(q[0]);          // 측정, 되돌릴 수 없습니다
r = M(q[0]);                   // 같은 bit에 다시 측정
```

**고전 제어흐름**은 익숙한 모양 그대로 읽으면 되고, 측정 결과에 반응하는 회로도 작성할 수 있습니다.

```
const n: int = 2;
var count = 0;
for i in 0..n {  H(q[i]);  }
if (r == 1) {  X(q[1]);  } else {  Z(q[1]);  }
while (count < 2) {  count = count + 1;  }
repeat {  H(q[0]);  r = M(q[0]);  } until (r == 1);
```

**고전 배열**은 `bool`, `int`, `float`, `bit`, `angle` 값에 익숙한 `T[]` 형태를 사용합니다.
스칼라를 둘 수 있는 곳이면 어디든 — `Main`, 헬퍼 연산, 반복문·분기 안에도 — 선언할 수 있고(OpenQASM의 전역 스코프 규칙은 컴파일러가 자동으로 처리합니다), 인덱스로 원소를 읽고 바꿀 수 있으며 반복할 때는 `.Count`로 길이를 확인합니다.

```qora
var counts: int[] = [1, 2, 3];
var weights: float[] = new float[3];   // 0으로 초기화된 원소 세 개
weights[1] = 0.5;
for i in 0..counts.Count-1 { counts[i] = counts[i] + 1; }
```

`float`에서 `int`로의 암묵적 변환은 허용하지 않으므로 `var i: int = 0.5;`는 컴파일 오류입니다.
소수 부분이 없는 `1.0`도 `float`이므로 같은 기준을 적용합니다.
재대입, 배열 원소, function·operation의 인수와 반환값에서도 동일하게 검사합니다.
반면 `var i = 0.5;`는 `float`으로 추론하며, `int`에서 `float`으로의 변환은 허용합니다.

**함수(function)** 는 고전 값을 계산하며, 반환한 값을 식에서 사용할 수 있습니다. 순수 함수이므로 큐비트 할당·게이트·측정·operation 호출은 허용하지 않습니다. 반면 `operation`은 양자 작업을 수행하면서 `bool`, `int`, `bit`, `float`, `angle` 가운데 한 가지 타입의 값을 반환할 수 있습니다.

```qora
operation Read(q: Qubit): bit { return M(q); }
operation Main(): bit {
    use q = Qubit[1];
    H(q[0]);
    return Read(q[0]);
}
```

실행 결과에는 **각 샷에서 진입 operation이 반환한 값만** 표시합니다. 하위 operation의 반환값은 호출자에게 전달될 뿐, 자동으로 실행 결과에 포함되지 않습니다. 반환형을 생략하면 반환값이 없으며, 내부에서 측정하더라도 그 측정값은 자동으로 표시하지 않습니다. 실행 도구가 측정을 추가하는 동작도 없습니다.
반환값 없는 operation은 `return;`으로 일찍 종료할 수 있고, 반환형이 있는 operation은 모든 경로에서 해당 타입에 맞는 값을 반환해야 합니다. 배열·튜플 반환은 아직 지원하지 않으며, `angle` 실행 결과는 라디안 단위입니다.

산술식은 중첩된 괄호를 지원합니다. `(1 + 2) * 3`의 값은 `9`이고, `1 + 2 * 3`의 값은 `7`입니다.
반환식, 호출 인수, 배열 인덱스, 반복문 범위에도 괄호를 사용할 수 있습니다.
비교 연산자(`==`, `!=`, `<`, `<=`, `>`, `>=`)의 결과는 `bool` 값입니다.

```qora
function IsPositive(value: int): bool { return value > 0; }
operation Main(): bool {
    var isEqual: bool = 1 + 2 == 3;
    isEqual = (1 + 2) * 3 == 9;
    return isEqual == IsPositive(3);
}
```

따라서 비교 결과를 저장하거나 인수로 전달하거나 반환할 수 있으며, 변수 타입을 생략하면 `bool`로 추론합니다.
산술 연산을 먼저 계산하고, 그다음 `<`, `<=`, `>`, `>=`, 마지막으로 `==`, `!=`를 계산합니다.
논리 연산자(`!`, `&&`, `||`)는 기존과 같이 조건식에서만 사용할 수 있으며, 측정식을 사용할 수 있는 위치도 변경하지 않습니다.

`bool`은 논리값 `true`/`false`를, `bit`는 측정 결과값 `0`/`1`을 담습니다.
두 타입은 별개이므로 `bool`과 `bit`, `int`, `float`, `angle` 사이의 암묵적 변환은 어느 방향으로도 허용하지 않습니다.
이 기준은 초기화, 대입, 배열 원소, 인수, 반환값에 동일하게 적용합니다.
조건문은 `bool`만 받으므로 측정 결과는 `if (r == 1)`, 정수는 `if (count != 0)`처럼 명시적으로 비교합니다.
따라서 `if (r)`나 `if (count)`는 컴파일 오류이며, `bool`끼리는 동등 비교만 가능하고 크기 비교에는 수치가 필요합니다.
실행 결과도 타입을 유지하여, 반환한 `bool`은 `true`/`false`로, 반환한 `bit`는 `0`/`1`로 표시합니다.

```qora
function angleOf(k: int): angle { return pi / k; }

operation Main()
{
    use q = Qubit[1];
    Rx(angleOf(4), q[0]);       // 함수 결과가 회전 각도
    var r: bit = M(q[0]);
}
```

사용자 정의 연산은 이름과 매개변수 뒤에 블록을 붙여 작성하고, `Main`이 진입점입니다.
현재 사용자 문법의 **`Controlled` 함자**는 내장 게이트에 제어 큐비트를 추가합니다.

```qora
operation Main()
{
    use q = Qubit[2];
    H(q[0]);
    Controlled X(q[0], q[1]);
}
```

`Adjoint`는 Qora 사용자 문법이 아니며, 현재 HIR이나 MIR에도 존재하지 않습니다.
자동 uncomputation은 정확한 SSA/CFG 정보를 분석하고 필요한 cleanup을 생성하는 향후 MIR scheduler로 구현할 계획입니다.

**네임스페이스와 import**를 사용하면 큰 프로그램을 여러 파일로 나눌 수 있습니다.
`import`는 Python처럼 파일 경로를 문자열로 적습니다.

`gates_lib.qor`

```qora
namespace GatesLib
{
    operation Bell(q: Qubit[])
    {
        H(q[0]);
        CNOT(q[0], q[1]);
    }
}
```

`rotations.qor`

```qora
namespace Rotations
{
    operation Tilt(q: Qubit)
    {
        Ry(pi/4, q);
        Rz(pi/8, q);
    }
}
```

`main.qor`

```qora
import "gates_lib.qor";         // 같은 디렉터리의 gates_lib.qor를 불러옴
import "rotations.qor";         // 같은 디렉터리의 rotations.qor를 불러옴

namespace App
{
    open GatesLib;
    open Rotations;

    operation Prepare(q: Qubit[])
    {
        Bell(q);                // open으로 GatesLib.Bell을 이름만으로 호출
        Tilt(q[0]);             // open으로 Rotations.Tilt를 이름만으로 호출
    }
}

operation Main()
{
    use q = Qubit[2];
    App.Prepare(q);             // App 네임스페이스의 연산을 정규화해서 호출
    Rotations.Tilt(q[1]);       // import한 다른 파일의 연산을 네임스페이스로 직접 호출
}
```

이름 해소 규칙은 네임스페이스를 사용하는 익숙한 프로그래밍 언어의 방식과 비슷합니다.
이름은 자기 네임스페이스, 전역 네임스페이스, `open`한 네임스페이스 순서로 찾습니다.
그런데 `open`한 두 곳에 같은 이름이 있으면 몰래 하나를 고르지 않고, 후보를 보여주는 컴파일 에러를 냅니다.

`import "lib/gates.qor";`는 현재 파일이 있는 디렉터리를 기준으로 `lib/gates.qor`를 읽습니다.
경로는 따옴표 안에 그대로 적고, 확장자도 포함합니다.
성공적으로 읽은 문서는 정규화된 경로를 기준으로 재사용하므로, 반복 import나 순환 경로에서도 같은 문서를 다시 읽지 않습니다.
읽을 수 없는 import는 진단으로 보고합니다.

내장 게이트 이름도 같은 규칙을 따르며, 내장 게이트는 암묵적인 `Qora.Intrinsic` 네임스페이스에 살기 때문에, 네임스페이스 안에서는 `Rx` 같은 이름의 연산을 직접 정의할 수 있습니다.
다만 어떤 호출이 사용자 정의 연산과 내장 게이트 둘 다를 뜻할 수 있으면 명시적인 모호성 에러가 납니다.
이때는 사용자 정의 연산은 `L.Rx(q)`, 내장 게이트는 `Qora.Intrinsic.Rx(pi/2, q)`처럼 적어주면 됩니다.

스코프 안에 같은 이름의 사용자 후보가 없다면 맨이름 게이트는 그대로 내장 게이트를 뜻합니다. 따라서 문서에서 배운 게이트 이름을 프로그램에서도 그대로 사용할 수 있습니다.

**오류가 있으면 컴파일러가 이유를 알려줍니다.** 출력 생성 전에 진단을 보고합니다.

```
[QSEM006] in `Main`: `Bell` expects 1 argument(s) but got 2
[QSEM016] in `Main`: index `q[5]` is out of range; `q` has 2 qubit(s) (valid: 0..1)
[QSEM018] in `Go`: `Flip` is ambiguous here: it could be `LibA.Flip` or `LibB.Flip`
          — qualify the call (e.g. `LibA.Flip(...)`)
```

**프로그램 실행하기.** 사용자 정의 연산, 루프, 고전 변수, `while`까지 포함한 Qora 프로그램을 지금 바로
Amazon Braket 로컬 시뮬레이터에서 실행할 수 있습니다.

```bash
dotnet build src/Qora
python -m pip install -r vscode/runner/requirements.txt  # Python 3.11-3.13
python tools/run_braket.py yourfile.qor --shots 1000
```

저장소에는 [Braket 반환값 검증](tools/braket_validation.py)과
[Qiskit 임포터 호환성 점검](tools/qiskit_validation.py) 스크립트가 있습니다.
Qiskit 스크립트는 실행 결과를 표시하는 도구가 아니라 진단용입니다. 현재 임포터는 생성된 고전 변수·출력 선언을 모두 지원하지 않으며, 내부 측정 레지스터를 Qora의 반환값으로 대신 표시하지 않습니다.
이 검증이 모든 Qora 프로그램을 모든 시뮬레이터나 장치에서 실행할 수 있음을 보장하지는 않습니다.

확인된 실행 제한이 있습니다. 수정 전 Braket 로컬 시뮬레이터는 `bool[]`의 요소를 읽거나 배열을 함수 인수로 전달하면
`AttributeError: 'BoolType' object has no attribute 'size'` 오류를 냅니다.
Qora 없이 직접 작성한 OpenQASM `array[bool, 2]`에서도 같은 문제가 재현됩니다.
따라서 Qora는 올바른 논리 배열 타입을 유지하며, 이를 임의로 숫자 배열로 바꾸지 않습니다.
[Braket 이슈 #429](https://github.com/amazon-braket/amazon-braket-default-simulator-python/issues/429)에 보고하고,
[PR #430](https://github.com/amazon-braket/amazon-braket-default-simulator-python/pull/430)으로 수정을 제출했습니다.
이 수정과 기존 PR #425·#426·#428을 결합한 환경에서는 논리 배열과 S·T 사례를 포함한 현재 Qora 실행 검증 54개가 모두 통과했습니다.
다만 아직 upstream 머지·배포 전이므로, 일반 패키지 설치에는 이 로컬 검증용 수정들이 포함되지 않습니다.
또한 결합 환경에서도 `Qubit[]` helper 매개변수의 요소를 측정하면 실패하거나,
일부 비연속 큐비트 배치에서 제어 게이트가 잘못된 결과를 내는 Braket 문제가 남아 있습니다.
이 사례들은 통과한 54개 목록에 포함되지 않으므로, 해당 결과가 모든 Qora 프로그램의 실행을 보장하지는 않습니다.

## 컴파일러 흐름

설계 계약은 **[컴파일러 아키텍처](https://aj-comp.github.io/Qora/architecture/ko/index.html)** 문서에서 확인할 수 있습니다.
실제 소스와 구현을 함께 따라가려면 **[컴파일러 개발자 매뉴얼](https://aj-comp.github.io/Qora/developer/ko/index.html)**에서 시작할 수 있습니다.

컴파일러는 당신이 쓴 코드를, 양자 컴퓨터가 실제로 실행할 수 있는 표준 형식(**OpenQASM 3**)으로 번역하는
프로그램입니다. Qora는 이 번역을 한 번에 하지 않고, 각자 딱 한 가지 일만 하는 작은 단계 여러 개로 나눠서 합니다.

가장 먼저, 당신의 코드를 컴파일러가 내부에서 다루기 좋은 형태로 옮깁니다. 이걸 **IR(내부 표현)** 이라고
부르는데, 컴파일러가 당신 프로그램을 자기 방식으로 깔끔하게 정리해 적어둔 "작업용 메모"라고 생각하면 됩니다.
원본 텍스트를 다시 읽는 대신 이 IR만 이리저리 손보기 때문에, 이후 단계들이 훨씬 단순하고 실수하기 어려워집니다.

그다음 이 IR 위에서 이름을 확인하고, 규칙 위반을 검사하고, 필요한 변형을 가한 뒤, 맨 마지막에 OpenQASM
텍스트로 뽑아냅니다. 아래 표의 각 줄이 그 단계 하나하나입니다:

| 단계 | 패스 | 입력 | 출력 | 하는 일 |
|---|---|---|---|---|
| Load and parse | `SourceGraphLoader` + *Janglim* | 진입 소스 + import한 파일 | 파싱한 문서와 import 그래프 | 소스 문서를 읽고 성공적으로 읽은 경로를 재사용하며, 각 문서를 AST로 파싱합니다. |
| Lower HIR | `AstToHirLowering` | AST + revision-bound lowering session | `HirProgram` | 각 문서를 불변 선언 트리로 다시 짓습니다. 네임스페이스는 하위 선언과 `open`을 구조적으로 소유하고, 모든 표현식은 타입과 고유 ID를 가진 HIR 노드가 됩니다. |
| Expand | `ModuleLoader` | 문서별 `HirProgram` + import 그래프 | 합쳐진 `HirProgram` | 이미 읽은 문서를 정해진 그래프 순서로 병합하며 네임스페이스 소유 관계를 보존합니다. 파일 입출력은 `SourceGraphLoader`가 담당합니다. |
| Resolve | `Resolver` | 정확한 `HirProgram` + source-bound rewrite session | 다시 작성된 `HirProgram` | `Bell(q)`처럼 짧게 부른 이름이 실제로 어느 callable인지 찾아 완전한 이름(예: `GatesLib.Bell`)과 타입 있는 선언 ID로 연결합니다. |
| Validate | `QoraValidator` + `SymbolTableBuilder` | 정확한 `HirSnapshot` | semantic artifact 또는 오류 목록 | 이름, 타입, 소유권, callable 계약을 검사하며 HIR 검증에 실패하면 컴파일을 중단합니다. 이후 MIR과 타깃 검사에서도 진단이 나올 수 있습니다. |
| Monomorphize | `Monomorphizer` | 검증된 HIR + rewrite session | 구체화된 HIR | 길이가 정해지지 않은 `Qubit[]`와 `bit[]` callable 매개변수를 실제 인수 길이에 맞춰 구체화하며 네임스페이스 위치를 보존합니다. 공통 HIR은 `.Count`를 유지합니다. |
| Finalize HIR | `HirPipelineBuilder` | 구체화된 HIR | 최종 `HirSemanticArtifact` | 변경된 HIR을 다시 검증하고 MIR lowering에 필요한 형식 큐비트 매개변수의 효과를 기록합니다. |
| MIR lowering | `QoraMirLowering` | 최종 `HirSemanticArtifact` | SSA/CFG `MirSnapshot` | 고전값마다 버전을 붙이고 제어 흐름을 명시합니다. 측정식은 단락 평가를 포함한 실제 실행 지점에서 내리며, 각 MIR 값이 어느 HIR 표현식에서 왔는지 타입 있는 연결 관계를 보존합니다. |
| MIR 분석 | `MirAnalysisStore` | 정확한 MIR 프로그램과 그 프로그램이 소유한 callable | 불변 분석 정보 | 소비자가 요청할 때 효과, CFG, 별칭, 메모리 상태, 경로 조건과 범위를 계산하고 캐시합니다. |
| Target lowering | `MirOpenQasmLowering` | lowered MIR | `MirOpenQasmTargetProgram` | CFG에서 구조화된 제어 흐름을 복원하고 충돌 없는 타깃 이름을 정한 뒤, OpenQASM이 소유하는 타입 있는 모델을 만듭니다. |
| Emit | `MirQasmEmitter` | 타입 있는 OpenQASM 타깃 모델 | OpenQASM 텍스트 | HIR을 다시 보거나 의미 판단을 하지 않고 완성된 타깃 모델만 직렬화합니다. |

- **타입 있는 IR**(`src/Qora.Core/Ir/`)은 처음부터 끝까지 컴파일러가 소유하며, 파서 엔진은 lowering 경계에서 역할을 마칩니다.
- **모듈 로더**는 `import` 그래프 전체를 하나의 프로그램으로 병합합니다.<br>그 뒤 **리졸버**가 연산 호출 대상을 완전한 이름(FQN)으로 고정하고, 이후 모든 호출부는 딱 하나의 연산을 가리킵니다.<br>네임스페이스를 쓰는 다른 프로그래밍 언어들처럼 모호하면 에러가 나며, 자세한 내용은 [설계 문서](docs/namespaces-design.md)에 있습니다.
- **검증기**는 `QSEM` 진단을 수집형으로 보고합니다.<br>한 번의 컴파일에서 인자 종류와 개수, 레지스터 크기, 인덱스 범위, 예약 이름, 재귀 호출, 잘못 놓인 `use`, 선언되지 않았거나 선언 전에 사용한 식별자 등을 한꺼번에 보고합니다.<br>또한 검증기가 사용하는 통합 심볼 테이블도 컴파일 단계 뷰에 같이 나옵니다.
- 검증을 마친 **HIR**은 소스 중심 의미 모델로 남습니다. HIR의 최종 effect summary에는 `QoraMirLowering`이 올바른 큐빗 버전을 만들 때 필요한 formal qubit의 `ParamModified` 집합만 남습니다. 그 뒤 lowering이 하나의 권위 있는 SSA/CFG MIR snapshot을 만들며, 큐빗 버전·양자 효과·분석과 모든 backend는 그 snapshot의 정확한 MIR 프로그램만 소비합니다.
- **자동 uncomputation은 향후 작업입니다.** 계획된 MIR scheduler는 하나의 정확한 SSA/CFG 프로그램에서 분석 정보를 읽고 cleanup 위치를 정한 뒤 필요한 역연산을 생성합니다. Qora 소스, HIR, 현재 MIR에는 `Adjoint`, inverse-request 표식, inversion 패스가 없습니다.
- OpenQASM backend는 정확한 lowered MIR snapshot을 받아 타입 있는 `MirOpenQasmTargetProgram`을 고정합니다. 충돌 없는 이름과 구조화된 타깃 제어 흐름은 이 lowering이 담당하며, `MirQasmEmitter`는 완성된 타깃 모델만 직렬화합니다.

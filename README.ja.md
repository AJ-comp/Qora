**Qora は量子プログラミングを学ぶための学習用言語です。** 量子コードは Qiskit や Cirq のような
Python ライブラリで書かれることも多く、また理論をすでに知っている前提の研究用言語で書かれることもあります。
初めて学ぶ立場では、すばやい実験と正確な概念の間を行き来するのが簡単ではありません。

Qora はその間を埋めることに焦点を置いています。なじみのあるプログラミング構文で回路を書くと、
コンパイラがまず「このプログラムは本当に量子コンピュータにできることか」を確認します。
そのあと標準 **OpenQASM 3** を作り、一行ずつ読んだり実際のツールチェーンへ渡したりできるようにします。

この方向性は設計基準にもつながっています:

- **エラーは出力より先に出ます。** コンパイルを通過したなら、その OpenQASM は有効です。
- **コンパイラの内部を確認できます。** コマンド一つで、ソース、AST、ソース形 HIR、シンボル情報、SSA/CFG MIR、量子効果の要約、QASM を確認できます。
- **量子のルールはコンパイラが直接検査します。** 同じキュービットを制御とターゲットの両方に使うこと、move 済みの束縛を使うこと、単一キュービットの位置へレジスタを渡すことは診断の対象になります。

## クイックスタート

最速の方法は VS Code 拡張機能から始めることです。
コンパイラ全体が拡張機能の中に入っているため、**追加でインストールするものはなく**、.NET も Python も不要です。

1. VS Code マーケットプレイスから [Qora Language](https://marketplace.visualstudio.com/items?itemName=qora-lang.qora-language) をインストールします。
2. `bell.qor` というファイルを作り、上の例を貼り付けます。
3. 保存すると、すぐに次の機能を使えます。

- **入力中に**エラーへ下線が付き、下線にホバーすると理由を確認できます。`CNOT(q[0], q[0])` も試してみてください。
- ゲートやキーワードにホバーすると、`H`、`use`、`M` などの短い説明が出ます。
- **`Ctrl+Shift+P` → `Qora: Transpile to OpenQASM`** を実行すると、コンパイル結果が横のエディターに開きます。
- **`Qora: Show Compilation Stages`** は、保存するたびにソース → AST → HIR/シンボル → SSA/CFG MIR/量子効果 → QASM の流れを表示します。

リポジトリから直接実行する場合は、.NET 10 SDK だけで足ります。

```bash
git clone https://github.com/AJ-comp/Qora.git
cd Qora
dotnet run --project src/Qora          # デモプログラムをパースして OpenQASM を出力
```

自分のファイルをコンパイルする場合や、コンパイルの各段階を確認する場合は、次を実行します。

```bash
dotnet run --project src/Qora -- --json bell.qor
dotnet run --project src/Qora -- --json --stages bell.qor
```

VS Code 拡張機能も同じ `--json` インターフェイスを使います。各応答には `{success, qasm, errors[]}` が含まれ、
`--stages` を指定すると AST、HIR、シンボル、MIR、量子効果の要約も含まれます。
ファイルパスを指定しない場合、`--json` は標準入力からソースを読みます。

## 5分でわかる言語ツアー

**キュービットとゲート。** 新しいキュービットレジスタは `use q = Qubit[N];` の形で割り当て、配列のようにインデックスでアクセスします。
ここでの `use` は C# の `using` のようにブロック末尾の自動解放を表すものではなく、Qora プログラムで使うキュービットレジスタを作る構文です。
補助演算はレジスタを `Qubit[]` で受け取り、呼び出し側から渡された実際の長さを `.Count` で確認できます。
ゲート呼び出しは関数呼び出しと同じ形です。

```
use q = Qubit[3];              // キュービットレジスタ q を割り当て、サイズは 3
H(q[0]);                       // 重ね合わせ
CNOT(q[0], q[1]);              // もつれ
Rx(pi/2, q[2]);                // 回転は角度が先
Reset(q[2]);                   // |0⟩ に戻す
```

組み込みゲート: `H X Y Z S T` · `CNOT/CX CY CZ SWAP CCX` · `Rx Ry Rz` · `Reset ResetAll`。

**測定** `M` は、キュービットの測定結果を古典 `bit` に格納します。
`bit` はリテラル `0` または `1` でも初期化できます。測定は、量子情報を古典的な結果として取り出す方法です。

```
var r: bit = M(q[0]);          // 測定、元に戻せません
r = M(q[0]);                   // 同じ bit に再測定
```

**古典制御フロー**は期待どおりで、測定結果に反応できます:

```
const n: int = 2;
var count = 0;
for i in 0..n {  H(q[i]);  }
if (r == 1) {  X(q[1]);  } else {  Z(q[1]);  }
while (count < 2) {  count = count + 1;  }
repeat {  H(q[0]);  r = M(q[0]);  } until (r == 1);
```

**古典配列**は `bool`、`int`、`float`、`bit`、`angle` の値に、なじみのある `T[]` 形式を使います。
スカラーを置ける場所ならどこでも — `Main`、ヘルパー演算、ループや分岐の中でも — 宣言でき（OpenQASM のグローバルスコープ規則はコンパイラが自動的に処理します）、インデックスで要素を読み書きでき、反復時には `.Count` で長さを確認できます。

```qora
var counts: int[] = [1, 2, 3];
var weights: float[] = new float[3];   // 0 で初期化された三つの要素
weights[1] = 0.5;
for i in 0..counts.Count-1 { counts[i] = counts[i] + 1; }
```

`float` から `int` への暗黙の変換は禁止されるため、`var i: int = 0.5;` はコンパイルエラーです。
小数部分がない `1.0` も `float` なので同じ規則が適用されます。
再代入、配列要素、function・operation の引数と戻り値でも同様に検査します。
一方、`var i = 0.5;` は `float` と推論され、`int` から `float` への変換は引き続き許可されます。

**関数（function）** は古典的な値を計算し、戻り値を式で使用できます。純粋な関数なので、量子ビットの確保・ゲート・測定・operation の呼び出しは禁止されます。一方、`operation` は量子操作を実行し、`bool`、`int`、`bit`、`float`、`angle` のスカラー値を返すこともできます。

```qora
operation Read(q: Qubit): bit { return M(q); }
operation Main(): bit {
    use q = Qubit[1];
    H(q[0]);
    return Read(q[0]);
}
```

各ショットの実行結果には、**エントリ operation が返した値だけ**を表示します。補助 operation の戻り値は呼び出し元に渡され、自動的に表示されません。戻り型を省略した operation は結果を返さず、内部の測定値も自動表示しません。ランナーが測定を追加することもありません。
戻り値のない operation は `return;` で早期終了できます。戻り型がある場合は全経路で対応する値を返す必要があります。配列・タプルの戻り値は未対応で、`angle` の実行結果はラジアン単位です。

算術式では括弧を入れ子にできます。`(1 + 2) * 3` は `9`、`1 + 2 * 3` は `7`になります。
戻り値の式、呼び出し引数、配列インデックス、ループ範囲でも括弧を使えます。
比較演算子（`==`、`!=`、`<`、`<=`、`>`、`>=`）の結果は `bool` 値です。

```qora
function IsPositive(value: int): bool { return value > 0; }
operation Main(): bool {
    var isEqual: bool = 1 + 2 == 3;
    isEqual = (1 + 2) * 3 == 9;
    return isEqual == IsPositive(3);
}
```

比較結果は保存・引数としての受け渡し・戻り値としての返却ができ、変数の型を省略すると `bool` と推論されます。
算術演算、`<`・`<=`・`>`・`>=`、`==`・`!=` の順に優先されます。
論理演算子（`!`、`&&`、`||`）は従来どおり条件式専用で、測定式の使用位置に関する制限も変更しません。

`bool` は論理値 `true`/`false`、`bit` は測定結果の `0`/`1` を保持する別々の型です。
`bool` と `bit`・`int`・`float`・`angle` の暗黙の変換は、どちらの方向も許可されません。
初期化、代入、配列要素、引数、戻り値には同じ規則が適用されます。
条件は `bool` のみを受け付けるため、測定結果には `if (r == 1)`、整数には `if (count != 0)` と明示的に比較します。
`if (r)` や `if (count)` はコンパイルエラーです。`bool` 同士は等価比較のみが可能で、大小比較には数値が必要です。
実行結果も区別を保ち、返された `bool` は `true`/`false`、`bit` は `0`/`1` と表示します。

```qora
function angleOf(k: int): angle { return pi / k; }

operation Main()
{
    use q = Qubit[1];
    Rx(angleOf(4), q[0]);       // 関数の結果が回転角
    var r: bit = M(q[0]);
}
```

ユーザー定義演算は、名前とパラメータの後ろにブロックを付けて書き、`Main` がエントリポイントになります。
ユーザー構文の **`Controlled` ファンクタ**は、組み込みゲートに制御量子ビットを追加します:

```qora
operation Main()
{
    use q = Qubit[2];
    H(q[0]);
    Controlled X(q[0], q[1]);
}
```

`Adjoint` は Qora のユーザー構文ではなく、現在の HIR や MIR にも存在しません。
自動 uncomputation は、正確な SSA/CFG facts を解析して必要な cleanup を生成する将来の MIR scheduler として実装する計画です。

**名前空間と import** を使うと、大きなプログラムを複数ファイルに分けられます。
`import` は Python のようにファイルパスを文字列で書き、拡張子も含めます。

`gates_lib.qor`

```qora
namespace GatesLib
{
    operation Bell(q: Qubit[])
    {
        H(q[0]);
        CNOT(q[0], q[1]);
    }
}
```

`rotations.qor`

```qora
namespace Rotations
{
    operation Tilt(q: Qubit)
    {
        Ry(pi/4, q);
        Rz(pi/8, q);
    }
}
```

`main.qor`

```qora
import "gates_lib.qor";         // 同じディレクトリの gates_lib.qor を読み込む
import "rotations.qor";         // 同じディレクトリの rotations.qor を読み込む

namespace App
{
    open GatesLib;
    open Rotations;

    operation Prepare(q: Qubit[])
    {
        Bell(q);                // open 経由で GatesLib.Bell を名前だけで呼ぶ
        Tilt(q[0]);             // open 経由で Rotations.Tilt を名前だけで呼ぶ
    }
}

operation Main()
{
    use q = Qubit[2];
    App.Prepare(q);             // App 名前空間の演算を修飾付きで呼ぶ
    Rotations.Tilt(q[1]);       // import した別ファイルの演算を直接修飾して呼ぶ
}
```

名前解決の規則は、名前空間を使うなじみのあるプログラミング言語の方式に近いものです。
名前は自分の名前空間、グローバル名前空間、`open` した名前空間の順に探します。
ただし、`open` した二つの場所に同じ名前がある場合、Qora は黙って片方を選ばず、候補を表示するコンパイルエラーを出します。

`import "lib/gates.qor";` は、現在のファイルがあるディレクトリを基準に `lib/gates.qor` を読みます。
パスは引用符の中にそのまま書き、拡張子も含めます。
読み込みに成功した文書は正規化されたパスを使って再利用するため、重複する import や循環する back-edge でも同じ文書を追加で読み込みません。
読み込めない import に対しては診断を出力します。

組み込みゲート名も同じ規則に従い、組み込みゲートは暗黙の `Qora.Intrinsic` 名前空間にあります。
そのため、名前空間の中では `Rx` のような名前の演算を直接定義できます。
ただし、ある呼び出しがユーザー定義演算と組み込みゲートの両方を意味しうる場合、明示的な曖昧性エラーになります。
このとき、ユーザー定義演算は `L.Rx(q)`、組み込みゲートは `Qora.Intrinsic.Rx(pi/2, q)` のように書きます。

スコープ内に同じ名前のユーザー候補がなければ、裸のゲート名はそのまま組み込みゲートを意味します。
つまり、ドキュメントで学んだゲート名をプログラムでもそのまま使えます。

**間違えたときは、コンパイラが理由を教えてくれます。** 出力を生成する前に、診断が報告されます:

```
[QSEM006] in `Main`: `Bell` expects 1 argument(s) but got 2
[QSEM016] in `Main`: index `q[5]` is out of range; `q` has 2 qubit(s) (valid: 0..1)
[QSEM018] in `Go`: `Flip` is ambiguous here: it could be `LibA.Flip` or `LibB.Flip`
          — qualify the call (e.g. `LibA.Flip(...)`)
```

**プログラムの実行。** ユーザー定義演算、ループ、古典変数、`while` を含む Qora プログラムは、Amazon Braket のローカルシミュレータで実行できます:

```bash
dotnet build src/Qora
python -m pip install -r vscode/runner/requirements.txt  # Python 3.11-3.13
python tools/run_braket.py yourfile.qor --shots 1000
```

リポジトリには [Braket 戻り値検証](tools/braket_validation.py) と
[Qiskit インポータ互換性診断](tools/qiskit_validation.py) があります。
Qiskit のスクリプトは実行結果を表示するランナーではなく診断用です。現在のインポータは生成された古典変数・出力宣言のすべてには対応していません。内部の測定レジスタを Qora の戻り値の代わりに表示することもありません。
これらの検査は、すべての Qora プログラムがすべてのシミュレータやデバイスで動くことを保証するものではありません。

確認済みの実行制限があります。修正前の Braket ローカルシミュレータは、`bool[]` の要素を読み出す場合や
配列を関数の引数に渡す場合に `AttributeError: 'BoolType' object has no attribute 'size'` を発生させます。
Qora を使わずに記述した OpenQASM `array[bool, 2]` でも再現します。
Qora は正しい論理配列の型を維持し、数値配列への暗黙の置き換えは行いません。
[Braket issue #429](https://github.com/amazon-braket/amazon-braket-default-simulator-python/issues/429) に報告し、
[PR #430](https://github.com/amazon-braket/amazon-braket-default-simulator-python/pull/430) として修正を提出しました。
この修正と既存の PR #425・#426・#428 を組み合わせた環境では、論理配列と S・T を含む現在の Qora 実行検証54件がすべて成功しました。
ただし upstream でのマージとリリースはまだ完了しておらず、通常のパッケージインストールにはこれらのローカル検証用修正は含まれません。
また、この組み合わせでも `Qubit[]` の helper 引数の要素を測定すると失敗する場合や、
一部の非連続な量子ビット配置で制御ゲートが誤った結果を返す Braket の問題が残っています。
これらは成功した54件には含まれず、54件の成功はすべての Qora プログラムの実行を保証しません。

## コンパイラの仕組み

設計上の契約は **[コンパイラアーキテクチャ資料](https://aj-comp.github.io/Qora/architecture/ja/index.html)** を参照してください。
具体的なソースから実装を追う場合は、**[コンパイラ開発者マニュアル](https://aj-comp.github.io/Qora/developer/ja/index.html)** から始められます。

コンパイラとは、あなたが書いたコードを、量子コンピュータが実際に実行できる標準形式（**OpenQASM 3**）へ
翻訳するプログラムです。Qora はそれを一気にやらず、それぞれが 1 つの仕事だけをする小さなステップに分けて行います。

まず最初に、あなたのコードを内部で扱いやすい形へ移します。これを **IR（中間表現）** と呼びます — コンパイラが
あなたのプログラムを自分なりに整理して書き留めた「作業用メモ」のようなものです。元のテキストを読み直す代わりに
この IR を作り変えていくので、以降の各ステップは単純で間違えにくくなります。

その後、この IR の上で名前を確認し、規則違反を検査し、必要な変換を施し、最後に OpenQASM のテキストとして
書き出します。下の表の各行が、その 1 ステップずつです:

| ステージ | パス | 入力 | 出力 | 何をするか |
|---|---|---|---|---|
| Load and parse | `SourceGraphLoader` + *Janglim* | エントリーソース + import 先のファイル | パース済み文書と import graph | ソース文書を読み込み、読み込み済みのパスを再利用しながら、各文書を AST に変換します。 |
| Lower HIR | `AstToHirLowering` | AST + revision-bound lowering session | `HirProgram` | 各文書を不変の宣言木として組み直します。namespace は子宣言と `open` を構造的に所有し、すべての式は型と一意な ID を持つ HIR node になります。 |
| Expand | `ModuleLoader` | 文書ごとの `HirProgram` 宣言木 + import graph | 統合された `HirProgram` | 読み込み済みの文書を決定的な graph 順で統合し、namespace の所有関係を保持します。ファイル I/O は `SourceGraphLoader` が担当します。 |
| Resolve | `Resolver` | 正確な `HirProgram` + source-bound rewrite session | 再構築された `HirProgram` | `Bell(q)` のような短い呼び出しを実際の callable に解決し、完全修飾名（例: `GatesLib.Bell`）と、その HIR ノードの型付き ID を記録します。 |
| Validate | `QoraValidator` + `SymbolTableBuilder` | 正確な `HirSnapshot` | 意味情報の artifact またはエラー | 名前、型、所有権、callable の契約を検査します。HIR 検証に失敗するとコンパイルを停止します。その後の MIR やターゲットの検査でも診断が出る場合があります。 |
| Monomorphize | `Monomorphizer` | 検証済み HIR + rewrite session | 特殊化された HIR | 長さ未指定の `Qubit[]` と `bit[]` の callable パラメーターを、引数の具体的な長さごとに特殊化し、namespace 内の配置を保持します。共通 HIR では `.Count` を保持します。 |
| Finalize HIR | `HirPipelineBuilder` | 特殊化された HIR | 最終 `HirSemanticArtifact` | 変更された HIR を再検証し、MIR lowering に必要な仮キュービットの効果を記録します。 |
| Lower to MIR | `QoraMirLowering` | 最終 `HirSemanticArtifact` | SSA/CFG `MirSnapshot` | 古典値ごとに版を与え、制御フローを明示します。測定式は短絡評価の経路を含む正確な評価地点で lowering され、型付き HIR↔MIR provenance が保持されます。 |
| Analyze MIR | `MirAnalysisStore` | 正確な MIR program と、それに属する callable | 不変の解析情報 | 利用側から要求された時点で、効果、CFG、alias、memory state、path condition、bounds を計算してキャッシュします。 |
| Target lowering | `MirOpenQasmLowering` | lowered MIR | `MirOpenQasmTargetProgram` | CFG から構造化制御フローを復元し、衝突しない target 名を決め、OpenQASM 所有の型付きモデルを作ります。 |
| Emit | `MirQasmEmitter` | 型付き OpenQASM target model | OpenQASM テキスト | HIR を参照せず、意味判断もせず、完成した target model だけを直列化します。 |

- **型付き IR**(`src/Qora.Core/Ir/`)はコンパイラが最後まで所有します; パースエンジンは lowering の
  境界で止まります。
- **モジュールローダー**は `import` グラフ全体を一つのプログラムに統合します。<br>その後 **リゾルバ** が演算の呼び出し先を完全修飾名(FQN)に固定し、以降の各呼び出しは一つの演算だけを指します。<br>名前空間を使う他のプログラミング言語と同じように、曖昧な場合はエラーになります。詳しくは [設計ドキュメント](docs/namespaces-design.md) にあります。
- **バリデータ**は `QSEM` 診断を収集型で報告します。<br>一度のコンパイルで、引数の種類と個数、レジスタサイズ、インデックス範囲、予約名、再帰、誤った位置の `use`、未宣言または宣言前に使われた識別子などをまとめて報告します。<br>また、バリデータが使う統合シンボルテーブルもコンパイル段階ビューに表示されます。
- 検証済みの **HIR** はソース中心の意味モデルとして残ります。HIR の最終 effect summary には、
  `QoraMirLowering` が正しいキュービット版を作るために必要な formal qubit の `ParamModified` 集合だけが残ります。
  その後 lowering が権威ある 1 つの SSA/CFG MIR snapshot を作り、キュービット版、量子 effect、解析、
  すべての backend はその snapshot の正確な MIR program だけを消費します。
- **自動 uncomputation は将来の作業です。** 計画中の MIR scheduler は 1 つの正確な SSA/CFG program から
  解析情報を読み、cleanup の位置を決め、必要な逆演算を生成します。Qora ソース、HIR、現在の MIR には
  `Adjoint`、inverse-request marker、inversion pass がありません。
- OpenQASM backend は正確な lowered MIR snapshot を受け取り、型付き
  `MirOpenQasmTargetProgram` を確定します。衝突しない名前と構造化 target control flow はこの lowering が担い、
  `MirQasmEmitter` は完成した target model だけを直列化します。

# Qora

**量子プログラミングを学びやすくする学習用言語。**
Q#·C# に近い構文で量子回路を書き、検証済みの **OpenQASM 3** を出力します。

**Qora は量子プログラミングを学ぶための学習用言語です。** 量子コードは Qiskit や Cirq のような
Python ライブラリで書かれることも多く、また理論をすでに知っている前提の研究用言語で書かれることもあります。
初めて学ぶ立場では、すばやい実験と正確な概念の間を行き来するのが簡単ではありません。

Qora はその間を埋めることに焦点を置いています。なじみのあるプログラミング構文で回路を書くと、
コンパイラがまず「このプログラムは本当に量子コンピュータにできることか」を確認します。
そのあと標準 **OpenQASM 3** を作り、一行ずつ読んだり実際のツールチェーンへ渡したりできるようにします。

この方向性は設計基準にもつながっています:

- **エラーは出力より先に出ます。** コンパイルを通過したなら、その OpenQASM は有効です。
- **コンパイラの内部を確認できます。** コマンド一つで、ソース、AST、ソース形 HIR、シンボル情報、SSA/CFG MIR、revision-bound MIR 解析、QASM を確認できます。
- **量子のルールはコンパイラが直接検査します。** すでに使ったキュービットの再利用、測定の逆転、単一キュービットの位置へのレジスタ渡しはコンパイル段階で止められます。

OpenQASM でそのまま安全な名前は変更されません。
ただし、ユーザー名がキーワード、stdgates のゲート名、またはすでに出力された別の名前と衝突するときだけ、
Qora は出力名を変更し、その理由を `// Qora:` ノートとして残します。

## クイックスタート

最速の方法は VS Code 拡張機能から始めることです。
コンパイラ全体が拡張機能の中に入っているため、**追加でインストールするものはなく**、.NET も Python も不要です。

1. VS Code マーケットプレイスから [Qora Language](https://marketplace.visualstudio.com/items?itemName=qora-lang.qora-language) をインストールします。
2. `bell.qor` というファイルを作り、上の例を貼り付けます。
3. 保存すると、すぐに次の機能を使えます。

- **入力中に**エラーへ下線が付き、下線にホバーすると理由を確認できます。`CNOT(q[0], q[0])` も試してみてください。
- ゲートやキーワードにホバーすると、`H`、`use`、`M` などの短い説明が出ます。
- **`Ctrl+Shift+P` → `Qora: Transpile to OpenQASM`** を実行すると、コンパイル結果が横のエディターに開きます。
- **`Qora: Show Compilation Stages`** は、保存するたびにソース → AST → HIR/シンボル → SSA/CFG MIR/解析 → QASM の流れを表示します。

リポジトリから直接実行する場合は、.NET 10 SDK だけで足ります。

```bash
git clone https://github.com/AJ-comp/Qora.git
cd Qora
dotnet run --project src/Qora          # デモプログラムをパースして OpenQASM を出力
```

VS Code 拡張機能も同じバイナリを `qora --json` で実行し、コンパイルごとに `{success, qasm, errors[]}` 形式の JSON 一行を受け取ります。

## 5分でわかる言語ツアー

**キュービットとゲート。** 新しいキュービットレジスタは `use q = Qubit[N];` の形で割り当て、配列のようにインデックスでアクセスします。
ここでの `use` は C# の `using` のようにブロック末尾の自動解放を表すものではなく、Qora プログラムで使うキュービットレジスタを作る構文です。
補助演算はレジスタを `Qubit[]` で受け取り、呼び出し側から渡された実際の長さを `.Count` で確認できます。
ゲート呼び出しは関数呼び出しと同じ形です。

```
use q = Qubit[3];              // キュービットレジスタ q を割り当て、サイズは 3
H(q[0]);                       // 重ね合わせ
CNOT(q[0], q[1]);              // もつれ
Rx(pi/2, q[2]);                // 回転は角度が先
Reset(q[2]);                   // |0⟩ に戻す
```

組み込みゲート: `H X Y Z S T` · `CNOT/CX CY CZ SWAP CCX` · `Rx Ry Rz` · `Reset ResetAll`。

**測定**はキュービットの測定結果を古典 `bit` に入れる演算であり、Qora で `bit` を得る方法も測定だけです。

```
var r: bit = M(q[0]);          // 測定、元に戻せません
r = M(q[0]);                   // 同じ bit に再測定
```

**古典制御フロー**は期待どおりで、測定結果に反応できます:

```
const n: int = 2;
var count = 0;
for i in 0..n {  H(q[i]);  }
if (r == 1) {  X(q[1]);  } else {  Z(q[1]);  }
while (count < 2) {  count = count + 1;  }
repeat {  H(q[0]);  r = M(q[0]);  } until (r == 1);
```

**古典配列**は `int`、`float`、`bit`、`angle` の値に、なじみのある `T[]` 形式を使います。
スカラーを置ける場所ならどこでも — `Main`、ヘルパー演算、ループや分岐の中でも — 宣言でき（OpenQASM のグローバルスコープ規則はコンパイラが自動的に処理します）、インデックスで要素を読み書きでき、反復時には `.Count` で長さを確認できます。

```qora
var counts: int[] = [1, 2, 3];
var weights: float[] = new float[3];   // 0 で初期化された三つの要素
weights[1] = 0.5;
for i in 0..counts.Count-1 { counts[i] = counts[i] + 1; }
```

**関数（function）** は古典的な値を計算します。`function` は純粋で値を返すため、void の `operation` と違い、その呼び出し自体が値になり、式のどこでも使えます（ゲート引数・条件・初期化式など）。量子ビットには触れられない（ゲートも測定も不可）ので、純粋な古典ヘルパーとして扱えます。

```qora
function angleOf(k: int): angle { return pi / k; }

operation Main()
{
    use q = Qubit[1];
    Rx(angleOf(4), q[0]);       // 関数の結果が回転角
    var r: bit = M(q[0]);
}
```

ユーザー定義演算は、名前とパラメータの後ろにブロックを付けて書き、`Main` がエントリポイントになります。
ユーザー構文の **`Controlled` ファンクタ**は、組み込みゲートに制御量子ビットを追加します:

```qora
operation Main()
{
    use q = Qubit[2];
    H(q[0]);
    Controlled X(q[0], q[1]);
}
```

`Adjoint` は Qora のユーザー構文ではありません。
HIR にも入りません。正確な `MirQuantumApply` に `MirFunctor.Adjoint` を付けられるのはコンパイラ内部の MIR パスだけで、
将来の自動 uncomputation もこの境界を使います。

**名前空間と import** を使うと、大きなプログラムを複数ファイルに分けられます。
`import` は Python のようにファイルパスを文字列で書き、拡張子も含めます。

`gates_lib.qor`

```qora
namespace GatesLib
{
    operation Bell(q: Qubit[])
    {
        H(q[0]);
        CNOT(q[0], q[1]);
    }
}
```

`rotations.qor`

```qora
namespace Rotations
{
    operation Tilt(q: Qubit)
    {
        Ry(pi/4, q);
        Rz(pi/8, q);
    }
}
```

`main.qor`

```qora
import "gates_lib.qor";         // 同じディレクトリの gates_lib.qor を読み込む
import "rotations.qor";         // 同じディレクトリの rotations.qor を読み込む

namespace App
{
    open GatesLib;
    open Rotations;

    operation Prepare(q: Qubit[])
    {
        Bell(q);                // open 経由で GatesLib.Bell を名前だけで呼ぶ
        Tilt(q[0]);             // open 経由で Rotations.Tilt を名前だけで呼ぶ
    }
}

operation Main()
{
    use q = Qubit[2];
    App.Prepare(q);             // App 名前空間の演算を修飾付きで呼ぶ
    Rotations.Tilt(q[1]);       // import した別ファイルの演算を直接修飾して呼ぶ
}
```

名前解決の規則は、名前空間を使うなじみのあるプログラミング言語の方式に近いものです。
名前は自分の名前空間、グローバル名前空間、`open` した名前空間の順に探します。
ただし、`open` した二つの場所に同じ名前がある場合、Qora は黙って片方を選ばず、候補を表示するコンパイルエラーを出します。

`import "lib/gates.qor";` は、現在のファイルがあるディレクトリを基準に `lib/gates.qor` を読みます。
パスは引用符の中にそのまま書き、拡張子も含めます。
同じ正規化済み絶対パスは、複数の import 経路から到達しても一度だけ処理を試みます。
そのため循環する back-edge は `loaded` に登録済みのパスとしてエラーなしでスキップされ、QSEM021 は廃止済みの予約コードとしてのみ残り、現在は出力されません。

組み込みゲート名も同じ規則に従い、組み込みゲートは暗黙の `Qora.Intrinsic` 名前空間にあります。
そのため、名前空間の中では `Rx` のような名前の演算を直接定義できます。
ただし、ある呼び出しがユーザー定義演算と組み込みゲートの両方を意味しうる場合、明示的な曖昧性エラーになります。
このとき、ユーザー定義演算は `L.Rx(q)`、組み込みゲートは `Qora.Intrinsic.Rx(pi/2, q)` のように書きます。

スコープ内に同じ名前のユーザー候補がなければ、裸のゲート名はそのまま組み込みゲートを意味します。
つまり、ドキュメントで学んだゲート名をプログラムでもそのまま使えます。

**間違えたときは、コンパイラが理由を教えてくれます** — 一度のコンパイルですべての違反を、出力の前に:

```
[QSEM006] in `Main`: `Bell` expects 1 argument(s) but got 2
[QSEM016] in `Main`: index `q[5]` is out of range; `q` has 2 qubit(s) (valid: 0..1)
[QSEM018] in `Go`: `Flip` is ambiguous here: it could be `LibA.Flip` or `LibB.Flip`
          — qualify the call (e.g. `LibA.Flip(...)`)
```

**プログラムの実行。** ユーザー定義演算、ループ、古典変数、`while` を含む Qora プログラムは、Amazon Braket のローカルシミュレータで実行できます:

```bash
pip install amazon-braket-sdk            # Python 3.10–3.13
python tools/run_braket.py yourfile.qor --shots 1000
```

両方の実行経路は、実測統計によるリリース検証にも使われます。
`tools/braket_validation.py` は、言語全体が実行できることを確認します。
`tools/qiskit_validation.py` は、Qiskit の `qasm3.loads(...)` が受け付ける平坦な部分集合を検証します。
ただし Qiskit のインポータはまだ `def`、`int`、変数ループインデックスを読めないため、Qiskit と実機へつなぐ平坦化出力モードを追加する予定です。

## コンパイラの仕組み

正式な段階別の説明は  **[Qora コンパイラ データシート](https://aj-comp.github.io/Qora/architecture.html)** にあります。

コンパイラとは、あなたが書いたコードを、量子コンピュータが実際に実行できる標準形式（**OpenQASM 3**）へ
翻訳するプログラムです。Qora はそれを一気にやらず、それぞれが 1 つの仕事だけをする小さなステップに分けて行います。

まず最初に、あなたのコードを内部で扱いやすい形へ移します。これを **IR（中間表現）** と呼びます — コンパイラが
あなたのプログラムを自分なりに整理して書き留めた「作業用メモ」のようなものです。元のテキストを読み直す代わりに
この IR を作り変えていくので、以降の各ステップは単純で間違えにくくなります。

その後、この IR の上で名前を確認し、規則違反を検査し、必要な変換を施し、最後に OpenQASM のテキストとして
書き出します。下の表の各行が、その 1 ステップずつです:

| ステージ | パス | 入力 | 出力 | 何をするか |
|---|---|---|---|---|
| Parse | *Janglim エンジン* | ソーステキスト | AST | あなたが書いたソースコードを、コンパイラが扱える構文木に変えます（形だけで、まだ意味はありません）。 |
| Lower HIR | `QoraLowering` | AST | `QProgram` (HIR) | パーサーの木を Qora のソース形 typed representation に組み直します。 |
| Expand | `ModuleLoader` | `QProgram` (HIR) | `QProgram` (HIR) | `import` で取り込んだ複数の `.qor` ファイルを 1 つのプログラムに統合します。以降は 1 ファイルだけ見れば済みます。 |
| Desugar measure | `MeasureConditionLowering` | `QProgram` (HIR) | `QProgram` (HIR) | `if (M(q[0]) == 1)` のように条件の中で直接行う測定を、「まず `bit` に測定して、その `bit` を検査する」形に書き換えます（OpenQASM は条件の中で測定できないため）。 |
| Resolve | `Resolver` | `QProgram` (HIR) | `QProgram` (HIR) | `Bell(q)` のような短い呼び出しが実際どの演算を指すのかを突き止め、完全な名前（例: `GatesLib.Bell`）に固定します。 |
| Validate | `QoraValidator` + `SymbolTableBuilder` | `QProgram` (HIR) | accepted semantic artifact（またはエラー一覧） | プログラムが量子コンピュータに本当に実行できる内容かをすべて検査し、誤りがあればすべてのエラーを集めて報告し、ここで停止します（OpenQASM は出力されません）。 |
| Monomorphize | `Monomorphizer` | `QProgram` (HIR) | `QProgram` (HIR) | `Qubit[]` callable を呼び出し地点の具体的な幅ごとに特殊化します。共通 HIR は `.Count` を保ち、各 target が既知の幅を使って lowering します（C++ template や Rust generic に近い方式です）。 |
| MIR lowering | `QoraMirLowering` | 検証済み HIR + 意味情報 | SSA/CFG `MirSnapshot` | 古典値ごとに版を与え、制御フローを明示しながら、型付きの HIR↔MIR provenance を保ちます。 |
| MIR analysis | revision-bound MIR analyses | `MirSnapshot` | 不変の解析情報 | その MIR revision に対して effect、alias、memory state、path condition、control region を計算します。 |
| 内部逆演算の実体化 | `MirAdjointMaterializer` | コンパイラ内部の逆演算要求を持つ MIR | 実体化済み MIR | 逆方向の MIR callable を合成し、要求を型付き呼び出しへ書き換えます。この要求と `Adjoint` は Qora ソースにも HIR にも存在しません。 |
| Target lowering | `MirOpenQasmLowering` | 実体化済み MIR | `MirOpenQasmTargetProgram` | CFG から構造化制御フローを復元し、衝突しない target 名を決め、OpenQASM 所有の型付きモデルを作ります。 |
| Emit | `MirQasmEmitter` | 型付き OpenQASM target model | OpenQASM テキスト | HIR を参照せず、意味判断もせず、完成した target model だけを直列化します。 |

- **型付き IR**(`src/Qora.Core/Ir/`)はコンパイラが最後まで所有します; パースエンジンは lowering の
  境界で止まります。
- **モジュールローダー**は `import` グラフ全体を一つのプログラムに統合します。<br>その後 **リゾルバ** が演算の呼び出し先を完全修飾名(FQN)に固定し、以降の各呼び出しは一つの演算だけを指します。<br>名前空間を使う他のプログラミング言語と同じように、曖昧な場合はエラーになります。詳しくは [設計ドキュメント](docs/namespaces-design.md) にあります。
- **バリデータ**(QSEM001–025)は収集型です。<br>一度のコンパイルで、引数の種類と個数、レジスタサイズ、インデックス範囲、予約名、再帰、誤った位置の `use`、未宣言または宣言前に使われた識別子などをまとめて報告します。<br>また、バリデータが使う統合シンボルテーブルもコンパイル段階ビューに表示されます。
- 検証済みの **HIR** はソース中心の意味モデルとして残り、`QoraMirLowering` が権威ある 1 つの
  SSA/CFG MIR snapshot を作ります。以降の MIR 解析とすべての backend は revision-bound な MIR 情報を消費します。
- **逆演算要求は MIR にだけ存在します。** 将来の automatic-uncomputation scheduler が正確な
  `MirQuantumApply` 命令へ `MirFunctor.Adjoint` を付けると、`MirAdjointMaterializer` が必要な逆方向
  callable を合成します。Qora ソースと HIR には `Adjoint`、conjugation node、inversion pass がありません。
- OpenQASM backend は正確な materialized MIR snapshot を受け取り、型付き
  `MirOpenQasmTargetProgram` を確定します。衝突しない名前と構造化 target control flow はこの lowering が担い、
  `MirQasmEmitter` は完成した target model だけを直列化します。
